# こもれび市計画の実装知見

## 設計

都市は32×32の一次元タイル配列として保持し、純粋関数による建設・月次成長・財政計算をCity autoloadから呼ぶ。道路網への接続と送電容量を別に計算し、停電・公害・犯罪・防火の問題によって区画が衰退する。住宅需要は雇用とのバランスと税率、公園は周辺の公害を軽減して成長へ影響する。初期道路と少量の区画を用意し、最初の3か月で成長を観察できるようにした。

目標は600人、資金がマイナスのまま3か月続くと敗北。月は4秒で進み、任意の翌月操作と停止・1倍・3倍も用意する。初期街の道路南側へ住宅3区画を追加すると、9月に720人でクリアする。施設を減らす、税率を上げるなど財政への対処もできる。

保存データは整数性・配列長・列挙値・人口と雇用の集計値・負債月数と勝敗の整合を検証する。結果月も保存し、再開した結果画面からキーボードやゲームパッドでタイトルへ戻れる。自動検証では通常のuser://保存を使わず、作業ディレクトリ内へ保存先を分ける。

## 素材と表示

住宅・商店・工場・施設・車・歩行者は画像を読まず、`Polygon2D` の面と `Line2D` の輪郭で等角投影の線画を実行時に作る。低密度と中密度は色だけでなく、屋根、庇、鋸屋根、煙突、盾、炎、送電鉄塔で識別する。IBM Plex Sans JP は Google Fonts 公式リポジトリから取得し、著作権表示を含む OFL 全文と同梱する。

街は独立 `SubViewport` と `CanvasModulate` で昼夜を表現し、図面の台帳は影響を受けずコントラストを保つ。背景と地図は青地、白線、寸法線、方眼、等高線、ハッチングで統一し、CanvasItem シェーダで紙の粒子・繊維・折り目を加える。

AnimationPlayerに待機・移動・建設・成長・問題・撤去を用意する。拡縮だけでは弱いため、建設の落下と弾み、成長の持ち上がりと閃光、撤去の傾きと透明化、停電の点滅を組み合わせた。車体の揺れと歩行者の上下・左右の動きも分ける。撤去時には街の表示を短く止め、粒子と画面揺れを加える。ゲーム進行の座標とSpriteの演出座標を分けると、アニメーション同士の干渉を避けやすい。

音は外部サンプルなしで倍音・ノイズ・エンベロープを合成する。タイトル・小都市・大都市・結果の4曲に、紙を動かす音と鉛筆を想起させるステレオ環境音、ベル・定規・紙の音色に寄せた5効果音を重ねる。Python 生成器は固定 seed で同一バイトを生成し、内容が同じなら mtime も変えない。

## 手直しラウンド (見た目の特色化)

### 分かりにくさの原因と効いた表現

前ラウンドは「HUD、中央の地図、画面下の共通操作ガイド」という構成が他ゲームと重なり、紙色の平面 SVG も都市計画の固有の作業感まで伝えていなかった。初見時は入力一覧と多くの数値が同時に目に入り、「道路沿いへ住宅を置き、翌月へ進む」という最初の一手が弱かった。

効いたのは、全画面を一枚の青焼き図面として扱い、街を等角投影の白線で描いたことだった。資金・人口・電力は図面右の「都市台帳」、建設対象は「製図道具」、ズームと時間は「縮尺・時間」に分けた。配置可能区画の水色線、黄色の完成プレビュー、赤い配置不可輪郭と具体的な理由を同時に見せ、台帳に常に次の一手を出す。最初の3枚だけ手書き注記を重ね、Enter / A で進行、Escape / B でスキップできるようにした。

### 手続き生成の手順、当たり外れ、手間

1. 32×32 の論理座標は変えず、`(x - y) * 幅 / 2`, `(x + y) * 高さ / 2` で等角投影へ写す。マウス入力は逆変換し、既存のシミュレーションと保存形式を維持する。
2. 地表の菱形、道路網、寸法線を先に描き、建物は共通の `Visual` ノード以下へ面と輪郭を組み立てる。既存の6動作は `Visual` の座標・回転・透明度へ適用する。
3. CanvasItem シェーダを色面だけへ適用し、UI 文字と線の可読性を保つ。最後に IBM Plex Sans JP を Theme の既定フォントにする。
4. 音は固定 seed で WAV を別ディレクトリへ再生成し、管理中の WAV とバイト単位で比較する。ループ端点、クリップ、チャンネル数も数値検査する。

当たりは、建物ごとに「住宅の屋根」「工場の鋸屋根と煙突」「警察の盾」のような記号を持たせたこと、白線だけでなく半透明の青い面を重ねたことだった。線だけの初期案は縮尺 0.5 倍で建物が線の塗りつぶしに見えた。色の差だけで種類を分ける案、旧 SVG の配色だけを青系へ替える案も、他ゲームとの識別に効かないため採用しなかった。

手間は SVG 生成より大きい。実行時の線幅、接地点、z-index、アニメーションの対象パスを同時に調整する必要がある。一方で、色、線幅、プレビュー、昼夜の変化を同じノード群に適用でき、各サイズの SVG と import ファイルを維持する必要がなくなった。

### 検証のしやすさとライセンス

手続き線画はファイル単体のプレビューができない。代わりに全13線画×全6動作の開始・中間・終了を固定倍率で撮る図鑑と、区画上の実縮尺画面の両方を目視する。詳細表示と全体図、配置可能プレビュー、配置不可理由、3枚のチュートリアルも個別のスクリーンショットにする。

線画、地形、シェーダ、WAV はすべて外部素材を使わないため、第三者ライセンスの確認対象は IBM Plex Sans JP だけになった。取得元 URL、IBM の著作権表示、Reserved Font Name、SIL Open Font License 1.1 全文をフォントと同梱する。

### Godot で図面 UI を作る時のハマりどころ

- `SubViewport` 内の等角投影と外側の `Control` で座標系が異なる。クリックは地図 `Control` のローカル座標から逆変換し、自動テストは `global_position + cell_to_screen()` で実画面座標へ戻す。
- 全体図では線幅も縮む。小さな装飾を追加するより、輪郭と半透明の面でシルエットを先に区別する方が効く。
- チュートリアルの全画面 `Control` は地図クリックを止める。パッド B は焦点中の Button が GUI キャンセルとして消費するため、`_input` で先にスキップとして扱う。
- 「翌月」の実行中に結果画面へ遷移する。遷移後に `gui_release_focus()` を呼ぶと、新しい結果ボタンの焦点まで外れる。焦点解除は月送りの前に行い、Enter / A で戻れることを実入力で検査する。

### skill 化の候補

`game-asset-search` へは、「画像不使用」の作業でも `Line2D` / `Polygon2D` の種類別図鑑、実縮尺画面、生成物の決定性をひとまとめに検査する手順を追記する候補がある。`godot-development` へは、等角投影の画面座標と論理セルの往復、画面遷移中の GUI フォーカス、全体図での線画目視検査を追記する候補がある。

## 操作と検証

マウスはドラッグ建設、右ドラッグ移動、ホイール拡大。キーボードは方向キーでカーソル、Enterで建設、Q/Eで道具、Spaceで停止、Tで速度、Nで翌月、Oで問題表示、Z/Cで税率、F11で全画面。ゲームパッドは十字キーとA、LB/RB、Start、Back、X、Y、左右トリガ、スティック押下を対応させる。チュートリアルの進行とスキップ、配置可否と理由、税率スライダー、系統別電力、手動翌月の経過時間、保存再開、勝敗到達を実 `InputEvent` で検証し、`make test` へ含めた。共有CIが `selfcheck` を直接呼ぶため、`selfcheck` からも `integration` を依存させた。

- selfcheck: 道路、電力、需要、公害、犯罪、防火、成長と退化、赤字回復と敗北、クリア、入力不変、保存破損を確認。
- screenshot: タイトル、3枚のチュートリアル、詳細と全体図、配置可能プレビューと配置不可理由、成長、昼夜、4問題表示、停電、建設・撤去の途中、勝敗、全13線画×6動作×開始・途中・終了を撮影。
- movie-play: 実マウスドラッグで住宅を追加し、実キー入力で通常の9月クリアとタイトル帰還を約28秒で録画。固定30fpsから60フレームごとに確認画像を抽出する。
- native.gd: 実描画でF11を往復し、全画面と1280×720へ復帰した画面を撮影。
- make citybuilder-run: 通常起動後、起動したPIDだけへNSRunningApplication.terminate()で終了要求。--quit-afterも別起動し、両経路のexit 0と音声リーク警告なしを確認。
- macOS・Windows・Linux・Webの書き出しは、同じ専用Godotと既存export templatesで検証する。

実物のゲームパッドの握り心地、他機種の性能、主観的な聴感はこの自動検証からは判断しない。入力イベントの到達と状態変化、音源の再生開始・波形・録音トラック・終了処理を検証対象にする。

## 検証で見つけた不具合

- 電力容量を全発電所の合算にすると、孤立した発電所が別の街の停電を解消した。接続成分ごとの容量へ変更し、道路で接続した後にだけ改善するテストを追加した。
- アナログトリガの0.6→0.7→0.8を別々の押下として扱うと、一度押し込むだけで税率が何段階も変化した。閾値を越えた最初のイベントだけを受け、解放後に再入力を許す。
- 問題表示の選択を残す場合、新しい地図側にも同じ表示種別を渡す必要がある。
- クリア・敗北月を保存しないと再開が前月へ巻き戻る。結果を再開する時にGUIのフォーカスを無条件解放すると、結果ボタンをパッドで押せなくなることも実入力で検出した。
- 録画の最後にmainをqueue_freeして1フレーム待つと灰色の空フレームが入った。音声を止めた後、描画ノードの解放はSceneTreeの終了へ任せる。
- ffmpegのfps=1/2による抽出は時刻の丸めがあり、単純な0秒・2秒のラベルと元の場面がずれる。固定30fpsではselectで60フレームごとに選び、画像の表示時刻を揃える。

- 保存先を直接WRITEで開くと、書き込み失敗時に前回の保存も失う。一時ファイルへの書き込み・flush・内容照合後にrenameし、一時保存先をディレクトリで塞いだ検証で旧データ保持と再試行を確認した。
- 再開時は人口のカウントアップ値も保存値に同期する。別の街の値が残っていても、最初の描画から正しい人口を表示する。

- 税率スライダーにフォーカスが残ると方向キーを奪う。マウス専用のスライダーをFOCUS_NONEにし、操作直後のキーとパッドで地図が動くことを検証した。
- 高速ドラッグは移動イベントが複数セルを飛ばすため、通過セルを補間する。道路が斜め方向でも上下左右でつながる経路を使い、5区画を一度の移動イベントで塗るテストを追加した。
- HUDの維持費は月末の値を残さず、初期化と建設・撤去直後にも現在の施設から再集計する。支払い自体は月次処理だけで行う。

## 環境と運用の知見

Godotのimportは終了コード0でもエディタ設定保存エラーを出す。worktree内にコピーしてad-hoc署名したGodotのself-contained modeを使い、設定・ログもworktree内へ収めた。macOSの実描画はサンドボックス内の描画サービス接続が失敗したため、許可された実行経路を使用した。既存Godot.appやシステム設定は変更していない。

警告音のファイル名warning.wavがimportログのWARNING検査へ誤一致した。ログの現物で警告とは異なることを確認し、素材名をalert.wavへ改めた。ログは全文で調べ、末尾だけで成功と判断しない。

WAVの終了処理は既存deckrogueの停止・stream解放・音声スレッドの待機を利用した。通常の終了通知と--quit-afterは別経路なので、両方を実行する。音声停止後に描画を先に消さないことが録画には重要だった。

webtunnelは既存認証・tailnetを利用し、citybuilderブランチをSwiftShader有効で起動した。サンドボックス内のTailscale状態取得は異常終了したが、通常の実行経路では接続済みだった。またup --waitでGitHub APIがタイムアウトし「runが存在しない」と出ても、実際のジョブは継続していた。runの現物とCDPを確認してから操作する。

runnerのcanvasは1279×656で、1280×720のゲームには左右余白が入る。クリックはcanvasの矩形から倍率と中央寄せの余白を計算し、ゲーム座標を写す。既定のHTMLシェルからstatusが消えたことと実画像の両方で起動を確認した。

## 判断点とskill・共有物への提案

アートは紙の都市計画図と小さな建築模型を採用した。防火はランダム災害ではなく予測可能な成長・衰退条件として表現する。道路と発電所を備えた独立集落も、issueの「道路に接し電力が届く」という条件を満たすので許容する。固定幹線への接続必須化は採用していない。追加判断待ちの仕様はない。

skill化候補は、接続成分ごとの都市シミュレーション、不変性・保存破損の検証、差分描画、全オブジェクトの複数姿勢撮影を組み合わせた都市シムの検証手順。既存godot-developmentには録画末尾の空フレーム対策、アナログトリガの段階値テスト、固定fps録画の正確な時刻抽出を提案する。

共有CIはdocuments/knowledgeの変更でも全ゲームを検証するため、今回も10ゲームへ展開した。知見ファイルをゲーム専用の変更として扱う判定は共有物側の改善候補。ルートにmovie-playの委譲targetがないため、録画プレイはmake -C games/citybuilder movie-playを使う。共有MakefileやCIは変更していない。

最終の実行結果、CI、ローカルとWebの画像・録画はPRの検証欄へ集約する。
