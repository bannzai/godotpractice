# 灯守の迷宮の開発知見

## ゲームの設計

フリー素材を使う2Dローグライトという依頼に対し、剣と無敵回避で六つの部屋を突破する短い探索を選んだ。敵編成・柱の配置・三択の強化をseedで変え、焚き火で購入する恒久強化を次の探索へ引き継ぐ。死亡時は欠片の半分、部屋制圧後の帰還と最深部の踏破では全量を持ち帰る。途中帰還に意味を持たせ、負けても次の挑戦が進む形にした。

他ゲームの画面・コードは参照していない。ランと戦闘状態をautoloadの `run.gd`、描画と入力を `main.gd` に分けた。部屋制圧と結果確定は状態を先に切り替え、同一フレームの複数衝突でも報酬が二重加算されない。

## 素材の準備

Kenney Tiny Dungeonの公式ページからZIPをcurlで取得し、packed atlasだけを同梱した。タイル番号は推測せず、同梱の個別PNGを番号付き一覧にして確認すると床・壁・キャラクターの取り違えを防げる。通常のtilemapには1pxの間隔があり、packed版は16px刻みで切り出せる。

SEはKenney Impact Sounds、BGMはOpenGameArtのRuhinre「Whispers in the Fog」。出典とライセンスの正はゲーム内 `assets/CREDITS.md` とそこから参照する音声クレジットにまとめた。音声は全ファイルをffmpegで最後までデコードしてエラーがないことを確認した。

日本語表示はNoto Sans JPの可変フォントを同梱した。Godot 4.7で初期値のweightが100になり、文字が極端に細く表示された。FontVariationの `variation_opentype` を文字列キー `wght` にしても今回の環境では変わらず、`TextServer.name_to_tag("wght")` が返す整数タグで450を指定すると改善した。実際の見え方の確認が必要。

公式資料: https://docs.godotengine.org/en/stable/classes/class_fontvariation.html

## 実装・検証で得た知見

- 移動量を8px以下に細分化して軸別に衝突を解決すると、回避中も薄い壁をすり抜けず、壁沿いを動ける。
- 柱の高さをランダム化すると固定の敵出現位置と重なるため、敵の生成時にも歩行可否を判定した。
- ローカルのGodotはsandbox内でユーザーデータやエディタ設定を書けず、ログの生成失敗でクラッシュする場合もあった。headlessのselfcheckは `--log-file` を作業領域内へ向けると実行でき、描画付き検証はGUIアクセスを許可して実行した。
- Oggを再生したまま即座にquitすると、音声スレッドの再生オブジェクトが終了時に残った。全AudioStreamPlayerをstopしstreamを解放、音声スレッドが停止を取り込む時間を設けてから終了すると警告が消えた。通常のウィンドウ終了にも同じ処理を使った。
- selfcheckは通常セーブと別の検証専用ファイルで保存・再読込を確認する。描画検証は `--no-save` で起動し、通常セーブを汚さない。
- 画面を直接キャプチャする開発スクリプトは、GodotのviewportだけをPNGへ保存するため、デスクトップの通知や他アプリが写り込まない。

## 再現するコマンド

```sh
cd /Users/bannzai/ghq/github.com/bannzai/godotpractice/games/dungeonlite
make run
make test
make screenshot
```

`selfcheck.gd` は戦闘・報酬・恒久強化・セーブ・seed再現・6室踏破を検証する。`playcheck.gd` は実際のボタンとキーイベントで画面遷移を確認し、焚き火・戦闘・一時停止・回避・強化選択・死亡・ボス・クリアを撮影する。到達画面を網羅するため、敵HPやプレイヤー位置を準備する検証fixtureを含み、その通過を無補助プレイのクリアとは扱わない。

別途、一時スクリプトで通常の移動・攻撃・回避・扉操作・強化選択だけを使う戦闘シミュレーションを実行した。恒久強化なし、初期体力・威力のまま、敵AIと弾を1/60秒刻みで進め、seed 8192 / 77 / 12345でいずれも6室踏破した。体力・敵位置・攻撃力・待ち時間の書き換えはせず、各回90欠片を持ち帰った。ゲーム時間は約53〜70秒。これは熟練した自動操作の成立確認であり、人間の初見プレイ時間の見積もりではない。
