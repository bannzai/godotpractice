# rhythm の実装知見

## 作品と設計判断

- オリジナルの「星灯りのリズム便」。夜の街へ音楽を届けるキツネ・トリ・ウサギの奏者を題材に、タイトル・選曲・演奏・成功/失敗結果・再演奏を構成した。進行と記録の唯一の保存先を RhythmState とし、判定と保存値の検証を rhythm_rules.gd に分離した。
- 3曲それぞれに60〜90秒の独自音源と2難易度のJSON譜面を持つ。音源先頭を第0拍、譜面開始を第8拍以降とし、導入中に操作を把握できるようにした。長押しは開始時の判定を保持し、終端で確定する。途中離しはミス、別レーンの演奏は継続できる。
- スコアは譜面のノーツ数で正規化して最大100万点。空打ちはコンボ切断・ゲージ減少・減点とし、無差別な連打で成功できない。曲終了時のゲージが60%以上なら成功。ランクと精度は判定内訳から計算し、曲・難易度ごとに最高記録を保存する。
- キャリブレーションは入力が遅れる方向を正の値とし、補正値を音声位置から引く。ノーツの表示と判定も同じ補正後の時刻を使う。音声を停止するヒットストップは同期を壊すため、成功時の停止感は奏者の姿勢だけを短時間止めて表現する。

## 素材と表現

- Python標準ライブラリでSVGと多音色の音声を独自生成し、ffmpegでOGGへ変換した。3人のシルエット・顔・衣装・楽器を描き分け、1キャラ1シートに待機・踊り・成功・ミス・祝福の5状態×4フレームを配置した。腕・楽器・耳・目などの部位も変化させる。
- AnimationPlayerの離散frameトラックと、位置・回転・伸縮・色の連続トラックを併用する。拍に同期する踊りは音声拍からseekし、命中・ミス・祝福は短い独立した反応として再生する。
- 背景は空・街・手前の電飾の3層で異なる速度を持つ。Compatibilityで動くcanvas_itemシェーダの薄い光を加え、ノーツとHUDのコントラストを優先した。Theme、ホバー、遷移、数値カウント、パーティクル、命中フラッシュ、ミス時の揺れを統一した。
- 手続きSVGは輪郭と部品の反復変更、フレームの規則的な生成に向く。一方、絵筆の質感や自然な体のひねりを表現する方法としては限界がある。今回は読み取りやすい平面的な図案を選択した。
- フォントは既存ゲームと同じM PLUS Rounded 1cをOFL全文付きで同梱。生成物をCC0と断定せず、外部素材を含まない独自生成物としてCREDITSへ記録した。

## 検証で見つかった問題

- macOSのsandboxでは、Godotの通常ログ・editor_settingsの保存が作業範囲外となる。importがexit 0でも保存ERRORが出るため、ログ全文の検査が必要。作業範囲内のself-contained Godotと絶対パスのlog-fileでheadless/exportを実行した。描画やCoreAudio、TailscaleのOSサービスへの接続には通常権限での実行を使い、システム設定は変更しなかった。
- Godot既定のui_cancelにはパッドBが含まれる。ミントの入力にBを使うので、キャンセルをEscape/Startへ明示して演奏中の誤中断を防ぐ。
- マウス/タッチの長押しを画面上部で離しても解放する必要がある。一方、ゲームが追跡していない解放を処理済みにすると、中断ボタンのGUIが解放を受け取れない。実InputEventを使うintegrationでこの回帰を検出し、追跡中の解放だけを消費するようにした。
- ログ全文検査は正常な計測名にも一致する。音声同期の計測欄を `error_ms` とするとERROR検索に引っ掛かったため、意味を保った `deviation_ms` に変更し、検査自体は緩めていない。
- 通常終了は音声停止とstream解放後に0.2秒待機する。フレーム数による終了では_exit_treeで回収を待つ。Movie Makerでは末尾15フレームを音声の解放区間にし、映像のシーンは維持する。

- 記録は最高スコアとクリア経験を分離する。後から高スコアの失敗を記録しても過去のクリアを失わせない。長押し終端と通常ノーツのMiss期限は期限順に処理し、フレーム飛びの有無でコンボやゲージが変わらないようにした。どちらもselfcheckに回帰検証を追加した。

## 音声同期

- `get_playback_position() + get_time_since_last_mix() - get_output_latency()` を時計にし、ミックス境界の小さな逆行をStateで抑制する。BGMはWebもストリーム再生に統一する。
- 公式資料: https://docs.godotengine.org/en/stable/tutorials/audio/sync_with_audio.html
- 実入力の統合検証はDummyとmacOSのCoreAudioで行う。再生が進むこと、補正式との差、補正後の最初の拍をFキーでPerfectにできること、判定線に換算した距離をログへ残す。これはエンジンと音声ドライバの測定であり、スピーカーとディスプレイを外部機器で測った物理的遅延の保証ではない。

## 共有物・skillへの提案

- godot-developmentへ、リズムゲームの実音声時計と譜面の判定時刻を照合する検証、長押し解放とGUIイベントの両立、演出だけを止める同期維持の例を追加したい。
- 画像生成と同じスクリプトで全音声を再生成すると、画像修正が重くなる。今回の `--images-only` のように素材種類を絞る入口をgame-asset-searchの手続き生成例にすると再利用しやすい。
- 知見ファイルの更新だけでも現CIは全ゲームを検証する。`documents/knowledge/<slug>.md`を当該ゲームへ対応付ける改善を共有側へ提案する。今回、ルートのMakefile・CI・rulesは変更していない。

## 最終検証

- ローカルの `make test GAMES=rhythm`、`make screenshot GAMES=rhythm`、`make movie GAMES=rhythm`、`make build-all GAMES=rhythm`、`make build-web GAMES=rhythm`、`make rhythm-run` はすべてexit 0。通常起動では専用の実入力シナリオでF11の全画面化とウィンドウ復帰、終了通知まで確認した。
- 17枚の代表画面・奏者ごとの5状態の連続フレーム・命中とミスの途中を目視した。26.03秒の `movie-play` は2秒間隔の一覧と末尾を目視した。録画は最初の約20秒を等速演奏し、その後は音声と時計を同時に終盤へseekする。省略区間は通常のMissとして処理し、録画中に省略の表示を出す。
- 全6譜面は実InputEventで完走し、各譜面のPerfect完走が100万点となることを検証した。別のシナリオでGood/Miss・途中離し・複数入力源の長押し・途中中断・失敗・再演奏・保存を検証した。物理ゲームパッドの接続は未検証で、ボタン割当とInputEventJoypadButton経由の演奏は検証済み。
- CoreAudioの実再生時計を使ったローカル検証では、補正後の最初の拍に対する入力差が8.712ms、判定線換算で2.962pxとなりPerfectだった。スピーカー出力とディスプレイ表示の物理測定、Windows/macOS/Linuxの全実機での聴感比較は行っていない。
- 各Godotログの全文を検査し、正常終了・フレーム指定終了を含めて警告、エラー、ObjectDBやresourceのリーク出力がないことを確認した。
- CI run `34035372020` は全ジョブ成功。artifactの17枚と5秒動画の1秒間隔・末尾を目視し、欠け・重なり・黒画面なし。Linux llvmpipeの既定除外であるV-Sync警告以外に警告・エラー・終了リークなし。
- webtunnel run `34046888349` で自分のブランチのWeb版をChromiumから操作し、タイトル→選曲→演奏→72秒の曲終了による失敗結果→選曲への復帰と記録表示を撮影・目視した。ブラウザエラー出力は空だった。成功結果はローカルの全譜面演奏と代表画面で検証した。
- 前回のWeb検証ではCDPの撮影がタイムアウトした一方、webtunnel標準プレビューから実画面を取得できた。再開後は同じコードの新セッションでagent-browserの操作・PNG撮影が成功した。撮影の失敗だけでゲームの描画失敗と判断せず、実画面と接続状態を分けて確認するとよい。
