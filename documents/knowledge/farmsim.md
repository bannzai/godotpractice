# こもれび農園の開発知見

## 設計と判断

issue #37 の農場生活シムを、春と夏を過ごす小さな絵本として実装した。主人公、種屋の商人、鶏を独立したスプライトシートにし、作物・建物・道具・背景も用途別の画像に分けた。初回実装では Python から生成するオリジナル SVG と M PLUS Rounded 1c を使い、後述の手直しラウンドで CC0 写真を加工した PNG と Yomogi へ置き換えた。音は倍音・撥弦・木管・打楽器を重ねた合成 WAV を維持し、農村の環境音と木を打つ移動音を追加した。制作方法と出典はゲーム内の `assets/CREDITS.md` に記載する。

農業・経済・日付・所持品・保存は Farm autoload、画面遷移と操作は main、地形表示は farm_world、キャラの再生は farm_actor に分けた。畑には Godot 4 の TileMapLayer と TileSetAtlasSource を使う。道具は向いているマスに届き、歩行は8方向。メニューを開いている間は時間と移動を停止する。

各作物の季節・成長日数・種価格・売値、食べ物の価格・回復量は Farm の定義を表示にも使う。翌朝に出荷精算・勝敗判定・作物の成長と乾燥・体力回復をまとめて処理し、最終日の出荷にも代金が付く。季節をまたいだ作物は枯れ、クワで片づけられる。井戸の近くで調べられるが、ジョウロは補充の往復を必要としない設計にした。

アートの方向、20日間の長さ、目標金額、音楽の好みは本番制作で再調整できる判断点。初回は既存作品の固有素材を使わず、丸い輪郭・深緑・クリーム・琥珀色の UI と手続き生成の絵本調を採用したが、他ゲームとの差が弱かった。手直しではゲームの規則を変えず、昭和の年賀状に刷った芋版、農家の日記帳、母の手紙、版画の村地図へ表現を限定した。

## 手直しラウンド（見た目の特色化）

### 分かりにくかった原因と効いた表現

初回画面は上の HUD、下の横長な共通操作ガイド、右の手帳、淡い多層背景という構成が他ゲームと共通していた。選択中の道具は分かっても、向いた畑で実行できるか、実行すると何が起きるか、町で次に何を選ぶかは操作して結果を見るまで分からなかった。町の種屋も農場に重なるモーダルだったため、農場と町を往来している感覚がなかった。

次の変更が特に効いた。

- 所持金・日付・体力・出荷・道具を右側の「農家の日記」一枚へ集約し、画面下の共通操作ガイドを廃止した。日記には向いたマスの結果を常に「○ / ×」と理由で表示する。
- 実行できる畑を黄緑、実行できない畑を朱色で囲み、家・井戸・出荷箱・村への道も近づいた時だけ濃く囲む。操作ボタンを探す前に対象と可否が分かる。
- 初回だけ母の手紙を出し、スキップ可能にした。続行時はクワ、種、水を一マスで順に成功させるたび、次の道具へ自動で切り替える。
- 町への移動を独立した版画の村地図にし、農場と種屋の間を印が歩く。行き先ボタンの下に「そこで何ができるか」を書いた。
- 写真の濃淡、古紙、茶墨・深緑・朱・黄土、Yomogi の細い筆致を全画面でそろえた。タイトル・村地図・農場を citybuilder、monsterquest、survivalcraft と同じ縮尺で並べても、農家の日記と版画として識別できた。

### CC0 写真を版画素材にする手順と比較

`game-asset-search` のライセンス表に従い、Wikimedia Commons の個別ファイルページで作者と CC0 1.0 を確認した。古紙、山間の農場、かぶ、にんじん、トマト、とうもろこしの原写真を `assets/source_photos/` に残し、URL・作者・ライセンス・加工内容を `assets/CREDITS.md` に記録した。検索結果のサムネイルや転載ページは根拠に使わなかった。

Pillow では固定サイズへトリミング後、グレースケール、自動コントラスト、弱いぼかし、固定閾値の3値化、茶墨・作物色・紙色への写像、古紙との乗算、固定座標の細い欠けを順に適用した。背景は写真全体、作物は写真の色面を成長段階ごとのマスク内だけに使った。キャラクター、小物、地形、UI は固定座標の図形を PNG へ直接描き、旧 SVG は残さなかった。再生成は入力写真とコードが同じなら同一 SHA-256 になる。

当たりだったのは、遠景の山と農地が大きな色面へ分かれる古い白黒写真、繊維の明暗が弱い古紙、作物を小さな輪郭マスク内の質感として使う方法だった。写真らしさを残し過ぎる多色化は UI と衝突し、細部の多い写真を単純な二値化だけにすると黒い塊になった。3値化前の弱いぼかしと、画面全体で5色程度に制限する方が安定した。かすれを乱数にすると再生成比較が難しいため、位置を固定した。

手続き SVG だけの初回は容量が小さく、座標と色をコードレビューしやすく、ライセンス確認も自作一件で済んだ。一方、輪郭と配色が他ゲームの生成物に寄り、Godot と外部ビューアで透明色の解釈が違う問題もあった。CC0 写真の加工は候補探し、各原典のライセンス確認、原写真の保管、閾値調整に手間が増えるが、土地の不規則な陰影と紙目が一度で入り、固有性が強い。PNG は画素結果を直接確認でき、Godot の SVG 解釈差も避けられた。検証は生成 SHA-256 と寸法・形式の自動検査に加え、原寸スクリーンショットの目視を必須にする。

### Godot で日記帳 UI を作る時の注意

- `refresh()` は現在のページとモーダルを破棄するため、新規開始の母の手紙は農場ページ生成後に `call_deferred()` で開く。再開時にはチュートリアル状態を明示的に解除する。
- 畑の結果プレビューは状態を変えない `Farm.tool_preview()` に集約し、日記の文章とワールド上の色枠で同じ判定を使う。実行関数とは分け、UI 更新のたびに呼んでも状態を進めない。
- 農場と村地図を別の `mode` にすると、農場の時計・移動を地図の背後で進めずに済む。地図はボタンのフォーカス移動と Esc / B の帰還を実入力テストに含める。
- Yomogi は細いので、小さな文字を薄色にすると紙目へ埋もれる。主要情報は18px以上と茶墨を使い、補助文だけ色を弱めた。画像化した文字は使わず、ローカライズ可能な Label と Button に残した。
- `CanvasItem` の描画順により TileMapLayer の下へ隠れないよう、対象枠は最後に追加した overlay の `draw` シグナルで描く。可否色は状態更新だけでなく毎フレームの向きにも追従させる。

### skill 化の候補

- `game-asset-search`: Wikimedia Commons の API で原寸 URL・作者・ライセンスを取得し、原写真の保存名、加工物、CREDITS の対応を一括検査する手順。写真の二値化・3値化・共通パレットを比較する小さなコンタクトシート生成も候補。
- `godot-development`: 状態を変えない結果プレビューを UI と対象ハイライトで共有する例、ページ再生成後の初回モーダル、別 mode の背後で時計を止める実入力検証を追加する案。

## 実装中に得た知見

- **保存位置と通行判定を共通にする。** 数値として画面内の座標でも、建物や井戸の内部なら再開後に動けない。保存データの座標検証と実際の移動に同じ `Farm.can_walk()` を使い、施設前の正常座標と家・井戸・木・池・右下端の不正座標を検証する。
- **CanvasItem の親の描画は子の下になる。** 農場の親 `_draw()` に選択枠を描くと、不透明な TileMapLayer に隠れる。選択枠と畑の境界は最後に追加した Node2D の `draw` シグナルで描く。
- **UI と時刻の照明を分ける。** CanvasModulate の農場と UI を別 CanvasLayer に置くと、夕方の光で HUD や手帳まで暗くなることを防げる。多層背景はさらに別のレイヤーに置いた。
- **InputMap の存在だけでは不十分。** 道具の実行と UI の決定キーを分け、プレイ中の調べる入力は `_input()` で消費する。メニューの背面ボタンを無効にし、時間と移動を止める。検証中に D キーで移動停止を確かめた後、GUI のフォーカスだけ右に移動していることもあるため、操作後の画面を検査する。
- **SVG の透明度指定は実エンジンで確かめる。** 外部の SVG 描画では半透明だった `#RRGGBBAA` が、Godot の実画面では黒い雲・影・眼鏡になった。`fill="#RRGGBB" fill-opacity="..."` と `stroke-opacity` へ分離し、全画像を再生成した。コード上の構文検査と別の変換器での目視だけでは、この差を見つけられなかった。
- **音源のループ境界を数値でも検査する。** 循環残響だけでは打楽器の先頭振幅と端数サンプルで接続差が残った。BGM終端8msを滑らかにつなぎ、全5曲のPCM端点差0、全14音源のクリッピング0を確認した。再生成のSHA-256も全51ファイルで一致した。数値検査は聴感の好みを保証するものではない。
- **素材に動作があることとゲーム中で再生することは別。** 主人公の農作業に加え、商人と鶏にも待機・移動・水/挨拶・収穫/羽ばたき等の再生を割り当てる。キャラ別の連続撮影で、開始・途中・終盤の実再生を確認する。
- **音声停止と解放は別。** 既存ゲームで実測した終了方法を踏襲し、通常終了は音声停止後にフレームを進め、フレーム数指定終了では `_exit_tree()` でも停止してミキサーの処理を待つ。Movie Maker は音がフレーム同期なので、専用スクリプトが録画末尾の12フレーム前に音声だけを止める。
- **サンドボックスとゲームの不具合を区別する。** 最初の Git 操作は worktree の共有 Git 管理領域への書込みで拒否された。依頼済みの commit・push は権限を上げて実施した。Godot は全起動へ絶対パスの `--log-file` を渡し、作業ディレクトリ内の self-contained バイナリと既存テンプレートへの symlink を使った。新しい `config/name` は別の `user://` 保存先作成を引き起こすため、識別子は元の farmsim のままにし、ウィンドウの表示名を日本語にした。
- **Tailscale の異常終了を未接続と即断しない。** preflight はサンドボックス内で `tailscale status` が Abort trap になったが、同じ読取りを通常権限で実施すると READY だった。新しい認証情報の発行や設定変更は不要だった。
- **待機コマンドの失敗と runner の失敗を分ける。** webtunnel の起動待ちは GitHub API のタイムアウト後に run が存在しないと表示したが、run を直接確認すると稼働しており、CDP へ接続できた。スクリーンショット取得も daemon の応答失敗後に PNG が生成されていたため、終了コードだけで撮影の有無を決めず現物を確認した。

## 検証と証拠

ローカルの Godot 4.7 / GL Compatibility で次を実行し、すべて exit 0 を確認した。描画付き起動では macOS の XPC 接続制限が出たため、通常権限で実行した。ゲームコードの変更やシステム設定の変更は不要だった。

| コマンド | 確認内容 |
| --- | --- |
| `make test GAMES=farmsim` | ロジック276件、実入力、保存・再開、アセットと終了検証 |
| `make screenshot GAMES=farmsim` | 35 PNG、F11の実キー往復、3体×6動作×3コマの実再生到達 |
| `make movie GAMES=farmsim` | 5秒・150フレームの起動録画 |
| ゲームディレクトリの `make movie-play` | 26秒・780フレームのプレイ録画 |
| `make build-all GAMES=farmsim` | macOS・Windows・Linuxへ書き出し |
| `make build-web GAMES=farmsim` | HTML・WASM・PCKへ書き出し |
| `make farmsim-run` | `RUN_FLAGS` で通常終了と60フレーム終了を指定し、実ウィンドウの起動・終了 |
| `generate_assets.py --verify` | 全51素材の再生成SHA-256一致、全14音源のクリップ・無音なし |

最終検証18ログの全文でエンジンの WARNING / ERROR と終了時リークがないことを確認した。通常終了に加え、`--quit-after` の1・8・40・150フレームも検証した。代表画面35枚と各キャラの動作を一覧で目視し、録画は2秒間隔のフレーム一覧と末尾を確認した。

26秒の録画は、成長待ちを収めるため「春10日・840 G・隣に収穫可能なかぶ」を開始時の条件とした。以後は実入力だけで耕す・植える・水やり・収穫・出荷・家で就寝・900 G達成・タイトル復帰へ進めた。初期条件と操作途中の書き換えを区別して記録することで、録画が検証した範囲を明確にできる。

実装コミット `96a47e3` の CI run `34035220490` は全31ジョブが成功した。`farmsim-screenshot-and-movie` のZIPはGitHubのdigestとSHA-256が一致し、35 PNGとmp4のフレーム一覧・末尾を目視した。CIの描画ログには llvmpipe の V-Sync 非対応警告が各1件あるが、ERROR・終了時リークはない。Actions基盤のNode.js非推奨警告はゲームのログと分けて扱った。

Web版は `game/farmsim` を `--software-webgl` で書き出したrunner上のChromiumで確認した。新規農場から耕す・植える・水やり・翌朝の成長・収穫・出荷・就寝後の60 G受取り・商店での種購入・春から夏への変更・20日間の結果・タイトル復帰を実際に操作した。ゲーム状態の注入は使っていない。最終結果は所持金165 G・売上60 G・出荷1個で操作内容と一致した。前のセッションでは深夜の強制翌日と12 Gのペナルティも画面で確認した。

Webでの長い連続入力は、操作が進んでいてもagent-browserの応答読取りがタイムアウトすることがあった。失敗と表示されても同じ操作を再送せず、別接続のスクリーンショットで現在地を確認した。以後は3日分以下に区切り、ベッドの確認画面で時間を止めてから次の入力へ進めた。1280×656のブラウザでは16:9のゲームが左右に余白を付けて表示され、文字とUIの崩れはなかった。

画面・キャラの連続フレーム・録画のフレーム・CI画像・Webの操作画面を puts へ掲載し、公開URLから取得した画像のSHA-256を原本と照合した。PR #48 の検証欄に埋め込んだ。

## 再利用する skill・ツールの候補

- godot-development: 保存データの座標を通行判定で検証する農場・見下ろしゲームの例、メニュー内のフォーカスと移動停止を組み合わせた実入力検証。
- game-asset-search: キャラ別の動作フレームを Godot で再生して撮影する検証、循環する BGM の境界と音量の検査。
- webtunnel: サンドボックス内の Tailscale 異常終了と設定不足、GitHub API のタイムアウトとrun失敗を区別する診断。操作は応答期限より短い区切りにし、応答不明時には画面確認を挟む。
- CIの変更検出: `documents/knowledge/<slug>.md` だけの変更でも全ゲームを検証する現行判定について、知見文書を対応するゲームに限定できるかを司令塔で検討する。

共有の規約・Makefile・workflow・skill はこのゲームの変更範囲に含めず、上記を改善提案として残す。
