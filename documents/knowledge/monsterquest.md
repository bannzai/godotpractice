# こもれびの調査隊 — 開発知見

## 実装方針

- オリジナルのモンスター収集RPG。町・草むらのルート・自宅・回復施設を歩き、捕獲と育成を経て町の調査隊長に挑む。
- 種族と技の定義は Catalog、進行状態と保存は Game autoload に集約する。画面は状態を表示し、戦闘イベントを順番に演出する。
- 現行 Godot の TileMapLayer と TileSetAtlasSource でグリッドを描画する。TileMap は非推奨のため、同じタイルマップの役割を TileMapLayer が担う。
  https://docs.godotengine.org/en/stable/classes/class_tilemaplayer.html
- 描画素材はオリジナルSVG、音源は独自合成、日本語フォントは同梱可能なOFLを採用する。

## 検証計画

純粋ロジック・保存の異常入力・実シーン操作を selfcheck で検証し、代表画面と攻撃中の画像を撮影する。ローカルとCIの動画をフレーム抽出して確認し、デスクトップ3種とWebをエクスポートする。

## 判断点

現時点でユーザーの判断が必要な未確定事項はない。実測した知見と検証結果は実装後に追記する。

## 実測した知見

- Godot 4.7 の実行時 `ui_accept` にはゲームパッド A が無かった。InputMapに `interact` のAだけを足してもButtonは反応しない。`ui_accept` と方向の `ui_*` にキーボード・パッド・左軸を明示し、`Input.parse_input_event` で実画面へ配送する検証を追加した。
- TabはGUIのフォーカス移動に先に消費される。メニューの開閉は `_input` で処理し、UI決定とぶつからない状態でのみ処理する。
- モーダルを描画で重ねるだけでは、背面ボタンを方向キーやクリックで押せてしまう。背面ボタンを無効化し、新しいメニューの最初のボタンへフォーカスする。プレイヤーの高いz_indexもメニューより手前へ飛び出すため、同じ描画順の中で扱う。
- macOSの全画面切替はアニメーションを伴う。F11往復検証はモード変更を待ち、次の操作まで1秒置く。0.2秒だけの待機では2回目の入力が配送されなかった。
- `--quit` や `--quit-after` による音声再生中の終了で AudioStreamPlaybackWAV / AudioStreamWAV のリーク警告を再現した。起動検証では再生開始を2フレーム待つ。録画は専用SceneTreeで末尾12フレーム前に音声停止し、描画を維持してから終了する。通常のウィンドウ終了でも停止後に音声サーバーへ反映する時間を置く。警告を検査対象から外す回避は行わない。
  https://github.com/godotengine/godot/issues/76745
- `.gitignore` の `tmp/` だけではGodotの素材走査を止められず、撮影済みPNGがインポート・エクスポートされていた。ゲームのMakefileが `tmp/.gdignore` と `build/.gdignore` を作り、exportの除外にも `tmp/*,build/*,scripts/dev/*` を指定する。
- 保存用JSONの数値はfloatとして読み込まれる。境界・整数性・必須項目・不明キー・種族・歩行可能座標を検査してから個体の数値をintへ戻す。破損JSONは `JSON.new().parse()` で判定し、現在の冒険を維持する。保存は一時ファイルからrenameし、検証用保存先はプロジェクトの `tmp/` に閉じる。
- SVG・WAVを標準ライブラリの生成コードから出すと、外部画像サービスに依存せず形と配色を揃えられる。再生成時のSHA256一致、素材記録漏れ、フォントのOFL同梱を検証した。

## 検証の範囲

- selfcheckはデータ整合、3タイプの全相性、既知のダメージ値、行動順、経験値・技習得、全滅とクリア、捕獲成功/失敗、7体目の預かり、交換、保存正常/異常系を検証する。
- 地形はBFSで全歩行セル・全草むら・建物と隊長の隣への到達、入口の往復、衝突と移動先の整合を検証する。
- 実入力検証はタイトルでA→矢印/WASD/方向パッド/左スティック移動→Startで手持ち→Aで先頭交代→Tab/Escで閉じる→隊長との対話→戦闘→攻撃演出完了を追う。撮影時は描画ありでF11の往復も検証する。
- スクリーンショットはタイトル、遊び方、町、ルート、自宅、回復施設、手持ち、預かり、野生戦、攻撃途中、隊長戦、クリア、全滅、タイトル復帰の14画面。
- ゲームパッドは仮想の実入力イベントをエンジンに配送する検証であり、USB/Bluetoothの実機認識は対象外。Windows/Linux/Webはビルド検証、Linuxの実描画はCIのXvfbで検証する。

## 共有skillへの改善提案（このPRでは共有物を変更しない）

- godot-development: InputMapの定義だけでなく、Buttonへゲームパッド入力を配送する検証雛形を追加する。
- godot-development: 録画末尾の音声停止と `tmp/` / `build/` の `.gdignore` 生成を雛形に取り込む。
- game-asset-search: SVGと加算合成WAVをコードで生成する場合の、再現性・音量・ライセンス記録の例を追加する。
