# こもれびの調査隊 — 開発知見

## 実装方針

- オリジナルのモンスター収集RPG。町・草むらのルート・自宅・回復施設を歩き、捕獲と育成を経て町の調査隊長に挑む。
- 種族と技の定義は Catalog、進行状態と保存は Game autoload に集約する。画面は状態を表示し、戦闘イベントを順番に演出する。
- 現行 Godot の TileMapLayer と TileSetAtlasSource でグリッドを描画する。TileMap は非推奨のため、同じタイルマップの役割を TileMapLayer が担う。
  https://docs.godotengine.org/en/stable/classes/class_tilemaplayer.html
- 現行の描画素材はCC0原典を加工した人物と直接描画を組み合わせた4階調PNG、音源は独自合成、日本語フォントはOFLのDotGothic16を採用する。第2ラウンドまでのSVGは履歴資料として残すが、本番画面からは参照しない。

## 検証計画

純粋ロジック・保存の異常入力・実シーン操作を selfcheck で検証し、代表画面と攻撃中の画像を撮影する。ローカルとCIの動画をフレーム抽出して確認し、デスクトップ3種とWebをエクスポートする。

## 判断点

現時点でユーザーの判断が必要な未確定事項はない。実測した知見と検証結果は実装後に追記する。

## 実測した知見

- Godot 4.7 の実行時 `ui_accept` にはゲームパッド A が無かった。InputMapに `interact` のAだけを足してもButtonは反応しない。`ui_accept` と方向の `ui_*` にキーボード・パッド・左軸を明示し、`Input.parse_input_event` で実画面へ配送する検証を追加した。
- TabはGUIのフォーカス移動に先に消費される。メニューの開閉は `_input` で処理し、UI決定とぶつからない状態でのみ処理する。
- モーダルを描画で重ねるだけでは、背面ボタンを方向キーやクリックで押せてしまう。背面ボタンを無効化し、新しいメニューの最初のボタンへフォーカスする。プレイヤーの高いz_indexもメニューより手前へ飛び出すため、同じ描画順の中で扱う。
- macOSの全画面切替はアニメーションを伴う。F11往復検証はモード変更を待ち、次の操作まで1秒置く。0.2秒だけの待機では2回目の入力が配送されなかった。
- `--quit` や `--quit-after` による音声再生中の終了で AudioStreamPlaybackWAV / AudioStreamWAV のリーク警告を再現した。起動検証では再生開始を2フレーム待つ。録画は専用SceneTreeで末尾12フレーム前に音声停止し、描画を維持してから終了する。通常のウィンドウ終了でも停止後に音声サーバーへ反映する時間を置く。警告を検査対象から外す回避は行わない。
  https://github.com/godotengine/godot/issues/76745
- `.gitignore` の `tmp/` だけではGodotの素材走査を止められず、撮影済みPNGがインポート・エクスポートされていた。ゲームのMakefileが `tmp/.gdignore` と `build/.gdignore` を作り、exportの除外にも `tmp/*,build/*,scripts/dev/*` を指定する。
- 保存用JSONの数値はfloatとして読み込まれる。境界・整数性・必須項目・不明キー・種族・歩行可能座標を検査してから個体の数値をintへ戻す。破損JSONは `JSON.new().parse()` で判定し、現在の冒険を維持する。保存は一時ファイルからrenameし、検証用保存先はプロジェクトの `tmp/` に閉じる。
- SVG・WAVを標準ライブラリの生成コードから出すと、外部画像サービスに依存せず形と配色を揃えられる。再生成時のSHA256一致、素材記録漏れ、フォントのOFL同梱を検証した。

## 検証の範囲

- selfcheckはデータ整合、3タイプの全相性、既知のダメージ値、行動順、経験値・技習得、全滅とクリア、捕獲成功/失敗、7体目の預かり、交換、保存正常/異常系を検証する。
- 地形はBFSで全歩行セル・全草むら・建物と隊長の隣への到達、入口の往復、衝突と移動先の整合を検証する。
- 実入力検証はタイトルでA→矢印/WASD/方向パッド/左スティック移動→Startで手持ち→Aで先頭交代→Tab/Escで閉じる→隊長との対話→戦闘→攻撃演出完了を追う。撮影時は描画ありでF11の往復も検証する。
- スクリーンショットはタイトル、遊び方、町、ルート、自宅、回復施設、手持ち、預かり、野生戦、攻撃途中、隊長戦、クリア、全滅、タイトル復帰の14画面。
- ゲームパッドは仮想の実入力イベントをエンジンに配送する検証であり、USB/Bluetoothの実機認識は対象外。Windows/Linux/Webはビルド検証、Linuxの実描画はCIのXvfbで検証する。

## 第 2 ラウンド (品質向上)

### 方向と検証方針

森の調査手帳をテーマに、アイボリー・深緑・真鍮色を基調とした絵本調へ整える。種族・相性・捕獲・育成・保存のルールは維持し、主人公・各種族・隊長・回復係・隊長の相棒を独立した素材とフレームアニメーションで描き分ける。

既存の14画面撮影と入力検証は変更前に成功した。追加する検証は、全キャラの待機・移動・攻撃・被弾・戦闘不能の連続フレーム、各演出の途中、実入力による20〜30秒のプレイ録画、通常終了とフレーム指定終了、Web実操作。検証結果と実測した知見は実装後に追記する。

### 実装中に確認したこと

- SVG の構文検査や rsvg-convert の成功だけでは Godot の表示を保証できない。入れ子の `<svg>` を使ったシートは Godot 4.7 で警告なしの透明画像になった。フレームは `<g transform="translate(...)">` で並べ、Godot がインポートした画素に透明だけのフレームが無いことを selfcheck でも検査する。
- 1体192px、6列×5動作の素材を `AnimatedSprite2D` に切り出した。待機・移動は繰り返し、攻撃・被弾・戦闘不能は末尾で停止する。移動状態を同じ値で再設定しても先頭へ巻き戻さず、終了済みの同じ動作を再実行するときだけ先頭へ戻す。
- キャラのシルエット・装備・目・翼・足・口を作り分けた。手続きSVGは配色と透過余白を統一しやすい反面、描画コードの変数上書きで樹木全体が画面外へ移ることもあった。再生成の一致だけでなくゲーム内の再撮影が必要。
- タイルの画像を独立した `TileSetAtlasSource` へ分けても、通行可能セル・草むら・入口のロジックは維持できる。建物・家具・小物も個別SVGへ分離し、水面のシェーダと花粉をGL Compatibilityで動かした。描画順を親画面内に閉じると、メニューより花粉やNPCが前へ出ない。
- 戦闘はターン全体を先に解決するので、画面から現在HPだけを読むと反撃前に最終HPが表示される。攻撃・回復イベントにその行動直後のHPと技の属性を持たせ、着弾時からゲージと数値を更新する。戦闘不能と自動交代も順に表示する。
- `ProgressBar` は親テーマ・割合文字の設定前にsizeを指定すると既定の最小高さで大きくなった。親へ追加してからsizeを設定するとHPの数値と重ならない。残HPの色はゲージ全体のmodulateではなく塗りのStyleBoxだけを変え、空のゲージを満タンのように見せない。
- 通知を地図の最下部へ重ねると室内の出口セルを覆っていた。通知をヘッダーの2行目へ移し、歩ける範囲と出口を常に見えるようにした。
- BGMは木管・撥弦・ベル・マレット・弦・打楽器を合成し、タイトル・探索・戦闘・隊長戦・結果で旋律、速度、拍子を分けた。末尾の発音と残響を先頭へ循環加算するとループ切断を避けられる。32kHzステレオ11音源は再生成のSHA256、クリッピング、無音、ループ境界を検査し一致した。CoreAudioによる再生は成功したが、聴感の主観評価とは区別する。

### 音声の終了処理

`AudioStreamPlayer.stop()` は再生停止を要求するだけで、音声ミキサーが次のミックスでフェードと削除を処理する。`_exit_tree` 内で停止・streamの解放だけを行うと、通常の `--quit-after 8/40/150` でWAVと再生インスタンスが残った。終了直前は次フレームをawaitできないため、停止後に150ms待つとheadlessとCoreAudioの両方で警告が消えた。CoreAudioの実測では再生位置と音量ピークも確認し、音声を鳴らさない回避ではないことを確認した。

Movie Makerは音声をフレーム同期で処理するため、終了時の待機だけでは解放が進まない。`movie.gd` と `demo.gd` では末尾12フレーム前に停止し、描画を続ける処理を維持する。通常のウィンドウ終了要求では停止後にタイマーで待機する。

`--quit-after` はエンジンで消費され、`OS.get_cmdline_args()` からは読めない。引数を読み取って終了前に停止する実装は使わなかった。

参照:
https://github.com/godotengine/godot/pull/122742
https://docs.godotengine.org/en/stable/classes/class_os.html#class-os-method-get-cmdline-args

### 自動撮影と録画

- 撮影は36枚。10体の全5動作を実際に再生し、frame_changedで開始・途中・終盤を捕捉した5行×3列の一覧をキャラごとに出力する。静止画の差し替えではフレーム再生を検証できないため、selfcheckでも経過時間に応じた進行と非ループ動作の完了を確認する。
- 戦闘の撮影条件に注意が必要。Lv14では最初の技が最大4技から押し出されており、古い技IDを投入してもエラーではなく「まだ使えない」と返る。撮影条件を習得中のレベルへ直し、HPが減り、選んだ技のメッセージへ到達したことを検査してから撮影する。
- `make -C games/monsterquest movie-play` は26秒・30fps・780フレーム。初期条件だけコハネLv15・経験値179へ設定し、その後は実キーとマウスイベントで、タイトル→12歩移動→隊長対話→戦闘→成長→クリア→タイトルまで進める。セーブは読み書きしない。2秒間隔のPNGも同targetが生成する。
- `make -C games/monsterquest run` で通常起動し、対象Godotプロセスのウィンドウとbootを確認して、そのプロセスだけへmacOSの通常終了要求を送った。makeはexit0で戻り、終了警告も無かった。ルートの `monsterquest-run` 追加PRが未マージのため、指示書にある代替コマンドを使用した。

## 手直しラウンド (見た目の特色化)

### 着手前の状態と方針

変更前のタイトル・町・ルート・戦闘・遊び方を `make screenshot GAMES=monsterquest` で撮影し、36枚の生成とログの成功を確認した。現行版は絵本調のパステル配色と、上に地名・右に状態表示・下に共通操作ガイドを置く構成である。選択中の結果や利用できない理由は操作前に表示されず、町とルートの関係を一枚で見る地方図も無い。

今回は戦闘・保存・座標・ポータルの既存ロジックを維持し、表示層と入力案内を中心に差し替える。アートは緑がかった4色のラスタードット絵、戦闘のみ差し色1色とする。UIは最暗色の窓と最明色の枠、`▶` カーソル、縦並びコマンドで構成する。新規冒険だけに短い場面内チュートリアルを出し、メニュー内の地方図で町とルートを結ぶ。

### 分かりにくかった原因と効いた表現

- 変更前は各画面の下に同じ操作一覧があり、プレイヤーが知りたい「この場所で次に何をするか」と「その選択で何が起きるか」が、一般的なキー説明に埋もれていた。町と小径も入口だけで接続され、冒険全体の位置関係を一画面で把握できなかった。
- 共通の操作一覧を廃止し、フィールドの窓には現在地に応じた次の目的、目的セルの`▶`、必要な決定操作だけを表示した。選択画面ではフォーカス中の項目にも`▶`を付け、技なら予想ダメージと相性、捕獲なら見込み率、移動なら到着後の行動を同じ窓内で先に示す。回復薬、預かり、現在地、隊長戦の逃走など、選べない項目にはその場で理由を表示する。
- 初回チュートリアルは実際に一歩動いた時だけ「話す・調べる」へ進み、決定操作で閉じる。Esc・Tab・Startでいつでもスキップできる。独立した説明画面ではなく町の風景に重ねたクラシックRPG窓にしたことで、教わった操作と対象物の対応が見える。
- 地方図は町と小径、途中の節点、隊長側の目的地を一枚の線で結んだ。現在地は無効な選択肢として理由を示し、もう一方を選ぶと場面の目的をプレビューしてから移動する。タイトル・地方図・フィールド・戦闘を同じ4色と黒地の窓で揃え、戦闘の攻撃粒子だけ赤を許可したため、他ゲームとの識別点を画面遷移後も維持できた。

### CC0素材と直接描画PNGの手順・当たり外れ

1. OpenGameArtでCC0の人物素材を探し、配布ページの作者・ライセンス・取得URLを確認して原典PNGを`assets/pixel/source/`へ保持した。取得時のSHA-256を生成スクリプトとクレジットの両方へ記録し、原典のすり替わりを再生成前に検出する。
2. 原典は固定座標で切り出し、最近傍縮小と輝度による4色減色を行った。主人公・隊長・回復係は原典を姿勢の土台にし、帽子・手帳・記章・外套を1px単位で加筆した。モンスター7体、16pxタイル、建物、地方図、UI、属性弾はPythonでラスタ画素を直接描いた。
3. 人物は32×32pxを6列×5動作に並べ、既存の待機・移動・攻撃・被弾・戦闘不能を保った。全PNGについて寸法、許可色、半透明画素の不在、原典ハッシュ、再生成したバイト列との一致を検査し、Godot側でも各フレームが空でないことと実時間で進むことを確認する。

当たりだったのは、CC0素材を完成品として貼るのではなく、人物の重心と歩行姿勢の土台に限定した方法である。直接描画だけより短時間で自然な人体を得つつ、装備の加筆と共通パレットで固有の調査隊員にできた。一方、配布シートごとにセル寸法・余白・背景色が違い、自動検出より明示した切り出し座標と原典ハッシュの方が検証しやすかった。小さなモンスター、タイル、UIは必要な輪郭が明確なので直接描画が速く、外部素材を探してから作風を揃える手間の方が大きい。

第2ラウンドの手続きSVGは、拡大しても輪郭を保てて色や寸法の変更が容易だった反面、Godotのラスタライズ結果、入れ子SVGの透明化、アンチエイリアス、座標変数の誤りを別途確認する必要があった。今回のPNGは解像度変更には弱いが、画素・色・透過を生成時とGodot読込後に同じ単位で検査でき、意図したジャギーと最近傍表示を証明しやすい。46枚を単一スクリプトで再生成して更新0件を確認できるため、手作業のドット絵ファイルより再現性も高い。

### GodotでクラシックRPG UIを作る時のハマりどころ

- `project.godot`の既定フィルタだけに頼らず、TextureRect・Sprite2D・AnimatedSprite2DにもNearestが継承されているか実ノードを走査する。pixel snapと16pxタイルの整数倍拡大を併用すると、TileMapLayerと人物の境界が揃う。
- フォーカスカーソルをButtonの文字列へ足す場合、元の文言をmetadataに保持しないとfocus_enteredのたびに`▶`が増える。無効ボタンはフォーカスできないため、不可理由は無効ボタン自体のmetadataだけでなく、常時見える説明欄にも出す。
- 場面切替の市松ワイプは`refresh()`から非同期で消える。代表画面を撮る時は約0.35秒待ち、遷移途中の証拠だけ別名で0.10秒に撮る。待たずに撮ると、正常な画面でもワイプが大半を覆った画像になる。
- 日本語Labelは幅を指定しただけでは自動改行されない。地方図の狭い説明欄では`AUTOWRAP_ARBITRARY`を明示し、1280×720の実画像で右端の欠けを確認する。
- 町と小径の環境音は同じBGMへ重ねるため、場面切替・室内・戦闘・結果・終了で専用AudioStreamPlayerを停止しstreamを解放する。最初の合成では町が規則的な信号音に聞こえ、小径の高音と連続ノイズは長時間で疲れやすかった。町へ左右の短い会話音と足音を加え、小径のノイズ量と鳥音の周波数を下げた再評価では、町と屋外を音だけで区別でき、耳刺さりもない結果になった。数値検査だけで終えず、実ファイルを音声入力で評価する工程が必要である。
