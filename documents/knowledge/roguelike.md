# 灯守りの深層: 実装と検証の知見

## 制作方針

5階の部屋・通路を潜るターン制探索。濃紺・青緑・琥珀を使う独自の地下遺跡とし、主人公と敵6種類を別のシルエットで制作した。ゲームの状態は RunState、生成は Dungeon、表示は main / board / actor_view に分ける。変更はゲームのディレクトリと本文書に閉じる。

## 実装中に確認したこと

- 生成と敵の行動で乱数生成器を共有せず、同じシード・階で同じ地形を再現する。40シード×5階の連結性・階段への到達を検証する。
- 視界・探索済み地形・ミニマップは同じ Dungeon のデータを参照する。画面は主人公を追尾する範囲だけ描画する。
- SVGのキャラを独立ファイルにし、AnimationPlayer の待機・移動・攻撃・被弾・登場・消滅を組み合わせる。画像と音声は固定内容で再生成できるスクリプトと CREDITS を同梱する。
- 音声終了は既存 deckrogue の停止・解放待ちを参照した。通常終了では待機後に quit、強制終了通知では音声スレッドの排出を待つ。
- Godot 4.7 のローカル起動はログの絶対パス指定だけでは user:// の ObjectDB Snapshots ディレクトリ作成を拒否される場合があった。検証コマンドに通常の権限を与えて起動できた。self-contained mode はエディタ設定を作業ディレクトリへ置く用途であり、この起動時ディレクトリの問題は残った。

## 検証結果

- `make test GAMES=roguelike` は lint・起動・全ロジック・キーボード/パッドボタン/二軸/マウスの実入力まで成功。
- `make screenshot GAMES=roguelike` は29枚を生成。タイトル、探索、道具、未識別と識別後、全5階、番人、勝敗、6種の演出、7キャラ×6動作×3時点を目視した。各階のHUDと画像ハッシュも照合した。
- `make movie GAMES=roguelike` とゲーム内 `make movie-play` は成功。起動5秒と操作30秒のMP4を生成し、2秒間隔と末尾のフレームで探索・道具使用・戦闘・自然敗北・タイトル復帰を確認した。
- `make build-all GAMES=roguelike` と `make build-web GAMES=roguelike` が成功。各出力の全文ログに警告・エラーなし。CREDITSとOFL全文を同梱している。
- 通常のウィンドウ終了要求と `--quit-after 1/30/120` は終了コード0、終了時リークなし。F11の全画面往復も描画付きで確認した。
- 最終CI・Web操作と公開した証拠URLはPR本文を正とする。Steam連携・ストア公開・PRマージは行わない。

## 判断点と共有skillへの提案

- 美術はSVGの線画と図形による独自制作。既存作品の素材を使わない。物理ゲームパッドの実機操作と音楽の聴感評価は、自動イベント・PCM検査だけでは保証できないため検証範囲を分けて報告する。
- godot-development の再利用候補: 自動生成マップの多数シード検査、実入力による探索録画、全キャラのアニメーション時刻を固定した撮影。
- game-asset-search の再利用候補: 統一パレットの独立SVGと場面別の合成音源、生成物クレジットをまとめて検査する手順。

## 実入力・描画によって見つけた問題

- 左スティックのX/Y軸イベントを `_input` で即座に一手へ変換すると、最初の軸だけで移動して待機時間に入り、斜めに動けなかった。軸イベントは `_process` の合成ベクトルで扱い、二軸の実イベントで回帰検証した。
- モーダルを同じフレームで二度閉じる経路では、`queue_free` 直後もノードが有効なため二重に `remove_child` していた。親から外したら参照をnullに戻し、フォーカスもツリー内のボタンだけへ戻す。
- キャラのz_indexが通常Controlより高いため、道具画面の前へ主人公が出ていた。モーダルと拡大地図の描画順を明示し、実際のPNGで重なりが解消したことを確認した。
- 長いメッセージは折り返しで指定した矩形を越える。ログを固定高のScrollContainerに入れ、最新行へ追従させた。
- 結果の数値Tweenをメイン画面に結びつけると、集計中にタイトルへ戻った際、破棄したLabelへ書き込んでいた。`summary.create_tween()`で表示ノードの寿命へ結びつけ、早い画面離脱を入力テストに残した。
- 射手の視線にも斜め移動と同じ壁角判定を適用した。壁の角を通り抜ける射撃をロジック検証で検出し、回帰検証を追加した。
- macOSで `process_frame` だけを待った撮影では、異なる階のPNGが同一ハッシュになった。描画完了の同期と全画像のハッシュ照合、各階HUDの目視を組み合わせて撮影結果を検査する。
- Node2D配下の演出Labelは画面のThemeを継承せず、LinuxのCI画像だけレベルアップの日本語が四角になった。同梱フォントをLabelへ明示し、OSの代替フォントに依存しない表示にした。

## 通常プレイでの到達確認

公開コマンドだけを使う検証で、seed 1118は158手・道具8回で5階から脱出し、seed 1110は176手・道具9回で番人を撃破した。体力・レベル・敵HP・所持品を勝利用に変更していない。経路計算には生成済み地形を参照するため、人間の初見難易度そのものを計測した検証ではない。

ローカルの `make test GAMES=roguelike` は、lint・起動・40シード×5階・アイテムと敵行動・勝敗・保存値解釈・実入力統合まで成功した。`make roguelike-run RUN_FLAGS='--script res://scripts/dev/shutdown.gd'` で通常起動targetの描画、F11の全画面往復、BGM/SE再生中の終了要求を確認し、終了コード0、ログに警告・エラーなしだった。

## 素材と検証の使い分け

キャラ7体、道具9種類、階段と金貨、タイル、背景3層、ロゴと装飾を独立したSVGで制作した。通常の剣・盾と強化品も輪郭を変えた。BGM8曲とSE7音は倍音・弦・鐘・ノイズ・打楽器の独自合成で、生成器を同梱する。非無音・非クリッピング・形式とクレジットを検査し、音声付き録画で確認できるようにした。音楽の聴感品質を自動検査だけで保証したとは扱わない。

webtunnelのpreflightはサンドボックスでTailscaleコマンドが停止する場合があり、通常の権限ではREADYになった。GitHub APIの一時的なタイムアウトでは、dispatch済みrunの有無とHTTP応答を確認し、重複起動せず復旧後に再実行した。システム設定や認証情報の追加・変更は行っていない。

共有CIはknowledgeの変更も共有物と扱い全ゲームを実行する。このゲームの文書だけなら対応するslugへ絞る改善を共有物への提案として残す。今回、ルートMakefile・workflow・他ゲームは変更していない。
