# 灯守りの深層: 実装と検証の知見

## 制作方針

5階の部屋・通路を潜るターン制探索。濃紺・青緑・琥珀を使う活字端末として、地形、主人公、敵6種類、道具、背景、演出を M PLUS 1 Code のグリフだけで描く。ゲームの状態は RunState、生成は Dungeon、表示は main / board / actor_view に分ける。変更はゲームのディレクトリと本文書に閉じる。

## 実装中に確認したこと

- 生成と敵の行動で乱数生成器を共有せず、同じシード・階で同じ地形を再現する。40シード×5階の連結性・階段への到達を検証する。
- 視界・探索済み地形・ミニマップは同じ Dungeon のデータを参照する。画面は主人公を追尾する範囲だけ描画する。
- SVGのキャラを独立ファイルにし、AnimationPlayer の待機・移動・攻撃・被弾・登場・消滅を組み合わせる。画像と音声は固定内容で再生成できるスクリプトと CREDITS を同梱する。
- 音声終了は既存 deckrogue の停止・解放待ちを参照した。通常終了では待機後に quit、強制終了通知では音声スレッドの排出を待つ。
- Godot 4.7 のローカル起動はログの絶対パス指定だけでは user:// の ObjectDB Snapshots ディレクトリ作成を拒否される場合があった。検証コマンドに通常の権限を与えて起動できた。self-contained mode はエディタ設定を作業ディレクトリへ置く用途であり、この起動時ディレクトリの問題は残った。

## 検証結果

- `make test GAMES=roguelike` は lint・起動・全ロジック・キーボード/パッドボタン/二軸/マウスの実入力まで成功。
- `make screenshot GAMES=roguelike` は29枚を生成。タイトル、探索、道具、未識別と識別後、全5階、番人、勝敗、6種の演出、7キャラ×6動作×3時点を目視した。各階のHUDと画像ハッシュも照合した。
- `make movie GAMES=roguelike` とゲーム内 `make movie-play` は成功。起動5秒と操作30秒のMP4を生成し、2秒間隔と末尾のフレームで探索・道具使用・戦闘・自然敗北・タイトル復帰を確認した。
- `make build-all GAMES=roguelike` と `make build-web GAMES=roguelike` が成功。各出力の全文ログに警告・エラーなし。CREDITSとOFL全文を同梱している。
- 通常のウィンドウ終了要求と `--quit-after 1/30/120` は終了コード0、終了時リークなし。F11の全画面往復も描画付きで確認した。
- 最終CI・Web操作と公開した証拠URLはPR本文を正とする。Steam連携・ストア公開・PRマージは行わない。

## 判断点と共有skillへの提案

- 美術はSVGの線画と図形による独自制作。既存作品の素材を使わない。物理ゲームパッドの実機操作と音楽の聴感評価は、自動イベント・PCM検査だけでは保証できないため検証範囲を分けて報告する。
- godot-development の再利用候補: 自動生成マップの多数シード検査、実入力による探索録画、全キャラのアニメーション時刻を固定した撮影。
- game-asset-search の再利用候補: 統一パレットの独立SVGと場面別の合成音源、生成物クレジットをまとめて検査する手順。

## 実入力・描画によって見つけた問題

- 左スティックのX/Y軸イベントを `_input` で即座に一手へ変換すると、最初の軸だけで移動して待機時間に入り、斜めに動けなかった。軸イベントは `_process` の合成ベクトルで扱い、二軸の実イベントで回帰検証した。
- モーダルを同じフレームで二度閉じる経路では、`queue_free` 直後もノードが有効なため二重に `remove_child` していた。親から外したら参照をnullに戻し、フォーカスもツリー内のボタンだけへ戻す。
- キャラのz_indexが通常Controlより高いため、道具画面の前へ主人公が出ていた。モーダルと拡大地図の描画順を明示し、実際のPNGで重なりが解消したことを確認した。
- 長いメッセージは折り返しで指定した矩形を越える。ログを固定高のScrollContainerに入れ、最新行へ追従させた。
- 結果の数値Tweenをメイン画面に結びつけると、集計中にタイトルへ戻った際、破棄したLabelへ書き込んでいた。`summary.create_tween()`で表示ノードの寿命へ結びつけ、早い画面離脱を入力テストに残した。
- 射手の視線にも斜め移動と同じ壁角判定を適用した。壁の角を通り抜ける射撃をロジック検証で検出し、回帰検証を追加した。
- macOSで `process_frame` だけを待った撮影では、異なる階のPNGが同一ハッシュになった。描画完了の同期と全画像のハッシュ照合、各階HUDの目視を組み合わせて撮影結果を検査する。
- Node2D配下の演出Labelは画面のThemeを継承せず、LinuxのCI画像だけレベルアップの日本語が四角になった。同梱フォントをLabelへ明示し、OSの代替フォントに依存しない表示にした。

## 通常プレイでの到達確認

公開コマンドだけを使う検証で、seed 1118は158手・道具8回で5階から脱出し、seed 1110は176手・道具9回で番人を撃破した。体力・レベル・敵HP・所持品を勝利用に変更していない。経路計算には生成済み地形を参照するため、人間の初見難易度そのものを計測した検証ではない。

ローカルの `make test GAMES=roguelike` は、lint・起動・40シード×5階・アイテムと敵行動・勝敗・保存値解釈・実入力統合まで成功した。`make roguelike-run RUN_FLAGS='--script res://scripts/dev/shutdown.gd'` で通常起動targetの描画、F11の全画面往復、BGM/SE再生中の終了要求を確認し、終了コード0、ログに警告・エラーなしだった。

## 前ラウンドの素材と検証の使い分け

前ラウンドでは、キャラ7体、道具9種類、階段と金貨、タイル、背景3層、ロゴと装飾を独立したSVGで制作した。通常の剣・盾と強化品も輪郭を変えた。BGM8曲とSE7音は倍音・弦・鐘・ノイズ・打楽器の独自合成で、生成器を同梱した。非無音・非クリッピング・形式とクレジットを検査し、音声付き録画で確認できるようにした。音楽の聴感品質を自動検査だけで保証したとは扱わない。

webtunnelのpreflightはサンドボックスでTailscaleコマンドが停止する場合があり、通常の権限ではREADYになった。GitHub APIの一時的なタイムアウトでは、dispatch済みrunの有無とHTTP応答を確認し、重複起動せず復旧後に再実行した。システム設定や認証情報の追加・変更は行っていない。

共有CIはknowledgeの変更も共有物と扱い全ゲームを実行する。このゲームの文書だけなら対応するslugへ絞る改善を共有物への提案として残す。今回、ルートMakefile・workflow・他ゲームは変更していない。

## 手直しラウンド（見た目の特色化）

### 分かりにくさの原因と効いた表現

前ラウンドは、上部HUD、中央の盤面、右側の小さいログ、下部の共通操作ガイドという他ゲームでも使った構成だった。ログは結果通知に見え、次の目的や選択後の変化を説明する場所がなかった。手続きSVGは個々の輪郭を増やせた一方、均一な線画と多層背景が他ゲームと似た印象になり、ローグライク固有の文字地図より画像が目立っていた。

画面下224pxを `MESSAGE LOG / TURN HISTORY` に割り当て、ログを画面の約3分の1を占める主役にした。右側の `NEXT ACTION` は、未探索、隣接する敵、近い道具、満杯の持ち物、空腹、階段、地図表示中を同じ位置で切り替え、操作と起きる結果をその場に書く。持ち物はフォーカス中の道具を彩色し、使用・装備後の値と実行できない理由を右側に出す。共通操作ガイド行は除去し、初回3ページのチュートリアルと `?` で開閉する手引きへ移した。階層遷移では五層を縦に結んだ地下図を挟み、現在地、記録済みの層、最終目的を色分けした。これにより、盤面を見る、ログを読む、右欄で次の一手を決める、という視線の順序が画面だけで成立した。

### フォントのグリフだけで作る手順と評価

`game-asset-search` の Google Fonts 検索で M PLUS 1 Code の配布元、上流、SIL Open Font License 1.1 を確認し、可変フォント `MPLUS1Code[wght].ttf` と OFL 全文を同梱した。`CREDITS.md` には取得元URL、上流URL、著作権者、ライセンス、無改変であることを記録した。画像やSVGは一切追加せず、既存の背景・キャラクター・道具・タイル・ロゴ・装飾SVGと生成器を削除した。画面は `Label`、`RichTextLabel`、`draw_string()` だけで構成し、`FontVariation` の `wght` 軸、色、文字サイズ、残像、拡縮、回転、透明度で差を作った。

当たりだったのは、1つのフォントを決めた時点で地形、UI、登場人物の線質が揃い、画像ごとの生成・切り出し・import設定・出典確認が不要になったことだった。フォント1件のライセンス確認だけで表示素材を監査でき、画像素材が残っていないことも拡張子走査で自動検証できる。小さな盤面でも `@ g } s O v W` の形と色が即座に区別でき、同じ文字へ待機・移動・攻撃・被弾・消滅・登場の6動作を適用しても輪郭が崩れにくかった。

外れだったのは、見栄えのよい記号を文字列へ直接選ぶと、M PLUS 1 Code 単独では `Ω`、`▣`、`▼` が Godot 上で欠字になったことだった。OSの代替フォントを許すとローカルでは気づけても、WebやLinuxで見た目が変わる。番人を `W`、古鉄の盾を `H`、地下図の矢印を `v` に置き換え、import設定でシステムフォントへのフォールバックを無効にした。selfcheck は実際に使うASCII、罫線、和文を `Font.has_char()` で検査する。文字だけでも、画面構成、字間、矩形、アニメーション、色の調整にはSVGを置く場合とは別の手間がかかり、スクリーンショットの目視は省けなかった。

前ラウンドの手続きSVGは、輪郭を自由に設計できる代わりに、キャラ、道具、背景、UIごとにファイルとimportメタデータが増え、全体が同じ図形生成の質感になった。今回のグリフ方式は形状の自由度を狭める代わりに、伝統的ローグライクの約束事をそのまま特色へ変え、ファイル数、ライセンス確認、OS間差異を減らした。比較では、旧画面が「画像を載せた共通レイアウト」、新画面が「地下端末の記録を読むゲーム」と一目で区別できた。

### 音と検証

既存のタイトル、各階、番人、結果のBGMと操作音を維持し、固定シードで12秒の環境音を生成した。低い機械の唸り、周期の異なる水滴、短い活字クリックを合成し、探索中だけBGMの下でループする。第三者の録音は使わず、生成方法と音の要点を `CREDITS.md` に記録した。環境音は単体ファイルの形式、長さ、非無音を検査できるが、BGMとの音量バランスは録画や実再生で確認する必要がある。

スクリーンショットはタイトル、盤面、探索地図、地下図、チュートリアル3ページ、ヘルプ、持ち物、道具詳細、ハイライト、各階、番人、勝敗、文字演出6種、7キャラ×6動作×3時点の34枚へ増やした。文字だけの暗い画面では、limited rangeの真っ黒が輝度16であるのに対しタイトル画面の平均輝度が約16.96だったため、動画の黒画面検出を「32以上」から「16.5以上」へ変更した。最終フレームの実画像も併せて目視し、閾値だけで成功と扱わない。

### Godotでのハマりどころとskill化候補

- `Node2D.draw_string()` の座標はベースラインなので、セル左上からフォントサイズ分を加えて配置する。キャラクターの `Label` と地形の直接描画で原点が異なるため、同じセル中央関数を共有する。
- 盤面の子にした拡大地図とミニマップは親の位置が加算される。画面全体の座標をそのまま書くとHUDへ重なるため、盤面ローカル座標へ換算し、PNGで装備値・ボタンとの重なりを確認する。
- 半透明パネルは背後のASCIIも読めるため、文字同士が重なる。モーダルと拡大地図は不透明、背景を見せたい通常画面だけ透過という役割分担にする。
- `game-asset-search` への追記候補は、フォント単独アートで「配布元とOFLの取得」「OSフォールバック無効化」「使用文字の `Font.has_char()` 検査」「画像拡張子が存在しない検査」を一続きにした手順。
- `godot-development` への追記候補は、暗色ゲームの動画を平均輝度の固定値だけで判定せず、limited rangeの黒との差と最終フレーム目視を組み合わせる手順、および `draw_string()` と `Label` の座標を揃える文字グリッド実装例。
