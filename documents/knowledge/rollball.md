# rollball の実装と検証

## 設計判断

独自の「ころころ工房」。玩具の部屋で小さなものから集める、キーボード・ゲームパッド向けの短い3Dゲームとした。部屋・家具・小物はプリミティブで制作し、配置は `room.gd` の決定的なデータで再現する。外部の作品名・キャラクター・音源は使っていない。

- 体積を正として巻き込みと脱落を対称に計算する。付着表示は玉の子に移し、回収した StaticBody3D は解放する。成長後の物理形状は球ひとつであり、小物ごとの衝突計算を持ち越さない。
- 進行は RunState autoload に集約する。UI は表示と操作要求を担当し、結果確定後の時間・直径・個数は固定する。
- 反発は連続接触ごとに発生させず、クールダウンで制限する。剥がれた物体は短時間回収を止め、即座に吸い直すループを防ぐ。
- カメラは玉の大きさに応じて距離を変え、壁の内側に制限する。棚の背後では視線が家具を貫通しない位置まで寄せる。
- マテリアルを色ごとに共有し、小物の影を省く。家具と玉は影を落とす。

## 検証で確認したこと

2026-09-06、Godot 4.7 stable、macOS / Apple M4 Max、GL Compatibility、1280×720。

| 検証 | 結果 |
| --- | --- |
| `make test GAMES=rollball` | exit 0。lint・boot・selfcheck・実シーン integration |
| `make screenshot GAMES=rollball` | exit 0。タイトル・プレイ・成長・成功・時間切れを撮影し目視 |
| `make movie GAMES=rollball` | exit 0。起動〜タイトルの5秒をフレーム抽出して目視 |
| デスクトップ3種と Web エクスポート | 両 make コマンド exit 0。ログ全文に WARNING / ERROR なし |
| 実時間の描画性能 | 最終 make performance は189物体で平均452.86 FPS / p95 3.489ms、成長中は平均480.86 FPS / p95 3.401ms（Dummy音声）。通常音声ドライバでも初回計測は平均145 FPS以上 |
| 最初の PR CI | run 34013477121 全件成功。rollball の PNG 5枚と起動動画を取得して目視 |

性能は `Time.get_ticks_usec()` の実時間で process_frame の間隔を測った値。ウォームアップ5秒、189物体のまま5秒、通常移動による成長10秒、VSyncを無効化して測定した。Movie Maker の固定フレーム数や headless の速度を FPS として扱っていない。CI の llvmpipe に60fpsは要求せず、CIでは描画内容を検証する。

実シーンの統合検証では、アクション入力に加え、左右矢印のキーイベント、左スティック、結果メニューの十字キー→A決定を送る。通常の移動・接触で70個を巻き込み直径3.204mに到達し、無操作で180秒経過すると失敗することを確認する。物理ゲームパッド本体の接続検証ではない。

## Godot のハマりどころ

- `--headless` と撮影用の `--audio-driver Dummy` で WAV を再生すると、終了時に AudioStreamPlaybackWAV / AudioStreamWAV が残る場合があった。音声を出さない検証では再生を開始せず、Movie Maker は録音が必要なので例外にする。通常の音声ドライバと Movie Maker の終了では警告が出ないことを確認した。判定は `AudioServer.get_driver_name()` と `OS.has_feature("movie")`。
- `--path` を指定すると録画ファイルの相対パスはプロジェクトを基準に解決される。リポジトリ基準のパスを重ねると出力先が存在せず、録画エラーが出てもエンジンが exit 0 になる場合がある。成果物の存在とログ全文の検査が必要。
- sandbox 内では Godot の標準ユーザーデータ領域への書き込みが拒否され、起動が abort することがあった。エンジンのエラーとゲームの不具合を分け、許可されたローカル検証として実行した。
- 日本語フォントを同梱して Theme に設定し、Linux の OS fallback へ依存させない。撮影前には複数の描画完了を待つ。半透明フッター越しに小物が見えるため文字欠けを疑ったが、play/growth の文字色画素比較と別担当の目視では文字の消失はなかった。
- InputMap の特殊キー番号を推測すると左右の矢印を取り違える。実 InputEventKey を送る回帰試験で確認する。
- ゲームパッドの独自 confirm を常に start_run へ結ぶと、結果メニューで「タイトルへ戻る」を選んでも再開する。GUIで未処理のconfirmはフォーカス中のボタンへ渡し、入力を消費する。ui_acceptにもゲームパッドを登録する。
- 環境光と指向性ライトを同時に強くすると明るいマテリアルが白飛びした。実スクリーンショットを見て、床・ラグ・小物の色が識別できる明るさへ調整した。

## 第 2 ラウンド (品質向上)

### 制作方針

木製玩具のアトリエという方向を維持し、主人公と小物を種類ごとに独立したメッシュシーンへ分ける。見分ける手掛かりを色だけに頼らず、顔・車輪・葉・装備のシルエットで用意する。物体配置、体積計算、制限時間、入力方式は維持する。

部位の AnimationPlayer、巻き込みと反発のパーティクル、統一した Theme、場面別の音楽を組み合わせる。結果や直径を直接書き換えずに実入力で遊ぶ録画を追加し、各モデルのアニメーション連続フレーム、通常終了とフレーム指定終了、Web 上の操作を検証する。

### 独立モデルと部位アニメーション

- 主人公、アヒル、ロボット、汽車、植木を `assets/models/` の別シーンにした。主人公の耳と縞、アヒルのくちばしと翼、ロボットのアンテナと腕、汽車の煙突と車輪、植木の鉢と葉で形を区別する。プリミティブの組み合わせでも、シルエットと可動部を種類ごとに変えると、色違いだけの物体から脱却できる。
- 各シーンの AnimationPlayer に待機・移動・巻き込み・衝突・お祝い・時間切れの6状態を持たせた。回転する玉の下にモデルを置き、さらにモデルの Pivot 以下で部位を動かす。ゲームの移動と見た目の動きを分けると、物理形状を変えずに表情を増やせる。
- 単発の巻き込み・衝突アニメーションを物理フレームごとの待機・移動指定で上書きすると途中で切れる。開始イベントで一度だけ再生し、単発状態の間は通常状態への切替を待つ。トラックは開始時に各部位の基準姿勢も戻す。
- 背景には窓の奥の山・雲、カーテン、家具、手前の小物を置いた。タイトルの緩やかなカメラ移動で3Dの視差を出す。GL Compatibility の環境光と影を維持し、レンダラは変更していない。

### 演出と UI の調整

- 巻き込み・成長・反発・勝利を CPUParticles3D と Tween の輪で表現した。反発時は物理移動を0.055秒止め、画面を揺らし、UIを短くフラッシュする。勝敗確定とリセット時にカメラ補正もゼロへ戻す。揺れの更新をプレイ中だけにすると、結果画面に補正が残るためである。
- Theme リソースで丸ゴシック、クリーム・青緑・珊瑚色、ボタン、パネルを統一した。ロゴ・キーアート・時計・収集数・達成章は別 SVG とした。キーアートの主人公も実モデルの配色と耳へ合わせた。
- 直径と個数を補間し、タイトル・プレイ・結果をフェードとスライドで切り替える。巻き込み数値を毎回別ラベルで出すと密集地で重なるため、短い間隔の加算はひとつの表示に合算する。反発時には加算表示を消し、何が起きたかを読めるようにした。
- モデル一覧の撮影では実ゲームのライトが残ると、一覧用ライトと重なって白飛びする。専用の照明へ切り替え、影距離と背景面の影を調整して、黒い三角形や白飛びが消えたことを連続フレームで確認した。

### 場面別の音と終了処理

- Python 標準ライブラリで木琴・撥弦・鐘・低音・ノイズ打楽器を合成し、タイトル12秒、プレイ15秒、残り30秒用12.8秒、成功8.73秒、時間切れ11.71秒を別 WAV とした。巻き込み・衝突・成長・成功・失敗の SE も別ファイルとし、生成方法と由来を CREDITS に記録した。
- 再生成2回の SHA-256 一致、全曲の非無音・非クリッピング・端点ゼロを検査した。最大ピークは0.780以下。テンポ・編成・波形の差と録画の音声トラックは確認したが、聴感による評価はこの実行環境では未検証である。
- Godot 4.7 の `OS.get_cmdline_args()` にはエンジンが消費した `--quit-after` が残らない。終了時に stop するだけでは Movie Maker の音声リソース解放が間に合わず、Ogg への変換や WAV の STREAM 再生指定でもリークが再現した。
- `make movie` 系は `--quit-after N -- --audio-stop-at-frame N` を渡し、ユーザー引数から終了時刻を受け取って12フレーム前に音声を停止・参照解除する。短い指定では再生自体を開始しない。通常のウィンドウ終了は stop 後に8フレーム待つ。裸の `--quit-after` を音声付きで直接呼ぶ場合にも、README の追加引数が必要である。第1ラウンドの終了確認だけではこの条件を捕捉できなかった。
- WAV はインポート後に QOA 圧縮されるため、`data.size()/2` をループ終端にすると12秒曲が約2.43秒で途切れた。`get_length() * mix_rate` からサンプル数を求める。単位の根拠: https://docs.godotengine.org/en/stable/classes/class_audiostreamwav.html#class-audiostreamwav-property-loop-end

### Web と証拠の扱い

- webtunnel は `--software-webgl --ref polish/rollball` で起動した。汎用例の8080では接続できず、実際の caller workflow が指定する8000で開けた。`#status` の削除を確認してから撮影・Enter開始・キー移動を行い、5個の巻き込みと1.21mへの成長を確認した。SwiftShader はこのモデル数だと実時間より進行が遅いため、ローカルの描画性能とは区別する。
- 画面と連続フレームは `puts upload` で既存 R2 へ保存して PR の「検証」に埋め込む。GUI の既定保存先を探す処理が SwiftData で待ち続けたため、既存認証情報を子プロセスの `PUTS_*` 環境変数へ対応させて CLI を実行した。資格情報をファイルやログには出していない。
- エクスポートは Git の ignore を参照しない。今回の大量の検証 PNG が配布物に入ったため、各プリセットの `exclude_filter` に `tmp/*,build/*` を設定し、ログの保存対象から消えたことを確認した。
- Web の確認では、その後も通常の A・D・W 入力で37個・直径3.28mのクリアへ到達した。タイトル・移動後・結果を撮影して目視し、console / errors に異常がないこと、全キー解放と webtunnel の停止完了を確認した。
- `make run` はアセットインポート用の target を経由しないため、検証用 `tmp/` が存在することを前提にできない。起動確認スクリプトが保存先を作るようにし、フォルダのない独立コピーから実行して4画像の作成・全画面と復帰・通常終了を確認する。
- 最終 CI のログ・画像・動画と Web 結果画面の証拠は PR #31 にまとめる: https://github.com/bannzai/godotpractice/pull/31

### 本番に向けた判断と道具の提案

仕様の判断待ちはなし。外部素材のスタイル合わせより、独立した手続きモデルと部位アニメーションの再現性を優先した。骨格アニメーション、専用3D制作ツール、GPU パーティクルへの移行は行っていない。モデル数が増える本番では、同一メッシュの描画共有と影の予算を別途設計する余地がある。

今回の「モデルごとの6状態×3時点の撮影」「実入力での25秒プレイ録画」「音声を再生した通常終了とフレーム指定終了」「検証生成物のエクスポート除外」を godot-development skill の検証例へ追加することを提案する。共有 skill やルールは変更していない。

## 手直しラウンド (見た目の特色化)

### 分かりにくさの原因と、効いた表現

第2ラウンドまでは、木製玩具のモデルや部位アニメーションは増えていた一方、タイトル・プレイ・結果を同じ整列したパネルで囲い、画面下に汎用の操作一覧を置いていた。部屋も1種類で、床に均等に並んだ玩具のどれから集められるかを色や形から判断する必要があった。このため、画面単体の品質を上げても、初見で次の行動を選ぶ手掛かりと、ほかのゲームから見分ける固有の構図が不足していた。

今回、進行を「タイトル → おもちゃ箱の部屋選択 → 初回だけの3段階チュートリアル → プレイ → 結果」にした。部屋選択では、選択中の紙カード、部屋名、床・家具・配置の短いプレビュー、遷移先を名前で示す開始ボタンを同時に見せる。チュートリアルでは既存のアヒル、ロボット、玉を3D空間へ置き、足踏み、体をひねる動き、手を上げる動きで「転がす・見回す・金の輪へ向かう」を順に示す。Enter / A で進み、Esc / B で飛ばせる。2回目以降は同じ実行中に再表示しない。

プレイ中は、現在巻き込める最寄りの玩具だけに金色の輪、上下する矢印、短い Label3D を付ける。大きすぎる物体へ当たった時は「まだ大きすぎる」と紙札へ理由を表示する。直径・目標・個数・時間は四つの独立した画用紙片に分け、旧来の画面下の共通操作ガイド行は廃止した。常時見せる情報を計測値と次の目標へ絞り、入力説明は必要になる場面内へ移したことが、初見の行動理解に最も効いた。

### 粘土表面と画用紙 UI の作り方

3D 表面は外部テクスチャ画像を使わず、`clay_surface.gd` で既存のプリミティブへ後付けした。各メッシュの頂点へ、固定 seed の3次元 FastNoiseLite による明暗と、座標から作る細い正弦波を合成した頂点カラーを設定する。さらに、固定 seed の FastNoiseLite を `NoiseTexture2D` の法線マップへ変換し、粗さの高い共有 `StandardMaterial3D` から参照する。元メッシュと基準色をキーに変換済みメッシュをキャッシュし、部屋、家具、小物、玉、チュートリアルのモデルへ同じ処理を適用した。形や当たり判定を作り直さず、既存のアニメーションと演出も維持できた。

当たりだったのは、強い凹凸よりも、低い normal scale と数％の頂点色むらを併用する設定だった。パステル色と丸い輪郭を壊さず、接写では指で均したような不均一さが出る。共有マテリアルと変換メッシュのキャッシュにより、100個を超える配置でも物体ごとにノイズ資源を生成せずに済む。一方、プリミティブは頂点密度が均一ではないため、頂点色だけでは大きな平面の模様が乏しい。法線ノイズを強くすると表面が石や砂に見え、正弦波を強くすると規則的な縞になる。最終値はタイトル、2部屋、モデル一覧の実 PNG を並べ、色の識別と柔らかい陰影が残る範囲へ下げた。

UI は `PanelContainer` ごとに色、角丸、影、わずかな回転を変え、1枚の大きな HUD ではなく切り抜いた紙片の重なりとして組んだ。CanvasItem shader の画面座標ノイズと細い正弦波で繊維状の輝度差を足した。画像アセットを増やさず解像度に依存しない点、文字量や部屋名が変わっても StyleBox の寸法を直せる点は扱いやすかった。外れだったのは、すべての札を同じ角度・同じ影で揃えることと、ノイズを文字まで強く変調することだった。前者は従来のテンプレート UI に戻って見え、後者は可読性を落とすため、傾きと色は札ごとに変え、繊維は弱い明度差だけにした。

前のラウンドの手続き SVG は、ロゴ、時計、収集数などの輪郭を意図どおり固定でき、Godot 外でも確認しやすい反面、別ファイルの図案と UI のレイアウト調整が分かれ、ほかのゲームにも似た平面的なカード構成になりやすかった。今回の手続き法線・頂点カラーは3Dモデル自体の光の受け方を変え、カメラ移動やアニメーション中も質感が残る。画用紙 UI も Godot の Control と shader を直接使うため、フォーカス、プレビュー、チュートリアルの進行と一体で調整できた。反面、SVG より Godot の実描画への依存が強く、headless のロード成功だけでは良否を判断できない。代表画面と連続フレームの撮影・目視に掛かる手間は増えた。

### 2つの部屋、音、検証

従来の「おもちゃのアトリエ」に加えて、「ひだまりプレイルーム」を追加した。前者は木の床、本棚、作業机と渦巻く配置、後者は桃色の床、大きな窓、丸いラグ、積み木の島と輪状の配置を持つ。部屋ごとに家具、照明、開始位置、配置の中心と広がりを変えつつ、同じ決定的な配置関数から100個以上を生成する。単なる色替えにせず、選択画面のプレビュー文と実際の進み方が一致するようにした。

既存の場面別 BGM と効果音を残し、アトリエには紙擦れと粘土を置く音、プレイルームには遠い玩具のベルを中心とした別の環境音を足した。Python 標準ライブラリの数式合成なので再生成でき、外部音源の取得やライセンス混在はない。波形、長さ、非無音、非クリッピング、決定的な再生成は検査できるが、世界観に合う音色かどうかは最終的に聴感確認が要る。

撮影スクリプトには、タイトル、2部屋の選択状態、チュートリアル3段階、両部屋のハイライト、巻き込み・成長・反発・勝利、結果、既存5モデルの6アニメーションを追加した。複数フレームを待っても、選択変更直後のカスタム描画が古い状態のまま撮られる場合があった。Theme の上書きだけでなく、ステージ画面と子 Control へ `queue_redraw()` を明示して解消した。プログラムから画面状態を連続で切り替えて撮る検証では、表示プロパティの更新と Canvas の再描画完了を別に扱う必要がある。

タイトル・部屋選択・プレイの変更前後と、近いジャンルの複数ゲームとの比較画像も作った。粘土の凹凸だけに頼らず、おもちゃ箱を正面から見た選択画面、3Dキャラクターが身振りする説明、画面内の金色の目標輪、非対称な紙札という大きな構図の差を組み合わせると、縮小した一覧でも rollball を識別できた。
