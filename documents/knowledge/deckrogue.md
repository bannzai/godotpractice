# deckrogue 開発知見

## 戦闘と探索の設計

- 独自の世界観「燈火の巡礼」。ゲーム状態は autoload の Run に集約し、画面は状態を参照して描画する。カードの表示と効果解決は同じカタログを参照する。
- 階層内の選択肢だけをシャッフルすることで、ランダム性を持たせながら休憩・成長・最上階への到達可能性を保った。
- 使用中のカードは、効果を解決してから捨て札または廃棄へ移す。先に捨て札へ置くと、山札が空のドロー効果で使用中のカードを引き直す可能性がある。
- パワーは廃棄へ移して再使用を防ぎ、強化値は戦闘中の状態として持つ。次の戦闘開始時に戦闘状態を初期化し、永続するデッキと遺物から開始効果を適用する。
- 弱体は攻撃側、脆弱は被攻撃側の行動境界で減衰させる。敵が新しく付けた脆弱を付与直後に減らさず、意図には状態異常を含む実ダメージを表示する。

## 素材の準備

- オリジナルのSVGと、Python標準ライブラリで合成したWAVを使用した。`scripts/dev/generate_assets.py` は固定seedで画像・音声を同じ内容に再生成する。19点のSHA256一致、SVGのXML構文、PCMの読込み、クレジット記録漏れを確認した。
- 日本語は同梱したZen Old Minchoをテーマに指定した。OFL全文とCREDITSを各エクスポートのinclude_filterへ含め、OSのフォントに依存しない構成にした。
- SVGは元サイズ以上に大きく見せるとインポート時のラスタライズ解像度の影響を受ける。キャラクターは表示サイズ以上の原寸で作ると扱いやすい。

## Godotの検証で確認したこと

- `--headless --quit` で音楽を再生すると、即終了によりAudioStreamPlaybackWAVが残る場合があった。headlessでは音声出力自体が不要なので再生しない。
- 描画付きの撮影はミュート設定で再生自体を止め、起動録画は`movie.gd`で終了10フレーム前に音源を停止する。`_exit_tree`で停止するだけでは遅く、終了前に音声サーバーが解放を処理する時間が必要だった。警告行を除外する変更は行っていない。
- 音声再生中の終了時リークはGodot側にも既報がある。今回の対処はローカルとCIのログで確認した。
  https://github.com/godotengine/godot/issues/76745
- InputMapはイベントの存在確認だけでなく、`KEY_LEFT`等の列挙値から物理キーイベントを作り、`event_is_action`で対応と競合を検査した。整数コードの左右キー取り違えを検出できる。
- 手札を枚数に応じて縮めると、追加ドロー時に日本語の名前や効果がはみ出す。カード幅を保ち、`ScrollContainer.follow_focus`でキーボード・ゲームパッドでも横スクロールさせた。デッキ一覧もフォーカス追従を有効にした。
- カードの通常状態だけ紙色にすると、ホバー時に共通ボタンの暗い背景へ戻り、暗い文字が読めなくなる。カードのホバー・押下背景も紙色で定義した。
- ダメージ数字には輪郭と描画順を与え、敵の被弾色の上でも読めるようにした。手札の捨て演出はスクロール領域外の表示用カードを動かすことで、途中で切り取られないようにした。

- `make test GAMES=deckrogue`成功。カード定義・全効果・山全体の保存則・廃棄・致死攻撃後の効果解決・状態異常・報酬・遺物・休憩・入力イベントを検査した。
- 固定seedの通常操作だけで8階層からボス勝利、無抵抗で敗北、結果からタイトル・再開のループを検証した。複数seedで状態・選択・報酬・最終結果の再現性も確認した。
- `make screenshot GAMES=deckrogue`成功。タイトル、地図、戦闘、ドロー・プレイ・被弾・捨て、デッキ、報酬、イベント、休憩、ボス、勝敗、9枚の手札・ホバー・スクロール、弱体と脆弱の同時表示を撮影した。

## 第 2 ラウンド (品質向上)

### 制作方針

- 深い紺と青緑、羊皮紙色、燈火の金、朱色の布で配色を統一し、切り絵と細密な線画を組み合わせる。キャラクターごとの輪郭・装備・表情を独立した素材で持たせる。
- 戦闘ルールとカードカタログは維持し、表示・演出と検証を強化する。キャラクターの待機・移動・攻撃・被弾・死亡は独立したスプライトシートで表現する。
- アニメーションの開始・途中・終了、演出、操作付き録画、Web 実操作、終了時の音声解放までを証拠として残す。検証結果と制作中の知見は実施後に追記する。

### 素材とアニメーションで得た知見

- 7種のキャラクターを各1枚の独立したシートにし、待機・移動・攻撃・被弾・死亡を各6コマで制作した。腕・翼・装備・冠などの部位を動かすと、全体の移動だけより動作の意味が伝わる。カタログの「岩角の獣」に従来は霊炎の絵が割り当てられていたため、岩角の四足獣を別に制作した。
- 入れ子の `<svg x="..." y="...">` はlibrsvgでは正しく描画されたが、Godotでは位置が無視され、全30コマが左上へ重なった。`<g transform="translate(...)">` に変更して解消した。外部描画器だけで素材を合格にせず、Godotがインポートした各コマの非透明領域とポーズの違いをselfcheckで検査する。
- 攻撃・死亡では腕や武器がコマを越えやすい。全210コマを余白付きに描画し、アルファ値のある範囲が256×320内に収まることを確認した。SVG56点とWAV13点はそれぞれ固定seedによる再生成でSHA256が一致した。
- `AnimatedSprite2D` と `AtlasTexture` でキャラごとの素材と共通の再生制御を分離できる。撮影では再生を止めてフレームを固定し、開始・途中・終了を同じ条件で比較する。実際の動きは実入力の録画で別に確認する。
- 被弾のヒットストップはキャラの `speed_scale` だけを65ms止め、UIと音楽の時間は止めない。画面再描画が早すぎると被弾最終コマや数字のフェードが切れるため、被弾完了を待ち、同じ戦闘中の一時演出は手札再描画から独立して保持する。
- 背景の視差と霧も手札再描画から独立させる。状態が変わるたびに背景を作り直すと、視差や霧の進行が毎回先頭へ戻る。
- `ProgressBar` はパーセント表示を消す前にサイズを設定すると、既定の最小高さが残って文字を覆った。スタイルと表示設定を確定した後にサイズを設定し直して解消した。
- 手続きSVGは透過・配色・部位の統一・再生成に向いている。今回は切り絵と線画の方向を採用した。絵画的な質感や複雑な身体運動をさらに求める場合は、専任の作画工程との比較が必要になる。

### 音と終了処理

- BGMをタイトル・探索・戦闘・ボス・敗北・勝利の6曲へ分け、撥弦・倍音のある笛・持続音・低音・金管・ベル・打楽器を重ねた。SEはカード・攻撃・防御・回復・強化・死亡・遷移の7種。全素材は独自合成で、PCM形式・非無音・非クリッピング・両端ゼロを検査した。
- Godot 4.7 は `--quit` と `--quit-after` を消費し、`OS.get_cmdline_args()` に残さない。引数を読んで終了フレームを先取りする案では強制終了に対応できなかった。
- 通常終了は `Sound.shutdown()` で音源を停止し、出力遅延の2倍以上かつ120ms以上と数フレームを待つ。`--quit-after` では終了通知後にawaitで延命できないため、`_exit_tree()`で停止後に実時間を待つ。この経路だけ同期する理由をコードに記録した。
- 音源を実再生する専用SceneTreeで、通常shutdown・`--quit`・`--quit-after 1/30/120` を実行し、CoreAudioとDummyの各条件でexit 0、ログ全文にWARNING / ERRORなしを確認した。headlessの再生抑止だけで検証を代替していない。

### 検証と道具の改善案

- `make -C games/deckrogue movie-play` は30fps・30秒の実入力録画。通常の開始操作後に乱数種だけ固定し、カード2枚をクリックして使い、敵の攻撃で自然敗北し、結果画面からタイトルへ戻る。体力や敵HPを撮影のために変更しない。
- スクリーンショットは全キャラ5動作の開始・途中・終了15枚、6種の演出、視差の両端と既存の代表画面・大量手札・状態異常を撮る。撮影用PNGをGodotが再インポートしないよう、tmpを作る際に `.gdignore` も用意する。
- `godot-development` への再利用候補は、コマごとの透明領域検査、フレームを固定した連続撮影、実入力録画、音声の終了時解放検証。共有skillは変更せず、このゲームの生成・検証スクリプトを提案例として残す。
- 現在の共有CIはknowledgeの変更でも全ゲームを実行し、初回CIでは変更対象外のcrewrtsに音声リソースの終了時リークが出た。ゲーム別文書を変更対象のゲームへ対応付ける共有PR #23が改善経路。共有ファイルや他ゲームはこの作業から変更しない。
