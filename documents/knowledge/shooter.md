# shooter の実装知見

## 設計と受け入れ条件

- 「星環防衛線」として、タイトル・戦闘・クリア/ゲームオーバー・再出撃を構成した。進行状態と保存は autoload、出現と弾の計算は純粋なロジック、入力と衝突は main、描画は flight_view に分離した。
- 敵の時間・座標・種類・ドロップを120機分のデータとして定義。150秒後にボスへ切り替わる。固定刻みで実際の射撃と当たり判定を通した検証では165.87秒でクリアした（被弾による中断を除外するため検証時だけ無敵・3連射）。
- 自機の当たり判定は中央の光点を基準とする。高速弾には前フレームからの線分との距離を使い、フレーム間の通り抜けを防ぐ。
- パワーアップは1本→2本→3本のショット。ボムは敵弾消去・雑魚撃破・ボスへのダメージ・一時無敵を一度のイベントとして処理する。
- 高得点は `user://shooter-save.json` に保存。結果確定だけでなく途中のタイトル帰還と通常のウィンドウ終了でも保存する。壊れたJSON・負数・小数・型違いの値をselfcheckで検査する。

## 素材準備

- 画像は独自のSVG図案。波形と独自譜面からPythonでBGM/SEを生成し、外部の原作素材を使用しなかった。出典と生成手段は assets/CREDITS.md に記録した。
- BGMをOGGに変換するとき、ffmpegの `-fflags +bitexact -flags:a +bitexact` でコンテナ由来の差異も抑制できた。同じスクリプトから全音声のSHA-256が一致することを検査した。
- Noto Sans JPとフォント固有のOFL全文を同梱。exportのinclude_filterにもOFL.txtを含めた。可変フォントの字幅/太さはOS任せにせずFontVariationで指定する。
- スクロール背景は上下の色を一致させ、星雲や曲線を境界から離すことで継ぎ目を解消した。

## Godotと検証で得た知見

- SceneTreeの検証スクリプトでautoload参照シーンをconst preloadすると、autoload識別子の解決前にコンパイルされる。call_deferred後にmain.tscnをloadして実ツリーへ追加すると検証できた。
- 固定刻みで数分を高速に進める統合検証では、120tickごとにprocess_frameを待つ。終了前はAudioStreamPlayerをstopし、0.15秒待ってからqueue_freeし、解放用のフレームも待つ。実時間が経過しないまま終了した場合のAudioStreamPlaybackWAV解放警告を回避できた。
- sandbox内ではGodotの標準userログへの書き込みが拒否され、ログローテート中にエンジンが異常終了した。通常権限でのMakefile実行で検証できた。直接コマンドの場合はtmp内の絶対パスを `--log-file` に指定しても回避できる。
- 撮影名を `screenshot-warning.png` にすると、成功ログのファイル名がWARNING全文検索に一致する。ボス警告の画像名を `screenshot-alert.png` に変更し、既存の検査を維持した。
- キーとパッドのInputEventをInputMapへ流し、8方向移動の速度正規化・連射・ボム・ポーズ・衝突・回収・全ウェーブ・ボス第2段階・クリア・記録復元をintegration_checkで検証する。検証の保存先をtmp内に分け、実プレイの記録を変更しない。
- スクリーンショットではタイトル、戦闘、爆発途中、警告、ボスの両段階、ポーズ、クリア、ゲームオーバーを描画して検証する。

## 最終検証での補足

- F11の押下/解放イベントで全画面化（モード3）とウィンドウ復帰（モード0）が成立し、全画面のPNGも目視確認した。描画信号の待機が終わらなかった追加検証は終了上限付きに変更し、process_frameを待って撮影して成功した。
- InputMapは「キーが存在する」だけでなく、矢印4方向とWASD8キーを実イベントで流して移動方向まで確認する。左/右の特殊キー数値の取り違えをこの検査で防げる。
- push後、リモートブランチとPR headが食い違いCIが起動しなかった。git ls-remoteとGitHub refs APIで最新コミットが存在することを確認し、PR更新APIでbaseを同じmainへ再指定するとheadが同期した。force pushや履歴変更は不要だった。

## 共有物・skillへの改善提案

- godot-developmentのpitfallsに、固定刻みの統合検証と音声解放待機、autoloadシーンを実行時loadする検証パターンを追加すると再利用できる。
- 検証ログのWARNING/ERROR検索では、正常なパス名にも一致する点をskillに注意事項として追加する。今回の共有Makefile・CIは変更していない。

## 第 2 ラウンド (品質向上)

### 制作方針

- 独自の軌道防衛用メカとして、自機・敵3種・旗艦を形状から描き分け、機体ごとの5状態のスプライトシートを用意する。青緑の自機、朱色の迎撃機、金色の狙撃機、紫色の編隊機で射撃特性を読み取れる方向にする。
- 既存の出現データ・当たり判定・約3分の進行を維持し、表示と音声の層を更新する。背景の多層化、Theme、パーティクル、入力を再現するプレイ録画を検証対象に加える。
- この節には実装と検証で確認した事実を追記する。現時点では第2ラウンドの検証は未実施。

### 素材とアニメーション

- `scripts/dev/generate_art.py` から、独自のSVG 28枚を決定的に生成する。通常機は128×128、旗艦は256×160のセルを使い、1機種につき横4フレーム×縦5状態のシートを持つ。待機・移動・攻撃・被弾・撃破で装甲、砲口、コア、排気を動かす。通常表示とアイコンは別画像で、アイテムも得点・強化・ボムを個別にした。
- `AnimatedSprite2D` の `SpriteFrames` / `AtlasTexture` を機種ごとに共有すると、敵の個体数が増えても同じフレーム資源を使える。selfcheckでは初期再生、5状態各4枚、各セルの寸法と非重複、再初期化と共有を検証する。分解する部品の最大範囲をセル内に収め、隣のフレームへのはみ出しを検査した。
- 被弾時間を毎弾リセットすると、非ループの被弾フレームでボスが止まり、攻撃姿勢に戻れない。被弾演出の再発火間隔と復帰時間を分け、連射が継続しても被弾・通常・攻撃を行き来することを統合検証へ加えた。
- タイトルは独自のキーアートとエンブレムを使い、星雲・遠景星・軌道・近景星の速度を変えた。背景の動きを抑え、弾と機体の輪郭が背景より明るく見える配色を選んだ。既存のGL Compatibilityと当たり判定は維持する。
- ThemeのFontVariationは可変軸のキーにOpenTypeタグの整数値が要る。文字列の `wght` を書いた初版では文字が細くなり、GodotのPNGを見て修正した。フォントを同梱しても太さの設定まで目視する必要がある。

### 演出と音声

- CPUParticles2Dの火花、Tweenで広がる衝撃波、被弾数と補給の文字、戦闘だけのヒットストップと揺れを追加した。HUDは揺らさず、粒子と文字は戦場の範囲でクリップする。canvas_itemの簡単なシェーダで周辺を少し暗くし、旗艦戦は色味を変える。
- Line2Dのscaleだけを拡大すると線幅も拡大し、ボムが太い帯になった。Tweenでscaleと線幅の逆数を同時に更新し、衝撃波の線幅を維持した。重なる数字は頻度を制限し、補給の文字は既存表示を上へ逃がす。
- タイトル・ステージ・旗艦・結果のBGMを別曲にし、pad、FM bell、pulse、倍音低音、打楽器、ステレオdelayを組み合わせた。音声8ファイルは再生成2回のSHA-256一致、デコード成功、最大ピーク0.7869、BGM先頭末尾の差は最大0.007464を確認した。実スピーカーでの試聴と聴感上のバランスは未検証。

### 終了処理の注意点

- `AudioStreamPlayer.stop()` と `stream = null` の直後には、AudioServer側に再生参照が残る。通常closeは停止して時間とフレームを待ち、`--quit` / `--quit-after` の `_exit_tree` は短い同期待ちで音声スレッドの回収を待つ。終了時の待ち以外にゲーム進行をブロックしない。
- Godotは `--quit` / `--quit-after` を処理済み引数として除去するため、`OS.get_cmdline_args()` から終了予定を読み取る方式は動かなかった。Movie Makerでは音声mix自体が描画フレームに同期するため、終了処理で時間だけ待っても回収が進まない。Makefileの `MOVIE_FRAMES` を `--capture-frames` としてuser argsへ渡し、最後の12フレームより前に音声を停止する。録画末尾の0.4秒は音声解放の区間になる。
- Godotの標準ログはゲーム内のtmpへ出し、tmpに `.gdignore` を置く。撮影PNGを次のimportで再取り込みしないため、録画やCIの余分な処理も減る。

### 本番前に再利用したい道具

- `godot-development` に、実InputEventの時刻付き再生、全状態のフレーム比較、通常close・強制終了・Movie Makerそれぞれの音声解放確認をまとめたい。今回の `demo.gd` は終盤の初期状態から26秒で移動・連射・ボム・ポーズ・ボス撃破・結果を通す。3分全体の敵出現と進行は既存の全ステージ統合検証で補う。
- Godotに渡すフォントの可変軸と、Line2Dの拡大時の線幅を、スクリーンショット検証例としてskillへ提案する。共有ファイルやcastle側はこの作業では変更していない。

### Webと画像掲載で確認したこと

- webtunnelは既存のcaller workflowとSecretsで起動できた。サンドボックス内のTailscale CLIは異常終了したが、接続状態を通常の権限で読み取るとREADYとなった。ChromiumのGodot起動表示が消えたことと実画像を確認してから操作した。
- macOSの画像で表示されていた改行キー記号が、Webではフォントに無く四角になった。出撃ボタンを `Enter / A` と書き、OSのフォントフォールバックに頼らない表示へ直した。
- `puts upload` はアプリの既定設定をSwiftDataから読む箇所で停止した。既存のR2用環境変数を `PUTS_ENDPOINT` / `PUTS_BUCKET` / `PUTS_PUBLIC_BASE_URL` / 認証用変数へプロセス内で渡すと、同じputsによるアップロードが成功した。認証情報はファイル・ログ・PRへ出力せず、新しい連携や認証発行は行っていない。
