# 黄昏の灯砦の実装知見

## 防衛ゲームの設計

独自作品「黄昏の灯砦」。経路と建設地点・塔・敵・ウェーブの正は `scripts/catalog.gd`、戦闘状態の所有者はautoloadのRun。画面はInputMapの操作をRunに渡し、攻撃・撃破・建設のイベントでアニメーションと音を開始する。

- タワーは射程内で終点に最も近い敵を優先する。地上範囲攻撃と対空、装甲貫通、減速を分け、色だけでなく機能で配置を選べるようにした。
- 戦闘を1/60秒以下に分割して進め、3倍速やフレーム落ちで減速・標的判定を飛び越えないようにした。
- 敵のHPや資金を変更しない通常ルールで、全10ウェーブ・ボス撃破と無防備敗北をselfcheckから確認する。購入失敗時に資金や塔を変更しないこと、強化2回と売却額も検査する。
- 星評価は残り拠点HPに応じる。JSONの破損を処理し、最高評価を `user://` へ保存する。自動検証は専用の保存先へ切り替え、プレイヤーの記録を上書きしない。

## 手直しラウンド（見た目の特色化）

### 分かりにくさの原因と効いた表現

前回は、上部HUD・右の情報パネル・画面下の共通操作ガイドという他ゲームでも使った構成に、コード生成したSVGを当てはめていた。タイトルからすぐ戦闘へ移るため、初見では世界のどこを守るのか、光る地点と塔の選択をどう結び付けるのか、次に押す操作は何かを画面から読み取りにくかった。

- タイトルと戦闘の間に正式な `map` 状態を設け、月夜の森から川と石橋を経て夜明けの灯砦へ至る1枚の横長タペストリーを見せた。タイトル・地図・戦闘で同じ長景を使うと、各画面が同じ旅程の一部としてつながった。
- 一般的な角丸パネルを、直線的な刺繍縁の巻物と塔ごとの糸色を持つ紋章盾へ置き換えた。下端の共通操作ガイドは廃止し、現在使える操作をボタン、現在の目的を戦場内の短文、次の敵を予告欄へ分けた。
- 初回だけ4手順の指南巻物を重ね、光る地点、紋章盾、建設後の残金、次の敵、襲来開始を順に教える。手順外のボタンは無効にするだけでなく「先に地点を選ぶ」「あと30金貨必要」のように理由をその場へ表示する。Q / Backまたは巻物のボタンで省け、完了記録は戦績とは別の `user://` JSONへ保存する。
- 建設可能、資金不足、占有、現在選択を色だけでなく、＋、斜線、四角、二重枠でも区別した。空き地点には選択中の塔を半透明で置き、建設後の姿と残金を決定前に確認できる。強化前後の威力・射程・間隔と売却後資金も並べた。

### 画像生成の手順、当たり外れ、手間

OpenAI image_genへ入力画像なしで3回依頼し、塔4種、敵5種、長景をそれぞれ透過PNGまたは横長PNGとして生成した。プロンプトでは粗い亜麻布、太い毛糸、チェーンステッチと伏せ縫い、平面的な横向き像、亜麻・茜・褪せた藍・煤茶・苔緑・黄土の限定色を共通条件にした。固有作品名、文字、ロゴ、枠、透かしは入れず、塔と敵は左からの並び順まで指定した。3枚とも初回出力を採用でき、生成そのものより、余白が不均等な敵をゲーム座標へ切り出す調整と、一覧撮影による識別確認に手間がかかった。

塔は4体がほぼ等間隔で、横幅の4等分をそのままAtlasTextureにできた。一方、敵は大きさと上下位置が不均等で、5等分すると隣の像が混ざったり小鬼群が欠けたりした。実画像を見て種類ごとの正規化領域を指定する必要があった。1枚絵には連続コマがないため、同じ領域を6フレームへ登録し、待機・移動・攻撃・被弾・消滅ごとに位置、拡縮、回転、色と透明度を変える方法で刺繍人形の動きを付けた。これはシルエットを保ちやすいが、手足そのものが差し替わる前回のSVGアニメーションより動作差は小さい。

前回の手続きSVGは固定条件から再生成でき、セル境界、各コマの差、SHA-256一致を自動検査しやすい。反面、モデルがコードで描く単純形状は他ゲームと質感が揃いやすく、背景、塔、敵を一目で同じ世界の絵にするのが難しかった。画像生成PNGは刺繍の密度、糸の不均一さ、長景の物語性で明確に優れたが、同じプロンプトから同一バイト列を再生成できず、構図と余白も一定でない。生成物はPNG自体を正として保存し、CREDITSへプロンプトの要点を記録し、9種類×5動作×開始・途中・終了の一覧画像と実戦画面を目視する方が検証しやすかった。

ライセンス確認では、生成3枚は第三者画像を入力せずOpenAI利用規約のURL、生成手段、プロンプトの要点、改変内容を `assets/CREDITS.md` に記録した。Zen KurenaidoはGoogle Fonts公式配布のTTFを取得し、配布元URL、著作者、OFL-1.1とOFL全文を同梱した。環境音は外部録音や旋律を使わず、固定seedの風、旗布、焚き火、木の軋みをPythonで合成した。

### GodotでタペストリーUIを作る時の注意点

- GL CompatibilityのCanvasItemで画面全体の `SCREEN_TEXTURE` を読み直す織物シェーダは、同じ画面を再帰的に写したような残像になった。入力を透過するColorRectへ、画面をサンプリングしない半透明の縦糸・横糸だけを描き、最前面で重ねると安定した。
- 横長画像をTextureRectへ入れる時は、タイトルと地図で `STRETCH_KEEP_ASPECT_COVERED` を明示する。画面遷移のフェード直後に自動撮影すると地図だけ暗く見えるため、遷移アニメーションが終わる0.4秒後に撮る。
- 生成画像の複数キャラは等間隔を前提にしない。切り出し領域を実画像で決め、塔と敵で表示高さを分ける。全種類を同じ一覧へ出す検証では、敵フラグを種類ごとに渡さないと塔のatlasを参照して空表示になる。
- 選択状態を色だけで示すと、織物シェーダと背景の色むらに埋もれる。線幅、記号、脈動、半透明の完成予想を併用し、無効ボタンには具体的な理由を本文として残す。
- 指南の既読は戦闘の `new_run()` で消さず、専用ファイルへ保存する。保存関数を同じ内容の再書き込みとして冪等にし、破損JSONは未読へ戻すと、テスト用保存先へ差し替えて初回と再訪を両方検証できる。

### skill化の候補

- game-asset-searchへ、複数キャラを含む生成画像の実寸・余白を一覧化し、正規化したAtlasTexture領域のたたき台と接触シートを作る手順を追加する。等分できるかを先に判定できれば、今回の敵atlasの試行を減らせる。
- godot-developmentへ、画面遷移のTween完了後に撮影する例、GL Compatibilityで画面サンプリングを使わない全画面質感オーバーレイ、初回指南の保存先をテスト時だけ差し替える例を追加する。
- 共有skillはこの作業ブランチでは変更せず、提案だけをこの文書へ残す。

## 素材・アニメーション

- 深緑の谷・金の灯・紺の石造りという配色で、塔4種・敵5種を独立したSVGシートにした。各シートは5動作×6コマ。部位を動かし、シルエットと装備で見分けられる。
- 画像18点と音声14点は固定条件のPythonスクリプトで再生成できる。全270コマの境界内収容とフレーム相違、再生成後のSHA256一致、WAV形式・非無音・非クリッピングを検査した。フォントはOFL付きで同梱する。
- 塔は建設・待機・攻撃・強化・売却、敵は出現待機・移動・被弾・死亡の場面にフレーム再生を接続する。被弾は55msの局所的なヒットストップとフラッシュ、建設・撃破はCPUParticles2DとTweenのポップ、拠点被害は画面揺れを使う。
- 即時に解決する攻撃には、発射から着弾までを同時に描いて減衰させるトレイルを合わせた。移動する弾より先に敵が死亡して金貨が増える不一致を避けるためである。臼砲は放物線の残光、陽光は太いビーム、氷晶は範囲の輪で区別する。
- 背景と前景に異なる速度の視差を付け、拠点にはGL Compatibilityで動くPointLight2Dを配置。HUDは前景の草より高い描画順にする。ローカル画像で草が最下部の操作説明に重なる不具合を検出して直した。

## 入力と表示で得た知見

- InputMapの方向入力に対する `InputEvent.is_action_pressed` は、既定ではJoypadMotionの向きを厳密に区別しない。左スティックは `exact_match=true` とし、十字キーだけでなくX/Yの正負を実入力で検証する。
- 同じフレームに売却と再建設が入っても、旧塔の表示を残さないよう売却イベント時に表示辞書から外す。状態が持つ地点の存在だけを見ると別種の塔画像が残り得る。
- 撮影用に戦闘を高速で進めると、ゲーム時間と表示アニメーションの実時間がずれる。ボス画面などを撮る直前に表示ノードを同期し直し、過去の死亡アニメーションを大量に残さない。
- マウスは地点の選択と建設を分け、選択しただけで資金を消費しない。キーボード・パッドは地点選択、塔切替、購入、強化、売却、速度、休止、結果からの復帰まで操作できる。

## 音声と検証環境

- 5場面のBGMと塔ごとの発射SEを独自合成。単純な正弦波だけにせず、撥弦、倍音の笛、持続音、低音、金管、ベル、ノイズ打楽器を重ねた。
- 音声停止ではplayer.stopとstream参照の解除後、出力遅延と数フレームを待つ。通常終了と `--quit-after` は別に検証する。headlessは音声再生を開始せず、Movie Makerでは再生する。
- サンドボックスではエディタ設定の保存とmacOSのウィンドウ描画が遮断された。headless用にはgodot-developmentのself-contained複製を用意し、実際のウィンドウ検証は必要な権限を得て通常のGodotで実施した。失敗ログを除外して成功扱いにはしていない。

## 検証記録

- `make test GAMES=towerdefense` はexit 0。lint・import・起動・selfcheck・入力統合・指定フレーム終了を通した。通常資金の戦略で全10波を拠点HP20のまま突破した。
- `make screenshot GAMES=towerdefense` はexit 0。代表画面、9キャラの5動作の開始/途中/終了、建設・強化・被弾・撃破・拠点被害・4塔の発射を含む31枚を目視した。処理を止めた敗北撮影ではカウントアップも停止するため、撮影時に最終HPを明示的に反映する。
- `make movie GAMES=towerdefense` と `make -C games/towerdefense movie-play` はexit 0。5秒の起動と30秒の実入力プレイの2秒間隔/末尾フレームを目視した。プレイ録画では建設・強化・3倍速・第4波までの戦闘を操作し、HPや資金は書き換えていない。
- `make build-all GAMES=towerdefense` と `make build-web GAMES=towerdefense` はexit 0。macOS・Windows・LinuxとWebの成果物を生成した。
- `make towerdefense-run RUN_FLAGS='--script res://scripts/dev/runcheck.gd'` はexit 0。描画・通常の音声出力・Escによる終了を確認した。実音声付きの `--quit-after 1/30/120` と描画付きF11往復もexit 0。最終ログ全文にWARNING/ERROR、終了時のObjectDB/リソース警告はなかった。
- PR #49へ画像と録画を `puts upload` で公開し、公開URLから取得した内容のSHA256をローカルと照合した。CIとWebの最終証拠・実行リンクはPRの検証欄に集約する。

## Web検証で得た知見

- このリポジトリのcaller workflowは8000番ポートで配信する。runner上で開くURLは `http://localhost:8000/index.html`。CDPのポートとは別であり、一般例の8080番をそのまま使うと接続できない。
- 1280×656のブラウザ表示ではゲーム全体を縦に合わせるため左右に余白が付く。ゲームの座標に縮尺と左余白を反映してクリックし、建設地点の選択を実画像で確認した。
- Tailscale越しのagent-browserのPNG転送が応答待ちになったため、同じrunnerのChromiumにCDP接続しJPEGで取得した。CDPのキー/マウス入力で操作し、ゲーム状態を書き換える評価式は使っていない。

## 残した判断点と再利用候補

- 美術は生成SVGによる絵本風の方向を採用。手描き絵画や写実的な表現は選んでいない。人間の初見の難度と音楽の好みはレビュー可能な画像・録画で評価する。
- 物理ゲームパッド実機の触感は未検証。InputMapに届くゲームパッドの実イベント、描画付きのF11を検証する。
- godot-developmentへの候補は、方向を区別するスティック入力検証、フレームを固定した全キャラの撮影、通常終了と強制フレーム終了の音声解放検証。
- game-asset-searchへの候補は、再生成一致・セル境界・各フレームの差分とPR用一覧の生成を一度に検査する補助スクリプト。
- 共有skill・ルールは変更していない。変更範囲はこの文書と `games/towerdefense/` に閉じる。
