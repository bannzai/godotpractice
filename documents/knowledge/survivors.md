# survivors の実装・検証知見

## ゲームの設計

独自の作品名は「宵森の灯守」。青緑の森で灯守を移動させ、10分生き延びる。最後の30秒に強敵が現れる。強敵の撃破は必須ではなく、600秒生存が勝利条件。

- 進行状態は autoload の RunState が所有する。画面は入力ベクトルを渡し、座標・武器・経験値・勝敗を読む。ポーズと強化選択では step が進行を止める。
- 敵は物理ノードにせず状態の配列で保持する。敵の追跡、自動投射、周回攻撃、範囲攻撃を軽量に更新し、画面でまとめて描画する。
- 出現編成・敵の能力・経験値の閾値は game_rules.gd が正。出現表の全境界を selfcheck で検査する。
- 経験値を一度に大量取得しても強化を順番に選択できる。全武器最大後も有効な3択を出す。能力値の上限に達した候補は除外する。
- 回復と磁石は撃破時のドロップに加えて定期供給する。ジェムが増え続ける場合は古いジェムの値を統合し、経験値を失わせずに数を制限する。

## Godot で得た知見

- キーボードの特殊キー番号を手書きで推測すると左右の割り当てが壊れる。実入力イベントで「移動・メニュー選択・決定・休止・再開」を通す検証を加え、誤りを検出した。InputMap の存在だけの確認では不足する。
- headless の入力検証でも、マウスの座標を検証する際は root.size を1280×720に設定する。既定サイズのままでは見た目と異なる座標をクリックしてしまう。
- macOS の全画面切替は非同期。F11の往復検証は各切替後にOSのアニメーション完了を待つ。
- 強化選択後に保留経験値で次の強化が始まる場合、最終的な phase は同じ upgrade のまま。画面名の変化だけでUIを更新すると古い候補を表示するため、選択処理後に候補UIを再構築する。
- Dummy音声ドライバの検証では、短い起動・終了中に再生したWAVのPlaybackが残り、exit 0でもリソースリークが出た。AudioServer.get_driver_name()でDummyを検出し、その環境では再生を開始しない。通常ドライバは別スクリプトで実再生を検証する。
- BGMのループは finished で再開する方式から AudioStreamWAV の LOOP_FORWARD に変更し、ループ終端を音源の長さとサンプルレートから設定した。通常ドライバで24秒の終端を越える再生を確認した。
- 演出の上限数をFIFOで制限する場合、大量撃破の hit/death によって範囲攻撃の輪まで初回描画前に消える。敵へのダメージ処理の後に輪を追加し、60体同時撃破でも残る回帰検証を追加した。輪の最終半径も攻撃判定の半径から求める。
- importは失敗診断があってもexit 0になった事例がある。Makefileのimportにログ全文のWARNING/ERROR検査を追加した。sandbox内ではGodot標準のアプリデータ・editor設定への書き込み制限に当たり、許可付き実行で検証した。

## 素材の準備

- 独自SVG13点と、独自の音列・波形合成によるBGM/SE5点を用意した。生成スクリプトを残し、2回の生成結果がSHA256で一致することを確認した。
- WAVのクリッピングなし、BGMの先頭と終端の差が1PCM以内であることを検査した。
- Zen Maru Gothic Mediumを同梱し、日本語表示をOSのフォールバックに依存させない。OFL全文を全exportのinclude_filterに含めた。
- game-asset-search の record-credit と check-credits を利用。生成物を勝手にCC0とはせず、由来・生成手段と利用条件をCREDITSに記録した。

## 通常起動の確認

`games/survivors/Makefile` の `run` は `Godot --path .` のまま維持する。`make -C games/survivors run` でエディタを開かずゲーム用ウィンドウが生成され、起動ログに `survivors boot` が出ることを確認した。

`run_capture.gd` はエディタバイナリで上記環境変数を指定した時だけ有効になり、撮影後に終了する。通常起動とエクスポートでは有効にならない。シーン・autoload変更後にも、個別ゲームのrunからウィンドウとタイトルを確認する。ルートのrunがmainへ入ったら `git fetch origin main` と `git merge origin/main` で取り込み、ルートの起動経路も確認する。

## 第 2 ラウンド (品質向上)

### 方針と開始時の確認

既存の10分生存・3種の武器・3択強化・終盤の強敵を維持し、夜の青緑、灯の金色、敵の珊瑚色を中心に美術を統一する。灯守・葉の精・蛾・石の巨獣・森の主を別々の輪郭で描き、各体に待機・移動・攻撃・被弾・死亡のフレームを用意する。画像と音声は再生成可能な独自の手続き生成物とし、生成元もゲーム内に保持する。

開始時の `make screenshot GAMES=survivors` は exit 0。タイトルとプレイのPNGを目視し、既存の読みやすさとUI操作座標を基準にした。通常音声付きの起動はsandbox内でAbort trap 6になったため、許可付きで描画・音声を検証した。更新後のCoreAudioで通常終了と強制フレーム終了の両方が成功した。

### 素材と描画の組み方

- 5体それぞれに160px角、横6枚×縦5動作のSVGを用意した。全150フレームの画像差分と透明な余白を検査し、死亡時の沈み込みで隣のセルへ絵が漏れる箇所を修正した。小さい絵でも輪郭で分かるよう、蛾の羽、巨獣の石甲冑、主の枝角と冠を使い分けた。
- `actor_visual.gd` のAnimatedSprite2Dが再生を所有する。同じ動作の指示で先頭へ戻さず、攻撃・被弾中の移動指示は保留する。死亡の最終フレームを保持し、再挑戦では明示的に待機へ戻す。
- `arena.gd` は敵の安定したIDで表示ノードを対応付ける。死亡中の表示は専用の子ノードへ移し、カメラ追従と再開始時の破棄を継続する。結果UIをすぐ全面表示すると主人公の死亡アニメが見えないため、敗北だけ0.65秒待って結果を出す。
- 描画の手前・奥を分け、タイル床、遠景の木々、霧、近景の枝、蛍を異なる比率で移動させる。GL CompatibilityのCanvasItemシェーダで周辺を暗くし、HUDはその上に固定する。日本語フォントとボタンの各状態は `assets/theme/night.tres` に統一した。
- 画像・音声の再生成入口は `scripts/dev/generate_assets.py`。SVGのロゴ輪郭化だけfontToolsを利用し、それ以外はPython標準ライブラリで生成する。PNGの目視前検査にはrsvgとPillowを利用した。最終素材はゲームが直接読み込めるため、生成用ツールはゲーム起動やCIビルドには不要。

### 演出と音声で見つけた問題

- 見た目のノード数にも上限が要るが、一斉撃破で枠が埋まると最後に発生する範囲攻撃・回復・レベルアップまで消えてしまう。演出をイベント単位で管理し、通常の命中・撃破を48組まで、重要演出を含む全体を64組までにした。60体一斉撃破後に重要演出が生成される回帰検証を追加した。
- 範囲の輪をアイコンの画像幅で拡大すると、画像の余白の分だけ判定より小さくなる。輪のLine2D頂点を実際の攻撃半径から作り、Tweenの拡大終了時に同じ半径へ達することを検査した。
- 粒子には独立した `spark.svg` を使用する。回復・成長・吸引の色、拡大する輪、浮かぶ数値を組み合わせる。ヒットストップは進行状態への時間入力だけを短く止め、画面の揺れやフラッシュは進める。
- 4場面のBGMと9種SEを、撥弦・木琴・ベル・倍音パッド・ベース・ノイズ打楽器で合成した。全13音声の再生成SHA-256一致、飽和なし、ループ接続点に局所的な大きな段差がないことを解析した。音声の実出力・拍周期・帯域の違いを検証したが、人の耳による主観試聴は行っていない。
- 通常音声はstop→stream参照解放→音声ミックス反映待ちで終了する。`--quit-after`には次フレームがないため、終了処理中に短い待機が必要。Webの単一スレッドでは同期待機をしない。
- Movie MakerはDummyドライバでも音声を動画へ書き込む。`Engine.get_write_movie_path()`で明示録画を判別して再生する。Godotは `--quit-after` をGDScriptへ渡さないため、Makefileのフレーム数を環境変数にも渡し、末尾2フレームを音声解放へ割り当てた。無音の録画を成功にしないよう、出力mp4の平均音量も検査する。

- webtunnelを `up survivors --software-webgl --ref polish/survivors --wait` で起動し、runnerのChromium上でタイトル→プレイ→敗北結果→タイトルを実操作した。状態を注入せず、Enterで開始して通常ルールで生存1分20秒・撃破125・レベル1の敗北まで進行し、マウスでタイトルへ戻った。各画面を撮影・目視し、ブラウザエラーなし。専用のagent-browserセッションを閉じて `down survivors` を実行した。

- 新たな仕様判断の保留はない。独自の手続き生成による絵本風の2D表現を採用し、音声の主観的な聴き心地・人間の初見難度・全機種の性能評価は自動検証の範囲と区別する。

## 手直しラウンド (見た目の特色化)

### 着手時の診断と方針

2026-09-07 の変更前画面をタイトル・プレイ・強化・結果の順で撮影した。夜の森と四角いパネルで統一されていたが、プレイ画面の上部と下部に幅広の HUD があり、操作ガイドも画面下の一行に集中していた。そのため、戦場よりテンプレート型 UI が先に目に入り、「敵から離れる」「光を拾う」「次の強化を選ぶ」という行動の順番が場面の中から読み取りにくかった。

このラウンドでは、画像生成のラスター素材を中心にキャラクターと武器を再構成する。背景は紫から青緑へ変化する空、地平線の縞状太陽、無限に流れる透視グリッドで作る。HUD は画面の縁の経験値光と小さな状態表示に縮小し、初回チュートリアルをプレイ中の発光マーカーと短い文章で示す。強化候補は、選択中の利点と現在からの変化が直接分かるネオン看板にする。

### 画像生成と手続き SVG の比較

game-asset-search の共通スタイル用テンプレートに沿い、元作品や既存ブランドの名称を使わず、輪郭・配色・発光・用途を文章で固定した。共通条件は「黒に近い宇宙色、シアンとマゼンタの縁光、太いシルエット、縮小しても識別できる正面寄りの切り抜き」とし、主人公、通常敵3体、強敵、武器3種を個別に生成した。タイトル絵だけは16:9で、縞状の太陽、透視グリッド、対峙する主人公と強敵、左側の文字用余白を一枚の構図として生成した。

- 当たりだったのは、キャラクターの輪郭とタイトル絵である。前ラウンドの手続き SVG より一体ごとの表面情報と光の揺らぎが多く、プレイ中の小さい表示でも、蛾の四枚羽、猟犬の低い姿勢、センチネルの円形、多角形の強敵を区別できた。タイトルも背景とゲーム中の色・太陽・グリッドを一度に予告できた。
- 外れだったのは「透過背景」という文章だけでは、市松模様を画像へ描き込む生成結果が出たことである。データハウンドとセンチネルは透過化の編集をやり直し、角のアルファ値とRGBAチャンネルを機械検査した。単にファイル形式がPNGであることは透明性の証拠にならない。
- 画像生成は9点を個別に作り、透明性の失敗した2点を再生成・編集した。1枚ごとの試行と目視に手間はかかる一方、複雑な形をSVGパスとして実装する時間は不要だった。手続きSVGは再生成の決定性、差分の小ささ、セル単位の自動検査に優れる。画像生成は質感と意外性に優れるが、同じキャラクターの完全に一致する複数ポーズを一度に得る難度が高い。
- 今回は各キャラクターの生成画像を共有テクスチャとして読み込み、待機・移動・攻撃・被弾・死亡を位置、傾き、拡縮、色、透明度の6フレームでアニメーションさせた。前ラウンドの5動作×6フレームという再生仕様は維持しつつ、スプライトシートのセル差分からポーズ変形へ方式を変えた。連続フレーム一覧を撮り、特に攻撃の踏み込み、被弾の振れ、死亡の沈み込みが見分けられることを確認した。
- 生成PNGは1254px角、タイトル絵は16:9で、Godot側では同じTexture2Dを全個体で共有して縮小する。敵ごとに画像を複製せず、ShaderMaterialだけに位相差を持たせた。ラスター素材へ変えた後の360体負荷試験をやり直し、前ラウンドのSVG時の数値を流用しない。

画像生成物は第三者素材を入力せず、OpenAIの生成機能とプロンプトの要点を `assets/CREDITS.md` に記録した。フォントはGoogle FontsのRocknRoll One Regularを公式リポジトリから取得し、作者の著作権表示とOFL-1.1全文を `assets/fonts/OFL.txt` に同梱した。旧フォントファイルは来歴のため残しているがコードからの参照とエクスポート対象から外し、現行画面・生成処理・配布物では使わない。

### 画面内の案内と Godot での注意点

- タイトルは「敵を避ける」「攻撃は自動」「光片を拾う」「10分を越える」を開始ボタンの近くへ置いた。常設の操作ガイド行は廃止し、初回だけ戦場内の対象を円と線で指す3段階の案内にした。移動距離、経験値取得、強化画面への到達を完了条件にし、待ち続けた場合も次へ進む。Tキー、ゲームパッドY、画面上のSKIPボタンで中断できる。
- 経験値は下部バーではなく画面四辺を時計回りに満たす発光線にした。現在のHP・残り時間・撃破・レベル・武器だけを隅へ寄せ、中央の敵・回収物・進行方向を隠さない。無限平面は境界で座標を制限せず、太陽と透視グリッドをプレイヤー座標と時間から描き直す。
- 強化画面は3枚のネオン看板へ「現在値 → 選択後」を直接表示する。GodotのButtonでは `mouse_entered` で見た目の選択番号だけを変えると、Enter/Aが以前のキーボードフォーカスを決定してしまう。ホバー時に `grab_focus()` を呼び、`focus_entered` を表示更新の正とする。マウス移動後にEnterでホバー中の候補が適用される統合テストを追加した。
- 全画面VHS効果は `hint_screen_texture` からRGBを少しずらし、走査線、粒状ノイズ、周辺減光を合成する。UIより後ろへ置くとタイトルや看板だけ質感が異なるため、入力を遮らないColorRectとして全画面の手前に置く。GLSLの `smoothstep` は小さい値から大きい値の順で指定し、逆順によるGL CompatibilityとWebの未定義差を避ける。
- RocknRoll OneはThemeとCanvasItemの直接描画の両方へ明示的に渡した。Themeだけ差し替えても `draw_string()` は変わらない。禁止フォント名の参照検索と全4 export presetの除外指定を両方行い、実行時と成果物を分けて確認する。
- 電気的な環境音は整数周期の発振だけで16秒ループを作り、BGMとは独立したAudioStreamPlayerで小さく重ねた。既存4譜面と9種SEの役割は維持し、音色だけを矩形波プラック、位相変調リード、デチューンパッドへ変更した。環境音も停止・参照解放の対象に含め、通常音声検証で再生と終了を確認する。
