# 潮風カートの実装知見

## 設計判断

- 周回コースの距離と左右位置を状態として持ち、3D の位置・坂・カメラ・ミニマップを同じコース関数から計算する。自由な車両物理ではなく、経路を基準に操舵するアーケード方式を採用した。ハンドルは横方向の移動、カーブの外向きの力への対抗、アイテム回避と内側のショートカット進入に使う。
- 周回はスタート線との接触だけで数えず、順番にチェックポイントを通過した回数から決める。逆走や復帰による重複通過は加算しない。
- CPU の順位と速度補正、アイテム、実測ゴール時刻をレース状態に集約した。結果画面は全車のゴールを待って順位表を表示する。
- フレーム落ちによる判定の抜けを防ぐため、レースの更新を細かい時間刻みに分けて積分する。

## 表現と素材

- ミント色のカワウソ、橙色のキツネ、紫色のフクロウは別の車体形状・顔・装備を持つ。各モデルのメッシュ構成と独立したシーン、AnimationPlayer の待機・走行・ドリフト・ブースト・被弾・歓喜の6状態を作った。
- UI は同梱した日本語フォントと共通 Theme を使う。素材は独自の手続き生成 SVG・メッシュ・多音色 WAV と OFL フォントで、assets/CREDITS.md に記録する。
- 海、島、灯台、近景のヤシ、遠景の島と雲を重ね、GL Compatibility で描画する。

## 検証中に確認したこと

- sandbox 内の通常 Godot はエディタ設定や user:// の補助ディレクトリ保存に失敗する。godot-development の prepare-sandbox-godot.sh で作業ディレクトリ内に自己完結版を用意した。GUI の描画確認は許可された通常の GUI 起動として実行している。
- 起動と selfcheck の終了コードだけでなく、インポートのログ全文にも ERROR が無いことを検査する必要がある。

## 残した判断点

- 元作品の再現ではなく、海辺の小さなサーキットと独自キャラクターによるアーケードレースを採用した。
- 実機ゲームパッドの接続と Windows / Linux 実機プレイ、聴感による音楽評価は、入力イベント検証やエクスポート成功と区別して報告する。

## skill 化の候補

- コース配置を表示と周回検証で共有する3Dレースの雛形。
- 3Dモデルの全アニメーションを開始・途中・終了で撮影する一覧生成。
- 実入力デモ・音声停止・終了時リーク検査と、公開PRへ検証画像をまとめる手順。

## 動作検証で見つけた不具合と対処

- ステア入力の基準となる右ベクトルは、坂でも単位長さにして表示と当たり判定に共用する。正規化を省くと、坂だけ横方向の距離がずれる。
- 路面の終端と落下判定を別の距離で定義すると、橋の先の空中を走れてしまう。路面の存在判定をコースデータに置き、本線とショートカットの幅から判定した。
- 結果画面は全車の実測タイムを使うが、ベスト保存は自分のゴール時点で行う。他車を待つ間にタイトルへ戻っても記録を失わない。
- macOS の全画面切替は非同期のウィンドウアニメーションを伴う。実入力統合テストで切替完了前に再び F11 を押すと復帰しないため、実時間の移行待機を設け、全画面化と復帰の両方を確認した。
- カードをマウスで選んだ後に Enter を押すと、Button の既定入力が先に消費しうる。ゲームの決定入力を `_input` で処理してから handled にし、カードのフォーカスが残ってもレースを開始する。
- 演出用 Tween を中断すると、途中のフラッシュ色が残る場合がある。次のポップアップでもフラッシュのアルファをゼロへ戻すようにした。
- 25秒デモで一度だけドリフトする固定操作は、CPUのアイテム命中と重なって失敗した。開発シナリオの乱数を固定し、被弾から回復後に入力を再試行することで、位置や進行度を直接変更せず、取得とブーストの実行を検証した。

## 音声終了の実測

- 通常の CoreAudio / Dummy 起動では裸の `--quit-after 60` と短い `--quit-after 2` が警告なしで終了した。通常の閉じる操作は音声を停止し stream を外してから複数フレーム待つ。
- Movie Maker は音声をフレーム単位で同期処理する。終了通知中の待機だけでは次の mix が発生せず、裸の `--quit-after` の録画でリークを再現した。専用録画スクリプトから事前停止し、任意フレーム指定では `--audio-stop-at-frame` をユーザー引数として渡す。
- Godot が消費した `--quit-after` は `OS.get_cmdline_args()` に残らない。そこから終了フレームを読めるつもりの枝を除去し、通常終了と録画の実際の経路を分けて検証した。

## 共有物への提案

- 現在の変更ゲーム検出は `games/` 外の変更をすべて共通変更として扱うため、ゲーム固有の `documents/knowledge/kartrace.md` だけでも全ゲームのCIが走る。知見ファイルを同名ゲームへ対応付ける改善を提案する。作業範囲に従い共有スクリプトは変更していない。

## 最終検証と Web 実操作

- ローカルで test、screenshot、movie、movie-play、build-all、build-web、kartrace-run を実行し、終了コード0とログ全文を確認した。32枚のPNG、25.53秒の実入力プレイ録画の2秒間隔と末尾、起動録画を目視した。
- CI run 34035605388 の全チェックが成功。artifact の32枚と5秒動画（0.5秒間隔と末尾）を目視し、表示崩れと終了時リークがないことを確認した。CIの描画ログには共有検証で除外されるV-Sync非対応通知のみが残る。
- webtunnel run 34047008328 はゲーム実装の最終コミット `5ab93a0` を Web エクスポートした。runner の Chromium へ CDP の実キー入力を送り、タイトルから3周を走り、全車の結果を表示してからEscapeでタイトルへ戻った。自分の記録は44.10秒。位置や周回などのゲーム状態は書き換えていない。
- SwiftShader の3D描画では実時間よりゲーム進行が遅くなるため、固定の待ち時間だけで完走を判断せず、撮影した周回表示と結果画面で判定した。アクセル保持に短い左操舵とアイテム操作を繰り返して走らせた。
- 先行するWebセッションでは撮影が応答しなかったが、新しいrunnerではCDP撮影と画面プレビューの両方が成功した。原因の断定は避け、CDPのDOM応答・プレビュー・撮影を別に調べる手順を改善候補とする。
- この環境でGitHub CLIの名前解決経路が接続タイムアウトになった際は、コマンド単位の `GODEBUG=netdns=cgo` で接続に成功した。システム設定は変更していない。
