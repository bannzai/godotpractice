# 潮風カートの実装知見

## 設計判断

- 周回コースの距離と左右位置を状態として持ち、3D の位置・坂・カメラ・ミニマップを同じコース関数から計算する。自由な車両物理ではなく、経路を基準に操舵するアーケード方式を採用した。ハンドルは横方向の移動、カーブの外向きの力への対抗、アイテム回避と内側のショートカット進入に使う。
- 周回はスタート線との接触だけで数えず、順番にチェックポイントを通過した回数から決める。逆走や復帰による重複通過は加算しない。
- CPU の順位と速度補正、アイテム、実測ゴール時刻をレース状態に集約した。結果画面は全車のゴールを待って順位表を表示する。
- フレーム落ちによる判定の抜けを防ぐため、レースの更新を細かい時間刻みに分けて積分する。

## 表現と素材

- ミント色のカワウソ、橙色のキツネ、紫色のフクロウは別の車体形状・顔・装備を持つ。各モデルのメッシュ構成と独立したシーン、AnimationPlayer の待機・走行・ドリフト・ブースト・被弾・歓喜の6状態を作った。
- UI は同梱した日本語フォントと共通 Theme を使う。素材は独自の手続き生成 SVG・メッシュ・多音色 WAV と OFL フォントで、assets/CREDITS.md に記録する。
- 海、島、灯台、近景のヤシ、遠景の島と雲を重ね、GL Compatibility で描画する。

## 検証中に確認したこと

- sandbox 内の通常 Godot はエディタ設定や user:// の補助ディレクトリ保存に失敗する。godot-development の prepare-sandbox-godot.sh で作業ディレクトリ内に自己完結版を用意した。GUI の描画確認は許可された通常の GUI 起動として実行している。
- 起動と selfcheck の終了コードだけでなく、インポートのログ全文にも ERROR が無いことを検査する必要がある。

## 残した判断点

- 元作品の再現ではなく、海辺の小さなサーキットと独自キャラクターによるアーケードレースを採用した。
- 実機ゲームパッドの接続と Windows / Linux 実機プレイ、聴感による音楽評価は、入力イベント検証やエクスポート成功と区別して報告する。

## skill 化の候補

- コース配置を表示と周回検証で共有する3Dレースの雛形。
- 3Dモデルの全アニメーションを開始・途中・終了で撮影する一覧生成。
- 実入力デモ・音声停止・終了時リーク検査と、公開PRへ検証画像をまとめる手順。

## 動作検証で見つけた不具合と対処

- ステア入力の基準となる右ベクトルは、坂でも単位長さにして表示と当たり判定に共用する。正規化を省くと、坂だけ横方向の距離がずれる。
- 路面の終端と落下判定を別の距離で定義すると、橋の先の空中を走れてしまう。路面の存在判定をコースデータに置き、本線とショートカットの幅から判定した。
- 結果画面は全車の実測タイムを使うが、ベスト保存は自分のゴール時点で行う。他車を待つ間にタイトルへ戻っても記録を失わない。
- macOS の全画面切替は非同期のウィンドウアニメーションを伴う。実入力統合テストで切替完了前に再び F11 を押すと復帰しないため、実時間の移行待機を設け、全画面化と復帰の両方を確認した。
- カードをマウスで選んだ後に Enter を押すと、Button の既定入力が先に消費しうる。ゲームの決定入力を `_input` で処理してから handled にし、カードのフォーカスが残ってもレースを開始する。
- 演出用 Tween を中断すると、途中のフラッシュ色が残る場合がある。次のポップアップでもフラッシュのアルファをゼロへ戻すようにした。
- 25秒デモで一度だけドリフトする固定操作は、CPUのアイテム命中と重なって失敗した。開発シナリオの乱数を固定し、被弾から回復後に入力を再試行することで、位置や進行度を直接変更せず、取得とブーストの実行を検証した。

## 音声終了の実測

- 通常の CoreAudio / Dummy 起動では裸の `--quit-after 60` と短い `--quit-after 2` が警告なしで終了した。通常の閉じる操作は音声を停止し stream を外してから複数フレーム待つ。
- Movie Maker は音声をフレーム単位で同期処理する。終了通知中の待機だけでは次の mix が発生せず、裸の `--quit-after` の録画でリークを再現した。専用録画スクリプトから事前停止し、任意フレーム指定では `--audio-stop-at-frame` をユーザー引数として渡す。
- Godot が消費した `--quit-after` は `OS.get_cmdline_args()` に残らない。そこから終了フレームを読めるつもりの枝を除去し、通常終了と録画の実際の経路を分けて検証した。

## 共有物への提案

- 現在の変更ゲーム検出は `games/` 外の変更をすべて共通変更として扱うため、ゲーム固有の `documents/knowledge/kartrace.md` だけでも全ゲームのCIが走る。知見ファイルを同名ゲームへ対応付ける改善を提案する。作業範囲に従い共有スクリプトは変更していない。

## 手直しラウンド (見た目の特色化)

### 分かりにくさの原因と効いた表現

- 前の画面は、丸い共通パネルの中へ説明と操作一覧を均等に並べていた。選択中の対象、決定後の行き先、いま進める操作の強弱が弱く、画面下の共通操作ガイドを読まないと次の行動を判断しづらかった。また、淡い海辺の配色と手続き SVG の部品が他ゲームと近く、レース固有の計器やコース上の情報が不足していた。
- タイトルは「ドライバー選択」と「次はガレージへ進む」を左右で分け、選択カードをマゼンタと黄色で点滅させた。ガレージは壁の大きなコースポスターだけを選択可能にし、未完成の2枚には選べない理由を直接書いた。初回だけ、アクセル、ハンドル、ドリフトを実入力すると進む3段階のチュートリアルをスタート地点へ重ね、Enter / A または Escape でスキップできるようにした。各場面に必要な操作だけを置き、画面下の共通操作ガイド行は廃止した。
- レース中の速度、ギア、周回、時間、アイテムをアーケード筐体風の計器へまとめ、順位は HUD から外してコース脇の電光掲示板へ移した。桃色から橙色へ変わる空、紫の路面、原色の縁石、低ポリの山とカート、ドット絵の観客と看板を同時に見せることで、タイトル、コース選択、走行画面のどこでも80年代アーケードレースと識別できるようになった。

### CC0 ドット絵と頂点カラーの作り方

1. game-asset-search のライセンス条件を先に CC0 / Public Domain と OFL に絞り、OpenGameArt の素材ページで作者、配布ライセンス、Copyright/Attribution Notice、配布ファイルの対応を確認した。観客は Summer Otters w/ Signs、ゴール看板は 2.5D Racing Resources を採用し、取得元と加工内容を `assets/CREDITS.md` に記録した。画像自体は再加工せず、Godot の region で必要なコマだけを切り出して nearest filtering で表示した。
2. カートとコースは `SurfaceTool` / `ArrayMesh` で面を組み、頂点ごとに原色を与えた。`StandardMaterial3D.vertex_color_use_as_albedo` を有効にし、車体、道路、縁石、山、設備のテクスチャを不要にした。少ない面数と面ごとの色差が、スプライトスケーリング風の荒い奥行き表現にもなった。
3. Potta One は Google Fonts の公式配布物と OFL-1.1 本文を一緒に置いた。ガレージのネオン音とコースの観客音は既存の決定的な Python 生成器へ追加し、場面別 BGM に重ねた。再生成前後の SHA-256 一致、22050 Hz / 16 bit / mono / 4秒、ピークと RMS、Godot のインポートとロードを検査した。

当たりだったのは、看板と観客だけを低解像度テクスチャに限定し、大部分を頂点カラーにした組み合わせである。少量の CC0 素材でも輪郭の硬いローポリ背景との対比が生まれ、素材集そのままの画面にならなかった。外れだったのは、レース素材という検索語だけで最初から完成した統一素材一式を探す方法で、ライセンスや画風の条件を同時に満たす候補が少なかった。用途を「観客」「ゴール看板」の小さい役割に分ける方が早かった。

前ラウンドの手続き SVG は、外部権利の確認が不要で、差分が読め、決定的に再生成できる点では強い。一方、同じ太線、角丸、配色、部品構成を複数画面へ使うと、題材が違っても似たUIになりやすい。CC0 探索は配布ページとアーカイブ内容の照合に手間が掛かるが、作者固有のドットの癖を少量加えられる。頂点カラーは素材探索が不要で3Dの一貫性を保ちやすいが、面の組み立てと全カメラ角度の確認は SVG より手間が掛かる。スクリーンショットでテクスチャのにじみ、裏面、色属性の欠落を発見しやすく、連続フレームでは低ポリモデルの6アニメ状態を検証しやすかった。

### Godot で計器 UI と場面内案内を作る時の注意

- `SurfaceTool` は頂点を追加する前に色を設定し、生成後のマテリアルでも頂点色を albedo に使う必要がある。片方だけでは頂点カラーが画面に現れない。透明なドット絵の Sprite3D は nearest filtering、region、billboard を明示し、遠景と重なる角度を走行スクリーンショットで確認する。
- アナログ速度計は `Control._draw()` で針と目盛りを描き、速度の更新時に `queue_redraw()` する。数値だけを状態として持ち、描画ノードを毎フレーム作り直さない。順位掲示板も同様に既存ノードの文字だけを更新し、レース状態を表示側から変更しない。
- チュートリアルは説明を時間で送るのではなく、通常プレイと同じ入力イベントを満たした時だけ次へ進める。JoypadMotion は1回の傾きが複数フレーム届くため、軸が中央へ戻るまでラッチしないと車種選択が複数個動く。
- 復帰位置には路面高さだけでなく上向きの余白を足す。被弾時は速度だけでなくドリフト時間、ドリフト入力、ドリフト向きも同時に初期化する。この3点は selfcheck と実入力統合テストへ回帰検証を追加した。
