# 潮風カートの実装知見

## 設計判断

- 周回コースの距離と左右位置を状態として持ち、3D の位置・坂・カメラ・ミニマップを同じコース関数から計算する。自由な車両物理ではなく、経路を基準に操舵するアーケード方式を採用した。ハンドルは横方向の移動、カーブの外向きの力への対抗、アイテム回避と内側のショートカット進入に使う。
- 周回はスタート線との接触だけで数えず、順番にチェックポイントを通過した回数から決める。逆走や復帰による重複通過は加算しない。
- CPU の順位と速度補正、アイテム、実測ゴール時刻をレース状態に集約した。結果画面は全車のゴールを待って順位表を表示する。
- フレーム落ちによる判定の抜けを防ぐため、レースの更新を細かい時間刻みに分けて積分する。

## 表現と素材

- ミント色のカワウソ、橙色のキツネ、紫色のフクロウは別の車体形状・顔・装備を持つ。各モデルのメッシュ構成と独立したシーン、AnimationPlayer の待機・走行・ドリフト・ブースト・被弾・歓喜の6状態を作った。
- UI は同梱した日本語フォントと共通 Theme を使う。素材は独自の手続き生成 SVG・メッシュ・多音色 WAV と OFL フォントで、assets/CREDITS.md に記録する。
- 海、島、灯台、近景のヤシ、遠景の島と雲を重ね、GL Compatibility で描画する。

## 検証中に確認したこと

- sandbox 内の通常 Godot はエディタ設定や user:// の補助ディレクトリ保存に失敗する。godot-development の prepare-sandbox-godot.sh で作業ディレクトリ内に自己完結版を用意した。GUI の描画確認は許可された通常の GUI 起動として実行している。
- 起動と selfcheck の終了コードだけでなく、インポートのログ全文にも ERROR が無いことを検査する必要がある。

## 残した判断点

- 元作品の再現ではなく、海辺の小さなサーキットと独自キャラクターによるアーケードレースを採用した。
- 実機ゲームパッドの接続と Windows / Linux 実機プレイ、聴感による音楽評価は、入力イベント検証やエクスポート成功と区別して報告する。

## skill 化の候補

- コース配置を表示と周回検証で共有する3Dレースの雛形。
- 3Dモデルの全アニメーションを開始・途中・終了で撮影する一覧生成。
- 実入力デモ・音声停止・終了時リーク検査と、公開PRへ検証画像をまとめる手順。
