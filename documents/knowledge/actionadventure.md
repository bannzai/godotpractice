# actionadventure 開発知見

## 方針

issue #44 の見下ろし探索ゲーム「灯守の島」。藍・翡翠・琥珀の配色で海辺の島と古い灯台を描き、固有のキャラクターと合成音源を使う。6画面のフィールドから6部屋の遺跡へ進み、風の輪（ブーメラン）・爆弾・押せる石・鍵・床スイッチを順に使って最奥の石梟と戦う。

作業は `games/actionadventure/` と本ファイルの中に閉じる。PRは作成・更新するがマージしない。

## 実装中の判断

- 永続状態は `AdventureState`、一部屋内の戦闘と表示は `world.gd`、UIは `presentation.gd` が持つ。道具の所持・宝箱の開封・仕掛けの作動・扉の解錠は保存する。
- 保存データはバージョン・型・値域・装備と所持の整合を確認してから反映し、破損時は現在の状態を変更しない。
- 各キャラはCC0素材から作った224×280pxのPNGシートで、56pxセルの4列×5行。待機・移動・行動・被弾・消滅の実フレームを `AnimatedSprite2D` で再生する。
- 音源は旋律・和音・撥弦・低音・打楽器を重ねて独自生成し、場面ごとにテンポと主楽器を変えた。BGMのループはGodot側で設定する。
- 撮影用の部屋・戦闘前提と、通常ルールの入力検証を分ける。撮影前提を設定した画像を通常プレイ完走の証明として扱わない。

## 検証で得た知見

- sandbox内で `--log-file` を絶対パスにしても、初回の `user://` ディレクトリ作成自体は権限不足で失敗する。Godotは import をexit 0で終える場合があるため、ログ全文のエラー検査が必要。今回の通常Godotによる権限付き検証では解消した。
- 画像名に `warning` を含めるとログ全文の警告検査が誤反応する。爆弾の導火線を撮った画像は `bomb-fuse` とし、警告を広く除外する回避はしない。
- `TextureRect` は画像の最小サイズが残らないよう、`expand_mode` と伸縮設定を先に指定し、最後に表示サイズを設定する。HUDの96px画像が32px指定からはみ出す問題を実スクリーンショットで発見した。

## skill化・共有物への提案

- godot-development: 見下ろしゲームの扇状攻撃・道具による通路解除・セーブ破損検証を再利用できる実入力テスト例にする。
- game-asset-search: シート生成の決定性・各動作の連続フレーム・音声の飽和とループ境界をまとめて検査する入口を追加する。

## 遊びの設計と検証

- 風の輪の部屋は、道具を対岸のスイッチへ当てると中央の橋だけが通行可能になる。橋以外の穴は残す。移動不能の検査を内部配列の空判定にせず、実際のキー入力で通過できる位置・できない位置を検査する。
- 爆弾を壁の前で使い切っても詰まらないよう、入手した部屋の宝箱を再調査すると3個まで補充できる。店では琥珀貨で3個ずつ購入できる。
- 石を押す仕掛けは一度成立すると保存し、鍵を取って扉を開いた後も解錠状態を維持する。主人公の体力が0になったフレームは、拾得と部屋の移動を打ち切り、死亡演出の後に結果画面へ進む。
- 入力マップの数値は思い込みで決めず、実エンジンの Key / JoyButton 定数と照合した。十字キーと左右矢印の誤設定は実入力テストが検出した。パッドは X=剣、Y=道具、A=調査・GUI決定、Start=持ち物。
- 会話の探索対象に草が混ざると、距離の近い草で探索を終了し、後ろのNPCに話せなくなる。対象種を先に絞ってから距離を判定する。
- 買い物の在庫上限と保存データの値域を揃える。代金を引く前に爆弾・薬の99個上限を確認し、コイン取得も9999で止める。満杯の購入と、上限状態での保存を回帰検査に入れた。
- `scripts/dev/playthrough.gd` はタイトル決定から通常キー入力だけで全12室を攻略する。位置・体力・装備・フラグを書き換えず、4304物理フレーム（約71.7秒のゲーム時間）で二つのハート宝箱・全仕掛け・ボス撃破・宝の取得まで到達した。入力の保持と解放は対にし、120秒分の期限を設ける。
- 26秒の `demo.gd` は見どころを収めるモンタージュ。部屋・装備・ボス体力は録画用に用意し、操作を実入力で発生させる。これは通常ルールのクリア証明と区別してPRに明記する。

## 表示と音声

- タイトル用主人公はPuny Charactersの24px範囲を地域パレットへ再着色し、nearest-neighborで拡大した448pxの独立PNGにした。
- キャラ、景観、UIを含む実画面を確認し、HUDアイコンのはみ出し、ボスの体力バーと案内文の重なり、古いHUDまで流れる画面遷移を修正した。遷移はプレイ領域だけを切り出して滑らせる。
- `CanvasModulate` で遺跡の環境光を落とし、主人公の `PointLight2D` で近くを照らす。HUDは独立した `CanvasLayer` に置いて暗くしない。
- 部屋変更時に演出ノードを置き換え、前の部屋の獲得ポップやパーティクルを残さない。ノードに束ねることでTweenも同時に終了する。
- 音声の通常終了は停止・stream参照解放・ミキサー待ち、Movie Makerは終了12フレーム前の停止を使う。CoreAudioで実再生を確認し、F11の全画面往復と通常終了も検証した。
- 全素材の出典・生成条件とフォントのOFL全文を同梱し、`check-credits.sh` を通した。生成物の再生成SHA256一致と音声振幅を素材担当が検査した。

## 残した判断点

新たに人間の選択を要する仕様分岐はない。家・樹木・遺跡の装飾は景観で、道具の仕掛け・岩・押石・穴に当たり判定を持たせた。前ラウンドの手続きSVGは廃止し、ShadeのCC0素材を出典・加工記録付きで採用した。音は引き続き外部録音・外部旋律を使わない独自生成物である。

物理ゲームパッド実機、Windows/Linux実機での起動、人の耳による音質評価と初見難度は未検証。入力イベントによるパッド検査、各OSのエクスポート成功、CoreAudioの実出力と区別する。

## 共有物への追加提案

- CIは `check` / `selfcheck` と描画・exportを個別実行しているため、各ゲームが追加した `integration` / `playthrough` は現在ローカルの `make test` で実行する。共有workflowの検証入口を `make test` に揃える提案を司令塔へ残す。
- ルートの委譲一覧に `movie-play` がないため、このゲームの操作録画は `make -C games/actionadventure movie-play` を使う。共有Makefileへの委譲追加は司令塔の作業とする。

## 最終確認で得た知見

- Movie Makerでシーンを先に `queue_free()` して描画を待つと、動画の末尾が灰色になる。終了12フレーム前に音声を止め、描画ノードは `SceneTree.quit()` の終了処理へ任せると、タイトルを保った末尾とリークなしを両立できた。
- 初回UI構築のフェードは、背後のフィールドが起動直後の録画へ透ける原因になる。初回だけ完成状態で表示し、以降の画面切替はフェードする。
- 点滅中の撮影判定は物理フレームの前では早すぎる。`RenderingServer.frame_post_draw` 後に可視状態を調べ、その描画済みフレームを保存する。
- webtunnel の実操作は run `34047005780`（ゲーム本体 `a097935`）で、タイトル→開始→東へ画面移動→敵との接触によるゲームオーバー→入口から再開→持ち物メニュー→タイトルへの復帰を確認し、セッションを停止した。公開ゲームの状態は書き換えず、Chromiumへ実キーとマウス入力を送った。その後の変更は初回タイトルの表示と開発用撮影・録画の終了処理であり、ローカルとCIの最新成果物で確認する。
- CIのXvfb/llvmpipeではV-Sync切替非対応の警告が出る。既存のCI規定が許容するドライバー警告で、ゲームのERROR・終了時リークは出ていない。ローカルの最終ログはこの警告もなく成功した。
- 画像添付は既存の `pr-attach-screenshots` skill が使えた。`puts upload` の公開URLを取得しSHA-256を照合してからPR本文を更新するため、添付画像の取り違え・壊れたリンクをまとめて検出できる。

## 手直しラウンド（見た目の特色化）

### 分かりにくさと似た見た目の原因

- 前ラウンドは「上にHUD、下に常設の操作ガイド、多層背景、Themeで統一」という共通構成を使ったため、題材が違っても画面の輪郭が他ゲームと同じになった。独自生成SVGも同じ生成方法・藍色中心の滑らかな図形へ寄り、見下ろし探索の目印より装飾が先に見えていた。
- 目的は上部の文章、操作は下部の一覧、対象物はプレイ領域という3か所に分散していた。初見では「どれへ近づくか」「何のキーを押すか」「今はなぜ開かないか」を対応づけにくかった。
- 地域の床・木・建物が同系色かつ同じ細かさで、村、森、湿地、遺跡の切り替わりを地形から読み取りにくかった。地図がなく、12画面の現在地と次の目的も頭の中で保持する必要があった。

効いたのは、目的を上部石版へ固定し、近づいた対象のすぐ上へ琥珀色の点滅輪・操作・結果をまとめる表現だった。選べない対象は輪と石版を赤へ変え、「小さな鍵が必要」「石を床の灯へ押す」のように不足と解決方法を同時に示す。常設の下部操作行は廃止し、最初の3枚だけ長老が移動、剣・道具、羊皮紙の地図を順に教える。案内はいつでも省ける。

### CC0素材を地域別パレットへ変える手順

1. game-asset-searchの検索スクリプトでOpenGameArtを調べ、検索結果のプレビュー画像ではなく作品ページの正式な配布ファイル欄とライセンスを照合した。
2. 作者と画風を揃えるため、Shadeの `16x16 Puny World Tileset`、`16x16 Puny Dungeon Tileset`、`Puny Characters` の3点を選んだ。すべてCC0-1.0で、リポジトリへの元ファイル同梱と改変が可能である。
3. 元ファイルを `assets/source/` に保存し、URL、SHA-256、画像寸法、ZIP内の採用ファイル、切り出し範囲、用途を `assets/palettes.json` に記録した。キャラクターZIPは展開せず、生成時に対象ファイルだけを直接読む。
4. `scripts/dev/generate_pixel_assets.py` で16pxまたは32pxの範囲を切り出し、海岸、森、遺跡、危険物、タイトルの各8色へ写像した。タイルは56px、キャラクターは56pxセル、景観は112px、背景は1280×720pxへnearest-neighborで拡大・合成する。
5. 35枚すべてについて、期待寸法、透明でない画素の存在、パレット外のRGB色がないことを生成直後に検査する。地域を横断する地形シートだけは4パレットの合計32色を上限とする。2回目の生成でPNG35枚とJSONのSHA-256が変わらないことも確認する。
6. `assets/CREDITS.md` に元素材の作者・URL・CC0・加工内容を、フォントにはStickの公式OFL全文を記録する。selfcheckでもPNGの寸法、4〜8色の各パレット、CC0素材3点、SVGと旧フォントがないことを検査する。

当たりだった点は、同じ作者の屋外・遺跡・人物を揃えたことで、切り出し元が違っても輪郭と陰影が自然につながったこと、Puny Charactersに複数の職業・敵・動作があり、既存の8キャラ×5動作×4フレームを保てたことである。元画像、切り出し範囲、色写像をデータとして残す方式は、目視だけでなく再生成と差分検査がしやすい。

外れだった点は、検索で得た別作者のOpen TilesetとRPG素材がPunyシリーズの輪郭や密度と合わず、混ぜるほど地域ではなく素材由来の差に見えたことだった。候補は採用せず削除した。また宝箱の最初の切り出し座標は空白で、ファイル生成の成功だけでは欠落を検出できなかった。透明でない画素の検査を必須にして座標を直した。16pxを56pxへ3.5倍する非整数倍率は画素幅が均一にならないため、実寸スクリーンショットで輪郭を確認する必要がある。

前ラウンドの手続きSVGは、外部素材の探索・権利確認が不要で、コードだけから決定的に作れる点は速かった。一方で、同じ作図語彙と配色を繰り返しやすく、ゲームボーイカラー風の粗い画素へ向かず、生成コードが画像内容より大きくなった。CC0素材の再着色は、正式配布ファイルの識別、ライセンス、切り出し座標の調査に手間がかかる代わりに、元から描かれた情報量と統一した画風を保ちつつ、このゲーム専用の色と大きさへ機械的に変えられた。

### 石版UIとGodotでのハマりどころ

- `Presentation` はモード変更時にボタンを作り直し、既定ボタンが `grab_focus.call_deferred()` を行う。統合テストが別ボタンへ直ちにフォーカスすると遅延呼び出しに上書きされた。再構築後のフレームを待ってから対象ボタンへフォーカスし、実際のAボタン・Enterを送る必要がある。
- 地図の2行×6地点を描く二重ループでは、マーカー生成のインデントが一段外れると内側の `room_index` と `center` がスコープ外になる。gdlintだけでなくGodotのimportで全依存スクリプトをコンパイルして検出する。
- selfcheckでPNGを `Image.load()` すると、エクスポート後に使えない読み方という警告が35枚分出る。インポート済みの `Texture2D` として読み、幅・高さを照合すれば、配布物と同じ経路を警告なしで検査できる。
- 画面遷移用の旧画面キャプチャより先に遷移先のActorを生成すると、旧画面の上へ新しい敵が見える。遷移中はActor群を隠し、完了時に表示する回帰検査を置いた。
- 風の輪が分裂敵を倒すと、同じ投擲中に追加された小敵へ次フレームで再命中した。投擲開始時の対象配列を固定すると、追加された小敵を同じ攻撃で巻き込まず、配列変更にも影響されない。

### skill化の候補

- game-asset-search: 正式配布ファイルとプレビューの区別に加え、スプライトシートの切り出し一覧、透明でない画素、寸法、パレット外色、再生成SHA-256をまとめて検査する補助スクリプトを追加する。
- game-asset-search: 複数素材を混ぜる前に、同一作者・同一シリーズ・セル寸法・動作数を表にして比較し、採用・不採用と理由をCREDITS用データへ残す流れを追加する。
- godot-development: `Texture2D`としての画像寸法検査、UI再構築後のフォーカス安定化、非整数nearest-neighbor拡大を実画面で検査する例を追加する。

## 2026-09-08 新規制作「残り火の森」

この節より前は過去版の記録。今回の開始時には `games/actionadventure/` が存在せず、他ゲームや過去版の実装を参照せずに新規制作した。現在の遊び方・検証コマンドは `games/actionadventure/README.md` に置く。

### 実測した知見

- Godot 4.7 の `CanvasItem` には `draw_ellipse` が存在する。同名の独自ヘルパーを別シグネチャで定義すると Parse Error になる。独自の影描画関数を `draw_shadow` に変更して解消した。editor import はスクリプトエラーがあっても exit 0 だったため、終了コードに加えてログ全文と実シーン生成を確認する必要がある。
- 部屋の座標上の隣接だけで接続を判定すると、祠から灯台へ直接移動でき、燭台の封印を迂回できた。接続そのものを `Journey.CONNECTIONS` に置き、移動と地図が同じ接続を参照するようにした。selfcheck には封印迂回ができない条件も含めた。
- 高速な headless 通しプレイでは、論理時間に追いつかない音声再生が終了時にリソースとして残った。headless では音声の再生予約を行わず、描画付きの検証では通常どおり再生することで、最終の両ログから warning/error がなくなった。撮影スクリプトはシーンを queue_free した後、数フレーム進めて解放を完了してから終了する。
- 描画付きの入力検証はウィンドウのフォーカスが安定する前に移動キーを送ると、移動量が足りない回があった。ウィンドウのフォーカスを取得し、開始直後のフレームを進めてから入力することで最終検証が成功した。
- 画像は 16px セルの横並びアトラスを Godot の Image で生成し、2倍の整数倍率で描く。外部画像ライブラリや画像生成サービスを使わず、音声も同じ生成スクリプトの波形合成で用意できた。制作方法と権利の扱いは assets/CREDITS.md に記録した。

### 今回の検証結果

- Godot 4.7 の import、67項目の境界条件、進行を改変しない通しクリアを `make -C games/actionadventure test` で実行し、exit 0、warning/error なし。
- 通しクリアは新規開始から歩行・剣・灯火・調べる操作だけを実行し、鍵取得、祠の解錠、押し石、灯火取得、二本の点灯、守護者討伐、エンディングへ到達。敵の体力や進行フラグを直接書き換えるケース別検証とは別に用意した。
- 描画付きでキー入力と9画面の撮影を実行し、exit 0、warning/error なし。森の宝箱案内と出口案内の重なりを目視で発見し、位置を修正した。最終の代表画面で日本語の欠けと重なりがないことを確認した。
- Windows・Linux の実行、配布用エクスポート、音声の聴感評価は未検証。ローカル描画ログでは CoreAudio の初期化と BGM・SE の読み込みを確認した。
