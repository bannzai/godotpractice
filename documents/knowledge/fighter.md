# fighter の実装知見

## 実装と判断

- 独自作品「燈環闘技」。夕暮れの工業都市で青緑・橙の装甲闘士が対戦する。立ち・しゃがみ・空中に弱強パンチ・キックを用意した。
- 画面をまたぐ試合状態を autoload、技性能を純粋関数、実際の接触を Area2D に分けた。99秒・2本先取。同体力の時間切れと相打ちは両者の本数を増やさず再ラウンドとする。
- ガードは後ろ入力。下段はしゃがみ、空中攻撃は立ちで防ぎ、空中ガードは設けない。被弾硬直とガード硬直を区別し、連続ガードを可能にした。
- コマンド履歴は向きを基準に下・斜め下前・前を記録し、期限内のパンチ入力で1回消費する。キーボードとパッドは同じInputMapを使う。

## Godot で実測した注意点

- `FontVariation.variation_opentype` の `{"wght": 600}` では同梱可変フォントが細いままだった。`TextServerManager.get_primary_interface().name_to_tag("wght")` の整数タグで指定すると、期待した太さになった。公式の整数タグ例に合わせ、撮影し直して確認した。
  https://docs.godotengine.org/en/stable/classes/class_fontvariation.html
- 高負荷時は初回フレームのdeltaが長くなり、0.12秒のTimerでも起動チェックの終了前にBGMが再生された。`Engine.get_process_frames() >= 3` を開始条件にし、初期描画後に再生するよう変更した。
- `AudioStreamPlayer.stop()` を呼んでも音声ミキサーの解放周期より早く撮影プロセスを終了すると、WAV再生リソースが終了時に残ることがあった。`_exit_tree` で再生を止め、撮影側でシーンを解放して0.2秒待つと警告なしになった。
- BGMはループ方式だけを実行時に変更しても終端が0のまま残り、即座に停止した。WAVのimport設定でForwardループと全サンプル範囲を指定し、録画の音量検査を追加した。修正後の録画は平均-37.1dB・最大-19.6dB。Movie Makerでは終了直前の4フレームで音声を停止し、ミキサーが解放した後で終了する。
- 型付き `Array[int]` を、動的なNode参照経由で通常の配列に置換すると実行時エラーになる。撮影の状態作りでは `wins.assign(...)` を使う。
- `Area2D.get_overlapping_areas()` の領域更新を待つため、実接触検証は物理フレームを進める。発生時間中に領域が反映され、アクティブ中に一度だけ命中することをHPとsignal数で検証した。
  https://docs.godotengine.org/en/stable/classes/class_area2d.html
- sandbox内ではGodotのuserログ・エディタキャッシュ作成が拒否され、起動が異常終了することがあった。許可された通常起動で検証し、exit 0だけでなくログ全文のWARNING／ERROR不在を確認する。

## 入力経路を通した検証で見つかった問題

- Startに「停止」と「決定」を割り当てると、1イベント中に停止直後の再開も処理される。停止分岐でイベント処理を終えるよう修正した。
- パッド南ボタンで一時停止を解除すると、同じ押下が弱キックとして戦闘に流れた。再開の決定ボタンを離すまで攻撃を抑止した。コマンド必殺技の実入力検証で発見できた。
- 画面遷移を直接呼ぶだけではこれらを発見できない。`Input.parse_input_event` にキーボード・パッドボタン・左スティックを渡し、CPUとの実接触、KO・時間切れ、再戦・タイトル復帰まで検証する方式が有効だった。

## 素材準備

- SVGは既存作品の素材を使わず幾何図形から独自制作。音声も固定乱数・正弦波による独自の合成で、生成スクリプトを同梱した。再生成したWAVのSHA256一致、非無音・クリップなしを確認した。
- OFLのNoto Sans JPを同梱し、OFL全文とCREDITSを全export presetのinclude_filterに加えた。OSの日本語フォントへの依存を避けた。
- game-asset-search の `check-credits.sh` が成功。生成物を自動的にCC0とはせず、制作方法と利用規約の帰属を記録した。

## 第 2 ラウンド (品質向上)

### 表現の方針

- 対戦ルールと技性能は第 1 ラウンドを維持する。蒼は白いスカーフと軽装、燈は大きな籠手と肩鎧で、輪郭と動きを分ける。キャラごとに独立したスプライトシートを持つ。
- 黄昏の工業都市を多層背景にし、青緑・琥珀・濃紺の配色と同梱フォントを画面全体で揃える。打撃、ガード、燈波、決着を粒子と画面演出で区別する。
- このゲームにボス・NPC・アイテムはないため、新規のゲーム要素は追加しない。最終ラウンドを音楽の盛り上がる場面として扱う。
- 品質向上前の23枚のスクリーンショットと通常起動を確認した。通常起動はsandbox内でAbort trap: 6となり、許可されたmacOSの起動で `fighter run OK` とexit 0を確認できた。

### 検証と知見

- 蒼と燈を各22動作×8フレームの独立SVGシートとSpriteFramesにした。軽装・スカーフと重装・籠手で輪郭を分け、ポートレートも別の構図で生成する。固定入力から同じ素材を再生成できるので、余白や関節位置の修正を全フレームへ反映しやすい。一方、手続き生成だけでは動きが規則的になりやすく、本番では原画・中割りの美術調整が必要になる。
- AnimatedSprite2Dを独立再生するとヒットストップ中も見た目だけ進む。戦闘側の発生・持続・硬直時間からフレームを選ぶことで既存の技性能を保持した。被弾は連続命中ごとに開始位置を更新し、KOだけは入力停止後も倒れる時間を進める。
- KOの回転で絵がセルの端を越え、隣の動作がジャンプ中に混ざる問題を連続フレームで発見した。セル内部にKO姿勢を収め、全352セルの透明な外周をselfcheckで検査する。空中キャラの影はスプライトから外し、床の高さで別描画する。
- GL CompatibilityでもCPUParticles2D、短命なTweenノード、CanvasItemのフラッシュ・周辺減光で打撃を表現できた。KO時に戦闘側の時間が停止すると被弾フラッシュも残るので、ラウンド終了時に解除する。HPの数値と減少跡は補間し、KO時は0へ揃える。
- 舞台を空・街・闘技場・霞の4枚に分け、視点に応じた移動量を変える。日本語ロゴは同梱フォントをfontToolsで輪郭化し、OSのSVGフォント描画へ依存させない。テーマはThemeリソースへ集約する。
- タイトル・通常対戦・最終ラウンド・結果の4曲と5種のSEを、倍音・FM・ノイズ・エンベロープを使って生成した。音色構成とテンポを場面ごとに変え、再生成一致・非無音・クリップなしを検査した。実際の聴感の好みまでは数値検査では判断できない。
- `--quit-after` は通常のウィンドウ終了通知を通らず、`OS.get_cmdline_args()` にも残らない。通常終了は音声停止後のTimerを待ち、共通の `_exit_tree` ではstream参照を外してミキサースレッドへ250msを与える。固定fpsのフレーム待ちは実時間の解放待ちにならない点に注意する。Webでは終了時のブロッキング待機を行わない。
- 撮影した一時PNGがGodotに再インポートされていた。import targetで `tmp/.gdignore` を用意し、開発用の撮影成果物をリソース探索・エクスポートから除外した。
- `make test GAMES=fighter` は714条件でexit 0。`make screenshot GAMES=fighter` は56枚でexit 0。全22動作×2人の開始・途中・終了、全通常技、打撃・ガード・KOの途中、キャラ別の燈波、ホバー・押下・画面遷移を目視し、セルの混入・欠け・文字の重なりがないことを確認した。
- webtunnelのSwiftShaderでもタイトル→選択→CPUとの2ラウンド→結果まで実入力で進められた。caller workflowの配信ポートは8000。macOSとLinuxでは代替フォントで表示できた再戦ボタンの「↵」がWebでは欠字になり、文言から外した。デスクトップの撮影だけでは見つからない差だった。
- PUTSの既定Keychain読み取りはこの環境ではOSStatus -25291となった。新しいキーは発行せず、既存のGitHub画像用R2認証をPUTSの環境変数へ渡すことで `puts upload` を実行できた。キーの値はログ・ファイルへ残さない。
- 欠字修正を含むコードで、test・screenshot・movie・build-all・build-webと `make -C games/fighter run` の自動起動確認がすべてexit 0。PR #25は未マージなので指示書のrun代替を使用した。通常終了と `--quit-after 90` のshutdown-checkもexit 0で、各ログ全文にWARNING・ERROR・終了時リークはなかった。
- movie-playは29秒・30fps・870フレーム。移動・ジャンプ・通常技・被弾・ガード・コマンド必殺技・結果・タイトル復帰をゲーム上の状態で確認した。15秒と22.5秒以降にCPUの体力が上回った時だけ、録画専用スクリプトが残り時間を短縮する。通常ゲームは99秒のまま。2秒間隔の一覧、ジャンプと必殺技の0.1秒間隔、末尾画像で動作と遷移完了を目視した。音量は平均−26.0dB・最大−6.7dB、5秒の起動動画は平均−25.6dB・最大−12.9dB。
- Linux CIでもテスト・全エクスポート・撮影・動画が成功した。CIの実行URL、artifactの目視結果、PUTSで公開した各画面・連続フレーム・録画・Web操作の証拠はPRの「検証」に集約する。

### 本番に向けた道具の改善候補

- godot-developmentへ、セル境界の透明ピクセル検査、判定時間とAnimatedSprite2Dの同期、通常終了と `--quit-after` の音声解放検証を追加すると再利用できる。
- 2秒間隔の録画一覧だけでは短い攻撃の崩れを見逃す。ジャンプ・必殺技の区間は0.1秒間隔でも抽出する。美術の改善には、連続フレームの差分とセル余白を同時に表示するビューアがあるとよい。

## 手直しラウンド (見た目の特色化)

### 分かりにくさの原因と効いた表現

- 変更前はタイトル・キャラ選択・対戦が同じ背景を共有し、全画面の下端に同じ形式の操作ガイドを置いていた。情報は存在しても、その場で選べる対象、決定後に起きること、必殺技の入力が離れており、画面の役割を輪郭と色だけで判別しにくかった。
- タイトルでは「挑戦者を選ぶ」、キャラ選択では2人の性能とコマンド表、世界地図では会場プレビューと「この会場でCPUと対戦」、結果では再戦とタイトル復帰を、操作対象の近くに置いた。選択中はシアンまたはマゼンタの二重枠に切り替え、決定先を文で示す。この配置にして、画面下の共通操作ガイド行を削除できた。
- 初戦だけ、移動、通常技、必殺技の3段階を対戦画面内で順に試す。チュートリアル中はCPUとタイマーを止め、完了・スキップ後だけ試合を始めるため、「読む間に攻撃される」状態にならない。再戦では表示しない。
- 背景の一部を差し替えるだけでは他ゲームと見分けにくい。大きなドット絵、観客席、スキャンライン、上部の体力ゲージと中央タイマー、左下の大きなコンボ数、画面中央を横切るK.O.、飛行機が移動する世界地図を一組にしたことが識別に効いた。

### CC0 素材を集めて加工する手順と所感

1. `game-asset-search` の OpenGameArt 検索で、横向きの人物、パンチ・キック・被弾、街のタイルを別々に探した。作品ページの作者、CC0表示、Public Domain notice、配布ZIPの直接URLを確認してから取得した。
2. 同じ Chasersgaming の `Brawler Asset Character 'Vigilante' SMS`、`RPG Asset Character 'Soldier' SMS`、`Brawler Asset Tile Set 'Market Street' SMS` を選んだ。同じ解像感と輪郭規則で揃い、public リポジトリへ原素材を同梱できるCC0だったことが当たりだった。Dela Gothic One はGoogle Fontsの配布元とOFL-1.1全文を確認した。
3. 16px級の原画は nearest-neighbor で6〜9倍にし、蒼電は青緑、紅蓮は橙・深紅へ色替えした。既存フレームの順序、位置ずらし、回転、縦つぶしを組み合わせ、既存の22動作×8フレームのAPIと攻撃時間を保った。
4. Market Streetは正方形の街素材で、そのままでは横長の格闘ステージにならない。左右反転、3色の色調補正、街頭小物、独自の観客・床・照明・看板を合成し、東京・ソウル・リオの会場へ展開した。生成済みPNGが同一なら書き直さないスクリプトにし、元素材から一括で再生成できるようにした。
5. 全素材のファイル名、取得元URL、作者、ライセンス、加工内容を `assets/CREDITS.md` に記録し、selfcheckで `assets/` 内の記録漏れを検査した。OFLの著作権表示と全文はフォントと同じディレクトリに保持し、export presetで配布物へ含める。

最初に見つけた候補には、GIFだけで提供されるもの、正面・斜め向き中心で格闘の横向き動作へ流用しにくいもの、2人分を並べると画素密度が揃わないものがあった。ライセンスが利用可能でも、必要動作・向き・解像感を最初に絞らない検索は外れが多い。今回は同じ作者の3素材を揃えたことで加工量を抑えられた一方、足りないしゃがみ・空中・ガード・KOは組み合わせで補う必要があり、素材探索よりフレーム割当と全352セルの検査に手間がかかった。

前ラウンドの手続きSVGは、座標を直接制御でき、固定入力から完全に再生成しやすく、セル寸法も揃えやすかった。しかし輪郭と陰影が幾何学的になり、他ゲームも同じ生成方法を使うと特色が薄れる。CC0の手描きドット絵は少ない色でも人物の体格・姿勢・街の小物に作者の癖があり、ぱっと見の情報量が増える。一方で、素材ごとの向き・フレーム数の差を吸収する加工、出典確認、原素材と生成物の対応記録が必要になる。再生成しやすさは、原素材を保存して決定的な加工スクリプトを同梱することで補えた。

### Godot でアーケード風 UI とドット絵を扱う注意点

- 大きなAtlasTextureへ小さなドット絵を並べる時は、`filter_clip` と `CanvasItem.TEXTURE_FILTER_NEAREST` だけでは不十分だった。回転・縦つぶし・影がセル端へ触れると隣の画像が混ざる可能性があるため、生成時に使用領域を2px内側へ自動移動し、全フレームの透明外周をselfcheckで検査する。
- 決定ボタンと攻撃ボタンが同じゲームパッド入力を共有する。チュートリアルのスキップや一時停止の再開に使った押下を、ボタンが離されるまで攻撃側で抑止しないと、試合開始直後に弱キックが出る。
- チュートリアル中にCPUだけ止めても、タイマーや飛び道具が進むと学習画面として不安定になる。戦闘更新の入口でCPU、タイマー、投射物をまとめて止め、プレイヤーの対象入力だけを受け取る。
- Dela Gothic Oneは日本語と英数字を同じ太い形で描けるため、アーケード筐体の見出しに向いた。小さい補足文は字間が詰まるので、本文サイズを抑えすぎず、長文を避けて画面内の対象近くへ分割する。
- 観客環境音はWAVのimport設定をForward loopにしないと一度で止まる。BGMと別のAudioStreamPlayerにして、世界地図と対戦だけで低音量再生し、タイトルと結果では停止する。停止処理では両方のstream参照を外し、終了時リーク検査を維持する。
- webtunnel上の`agent-browser press`は押下から解放までが同一描画フレームへ収まることがある。移動・通常技は`keydown`と`keyup`の間を複数フレーム空け、0.65秒以内の波動拳コマンドはcanvasへ80ミリ秒間隔で一連のKeyboardEventを送ると、実装と同じ入力履歴を検証できた。
- fighter、shooter、platformer、kartraceの実スクリーンショットを同寸法で並べると、fighterは高彩度のシアンとマゼンタ、黒い走査線、対面する大きな人物、体力ゲージ、世界地図で判別できた。単独画面だけでなく、近い操作ジャンルの画面と並べると特色の有無を判断しやすい。

### skill 化の候補

- `game-asset-search` に、OpenGameArtの作品ページにあるCC0表示・Public Domain notice・作者・配布ZIP URLを1つのmanifestへ保存し、取得ファイルとCREDITSの対応漏れを検査する手順を追加する。
- `game-asset-search` に、検索前に必要な向き・最低動作・画素密度・1作品内で揃える範囲を指定し、GIF・スプライトシートを連続フレームの一覧へ変換して候補比較する補助を追加する。
- `godot-development` に、PNG AtlasTextureの全セルについて透明外周を検査するselfcheck例と、メニュー決定・チュートリアルスキップ・攻撃が同じ入力を共有する時の「離すまで抑止」検証を追加する。
