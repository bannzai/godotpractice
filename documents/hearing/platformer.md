# platformer 開発ヒアリング

対象は issue #3 の横スクロールアクション「そらいろ便」。開発と追加指示への対応を振り返った記録。実装・知見の PR は https://github.com/bannzai/godotpractice/pull/19 。

## 1. 開発の進め方

1. 作業指示書、AGENTS.md、PROJECT.md、issue #3、既存の雛形と検証ターゲットを読み、変更範囲と完了条件を確認した。
2. 素材準備をサブエージェントへ委譲し、並行して進行状態の autoload、主人公、敵、アイテムブロック、TileMapLayer の2ステージを作った。別のサブエージェントには状態ロジックの selfcheck 追加と読み取りレビューを依頼した。
3. タイトル、HUD、一時停止、死亡・ステージクリア・最終結果、再開操作を組み込んだ。最初から独自の「配達人・草原・結晶洞窟」という題材にした。
4. lint、起動、状態ロジックの検証を通し、実画像で見つけた雲の白い矩形、細すぎる文字、スクロール後に消える背景を直した。地面の全段に草が繰り返される点は内部用タイルの追加で改善した。
5. 実入力と物理フレームを動かす playcheck を追加した。ブロックへの衝突、踏みつけ、巨大化、被弾、残機切れと再開を確認し、最後に両ステージを入力だけで走破した。
6. 撮影をタイトルだけから11画面へ広げ、録画、デスクトップ3種とWebのエクスポート、CIを確認した。CI artifactの画像・動画も目視し、PRをready for reviewにした。
7. 追加指示で、putsによる画像公開とPR本文への埋め込み、通常のmake runによる起動確認を行った。

詰まった点は、ゲームの不具合と検証コードの問題を分けて扱った。例えば敵が段差の中に生成される不具合は地形から足元の高さを求めて修正した。一方、結合テストの前のケースで敵が移動していた問題はケースごとの再初期化で解消し、コイン取得も起こる踏みつけテストでは得点が厳密に200とは限らない点を直した。地下の走破テストはジャンプの保持時間を調整した。検証を通すための無敵付与や、走破途中の座標移動は使っていない。

反省点は、draft PRの作成が最初の実装・描画確認後になったことと、通常起動の確認が追加指示まで不足していたこと。READMEには一度、ルートに存在しないmake runの案内を書いてしまい、実際のMakefileを確認してゲーム側のコマンドへ訂正した。

## 3. 欲しかったが無かったツール・skill・スクリプト

- **通常起動の検証スクリプト**: make runの実プロセスを特定し、タイトルの画像を取得し、撮影用プロセスだけを停止するところまで欲しい。複数ゲームが同時起動しているため、Godotという名前だけで停止対象を選べない。今回はウィンドウID・PID・固有ログパスを個別に調べた。
- **Godotの入力・物理検証の雛形**: キー／パッドイベント、フレーム待機、ケース初期化、終了コードまで共通化されていれば、playcheck作成の手間が減った。ゲーム固有の走破判断は別途必要。
- **PR画像更新スクリプト**: 撮影、動画末尾の抽出、puts upload、公開画像の確認、本文の指定範囲だけの差し替えを一括化したい。今回はMarkdown出力を保存してPythonで本文へ組み込んだ。
- **アニメーション検証**: 同じ操作の開始・途中・終了を連続撮影する仕組みが欲しい。単一の途中画像では、時間方向の滑らかさや遷移の終了を判定しきれない。
- **音の評価経路**: ファイル形式・音量の検査はできたが、BGMループの聴感やSEの聞き分けを評価できなかった。
- **既存skillの環境対応**: privateリポジトリからの認証付き取得、sandbox内ログ出力、可変フォント、音声停止をgodot-developmentへ追記すると再利用できる。

共有CIはゲーム別の知見ファイル変更でも全9ゲームを検証した。知見の変更を該当ゲームへ対応付ける改善も有効だが、共有物の変更は行わず提案として残した。

## 4. 素材の準備方法と使い勝手

- **画像**: CodexがSVGコードを作り、scripts/dev/generate_assets.pyから生成した。主人公・敵・コイン・強化・地面・ブロック・背景装飾など、最終的に14 SVGを用意。寸法と色を揃えやすく、地面内部用2枚も追加しやすかった。専用画像生成サービスへの待ち時間は不要だった。一方、小さい画像をタイトルで拡大するとぼやけたため、その表示にはnearestフィルタを指定した。素材担当がGodotで一覧画像を作り、親側もゲーム内の見た目を確認した。
- **BGM・SE**: Pythonのmath/wave等で正弦波からPCMを合成した。草原・地下のBGM2曲と、ジャンプ・踏みつけ・コイン・強化・死亡・クリアのSE6種。22,050 Hz、mono、16 bit。既存曲・録音サンプルは使っていない。少ない依存で再生成できる利点があるが、聴取評価をしていないので音楽としての品質は断定できない。
- **フォント**: Google FontsのNoto Sans JPを取得し、OFL全文と著作権表示を同梱した。日本語表示をOSの代替フォントへ依存させずに済んだ。ただし可変ウェイトの初期値が細く、Godot側で指定を直す必要があった。
- **再現性・ライセンス**: 素材担当が再生成時のハッシュ一致を確認。CREDITS.mdに素材・作者・出典・生成手段・条件を記録し、check-credits.shとselfcheckで記録漏れを検査した。独自生成物を自動的にCC0とは表記していない。OFL.txtとCREDITS.mdはexport presetのinclude_filterへ明示し、出力PCKの中にも存在することを確認した。

フリー画像・フリー音源サイトからの素材取得はしていないので、その検索精度や取得手間を今回の実測として比較することはできない。

## 5. 動作確認の方法と限界

| 方法 | 効いた点・不足した点 |
| --- | --- |
| headless起動・selfcheck | シーン、状態遷移、ダメージ、無敵、時間切れ、入力割当、クレジットの検査に有効。見た目は分からない |
| headlessのplaycheck | 加減速、可変ジャンプ、実衝突、敵・アイテム、再開、2ステージ走破を検証。キーとパッドの合成イベントでメニュー操作も検証。物理パッド実機の検証ではない |
| screenshot.gd | タイトル・草原・洞窟・変身・踏みつけ・ポーズ・ステージクリア・最終クリア・ゲームオーバー・全画面・縮小の11画面。背景やフォントの不良はこれで発見した |
| movie | 起動からタイトルまで5秒録画。0.5秒間隔の10フレームと末尾を目視。連続動画の全フレームを見たわけではない。音量解析で音声の存在を確認したが聴取はしていない |
| CI artifact | LinuxのXvfb＋llvmpipeで生成された11画像・mp4も取得して目視。macOSでだけ表示できるフォントや描画への依存を検査するのに有効 |
| 通常make run | エディタなしのウィンドウと起動ログを確認。同じrunターゲットにPNG出力オプションを加えてタイトルを目視。シーンやautoloadは差し替えていない |
| webtunnel | 未使用。プロジェクト文書に接続設定とWebGL対応の未解決前提があったため、ローカルとCI artifactを利用 |

変身は時間を進めた途中の拡大・点滅、踏みつけはTweenによる潰れ途中を撮影した。playcheckでは実際に落下して敵を踏む処理も検査した。ただし撮影用の場面では演出開始メソッドを直接呼んでおり、操作から演出終了までの全経路を動画で検証したわけではない。

最終的にtest・screenshot・movie・build-all・build-webはexit 0。最新コードのCIも全成功。CI描画ログには既知のV-Sync非対応警告があり、既存Makefileの除外規則に従った。Windows/Linux実機とWebブラウザでのプレイ、実機パッド、音の聴取は未実施。通常起動の撮影用プロセスは画像取得後に停止したため、そのmake終了を正常完走の証拠にはしていない。

## 6. Godot固有のハマりどころと回避策

- **ログ出力で起動時クラッシュ**: sandboxでuser://logsを更新できなかった。Makefileの--log-fileを作業ディレクトリ内の絶対パスへ向けた。エクスポートでもexit 0なのにエディタ設定の保存エラーが出たことがあり、終了コードだけでなくログ全文を検査し、必要なアクセス権で再実行した。
- **終了時のWAVリソース保持**: 即時終了や録画終了でAudioStreamPlaybackWAV等の警告が出た。headlessでは再生を開始せず、描画側はSTREAM再生と明示停止を使用。録画専用SceneTreeでは終了8フレーム前に停止し、ミキサーへ反映する時間を確保した。
- **描画用テクスチャの寿命**: _draw内だけでloadした雲が白い矩形になった。preload定数でリソースを保持して解消した。
- **背景とカメラ**: ワールドと同じCanvasItemの背景がスクロールで消えた。背景専用CanvasLayerへ分離した。
- **可変フォント**: Noto Sans JPの既定ウェイトは100。今回の環境では文字列wghtの指定で太さが反映されず、TextServer.name_to_tag("wght")の数値タグで600を指定すると反映された。
- **標準ボタンと独自アクションの違い**: confirmへパッドを設定してもButtonの決定には使われなかった。実行時のui_acceptを調べてパッドAを明示追加した。Buttonは解放時に決定するため、合成入力のテストでも解放後にフレームを待った。
- **成長時の衝突形状**: 主人公の原点を足元にし、巨大化時は形状と画像を上へ伸ばして接地位置を維持した。
- **敵の地形への埋まり**: 固定Y座標で配置せず、配置列の衝突タイルから足元の高さを求めた。
- **殻を蹴った直後の被弾**: 接触が次フレームにも残るため短い猶予を追加し、殻の速度をダッシュより速くした。
- **一時画像のimport**: tmpに.gdignoreを置く処理をMakefileへ追加し、検証用PNGまで素材として取り込まれないようにした。

これらは今回の環境で観察し、修正前後で確認した知見。Godot全バージョンや全OSに共通する仕様・不具合だとは断定していない。
