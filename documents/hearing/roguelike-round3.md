対象は issue #40、作業ブランチは `game/roguelike`。開発完了時のコミットは `150f8e0`。この文書は今回の実行結果・コード・素材クレジット・知見に基づく振り返りであり、未実施のことは実績に含めていない。依頼どおり、この文書はコミットしない。

## 1. 開発の進め方

### 作った順序と分担

1. 作業指示書、AGENTS.md、PROJECT.md、issue #40、Godot と素材の skill を読み、既存の monsterquest / deckrogue の構成や検証・音声終了処理を参考にした。
2. 主担当がタイトル・探索・結果の画面と入力・統合を持ち、サブエージェントをロジック、素材、キャラアニメーション・演出に分けた。先に担当ファイルと API を決め、状態は `RunState`、地形生成は `Dungeon`、敵・道具の定義は `GameData` に寄せた。キャラ画像の名前と敵種別の名前も合わせた。
3. タイトルから探索して結果へ戻れる画面ループを組み、生成・戦闘・道具処理を接続した。最初の実装コミット `2405aa3` には探索・戦闘と画面ループをまとめ、draft PR を作成した。画面ループだけのコミットを別に切ったわけではない。
4. 素材担当の独立 SVG・音源と、演出担当の `AnimationPlayer`・粒子・ポップアップを統合した。視界、ミニマップ、持ち物、識別、階層、敵 AI、成長、満腹度、保存、勝敗の検証を進めた。
5. 実入力の統合検証と30秒の操作録画を追加し、モーダルの重なり、早い画面離脱、スティック斜め移動など、実際に操作して出る問題を修正した。`6157c2d` に入力・連続撮影・描画順などをまとめた。
6. 強化装備にも別の輪郭の画像を用意し、通常初期値から脱出・番人撃破まで到達できること、終了時の音声解放、各 OS のエクスポートを確認した。知見を `documents/knowledge/roguelike.md` に残した。
7. CI の Linux 画像を目視して日本語ポップアップのフォント欠落を発見し、`2c07b64` で修正した。さらに操作録画の最終フレームに灰色の空画面が写ることを見つけ、`150f8e0` で録画終了時の画面解放を修正した。
8. Web 版をブラウザで操作し、最終 CI の画像・動画も確認した。画像と録画を puts で掲載し、受け入れ条件17項目の結果を PR 本文に揃えて ready for review にした。マージはしていない。

### 詰まった点と進め方の反省

- ロジック、素材、演出をファイル単位で分担できた点は有効だった。統合後の入力・描画・寿命管理の不具合は主担当へ集約し、担当間で同じファイルを同時に直すことを避けた。
- macOS の描画確認だけでは Linux のフォント欠落を見つけられなかった。CI を「成功しているか」だけでなく、実際の PNG を見る段階まで行って修正できた。
- 撮影が終了コード0でも、別の階の画像が同一になっていた。画像ハッシュと HUD の階数を併せて確認したことで、撮影側の問題と分かった。
- Web 確認用セッションを早く起動しすぎ、ほかの確認をしている間に期限切れになった。さらに製品コードの修正で再起動した。次回はローカルと CI の主要な表示問題を潰してから、実操作に入れるタイミングで起動した方が無駄が少ない。
- Web の配信先を最初は skill の例にあるポート8080と仮定して接続に失敗した。caller workflow の実設定は8000だった。例示値ではなくリポジトリの設定を先に読むべきだった。
- puts の追加アップロードが自動承認レビューで一度拒否された。作業指示書の「Web の撮影画像を puts upload で PR に掲載する」という明示指示と、目視済みの送信対象5枚を提示して再審査が通った。別の経路で拒否を回避したわけではない。

### 開発・検証・公開のコマンド

- Godot 4.7 のローカル実行ファイル `/Applications/Godot.app/Contents/MacOS/Godot` と `make` を使用した。
- `make test GAMES=roguelike` で `gdlint`、起動、selfcheck、実入力統合を実行した。`gdlint scripts/` に合わせて型や記述を調整した。
- `make screenshot GAMES=roguelike`、`make movie GAMES=roguelike`、`make -C games/roguelike movie-play` を実行した。
- `make build-all GAMES=roguelike`、`make build-web GAMES=roguelike` で macOS / Windows / Linux / Web をエクスポートした。
- `make roguelike-run RUN_FLAGS='--script res://scripts/dev/shutdown.gd'` で通常の起動 target を通して実ウィンドウを表示し、F11 の往復と終了要求を自動化した。Godot の `--quit-after 1/30/120` も別途実行した。
- Python で SVG と WAV を生成した。画像は `fontTools` でフォントの字形を SVG パスへ変換し、撮影一覧の作成には Pillow を使った。音声生成は `wave`、`array`、`math`、固定シードの乱数など標準ライブラリを使った。
- `ffmpeg` で AVI から MP4 へ変換し、2秒ごと・末尾の静止画を抽出した。`ffprobe` で解像度・秒数・フレーム数を確認し、音声の無音・ピークも検査した。
- `rg`、Git の差分・ログ、Python のハッシュ計算で現物を確認した。コミット前・push 前には電話番号の差分点検スクリプトを実行した。
- `gh issue view`、`gh api`、`gh pr create --draft`、`gh pr edit --body-file`、`gh pr ready`、`gh pr checks`、`gh run view/list/download` を使用した。PR の更新は本文ファイルから行った。
- `puts upload <画像パス> --template URL` で画像と動画をアップロードした。ハッシュと公開 URL の manifest を保持する Python スクリプトを作り、変更のないファイルの再送を省いた。
- webtunnel の `preflight.sh`、`webtunnel-cli.sh up roguelike --software-webgl --ref game/roguelike --wait`、CDP 接続、`down roguelike` を使用した。ブラウザは `agent-browser --session roguelike --cdp ...` で操作した。

外部の画像生成 API、既存作品の画像・録音、Steam SDK は使用していない。export templates は用意されているものを利用し、この作業で新たにダウンロード・導入した実績としては扱わない。

## 4. 素材の準備方法と使い勝手

### 画像

`scripts/dev/generate_art.py` で独自 SVG を生成した。主人公と敵6種類は96pxの別ファイルとし、マントと灯火、甲虫、弓の骸骨、胞子粘体、石像、蛾、大型の番人という輪郭の違いを持たせた。道具9種類、階段、金貨、床、壁、タイトル背景3層、ロゴ、装飾も独立した素材にした。強化剣と強化盾は、最終調整で通常品と違う輪郭へ描き分けた。

Python と SVG はパレット、サイズ、余白、ファイル名を揃えやすく、再生成が安定し、細部をコードで直せる点が使いやすかった。一方、形を組み立てる記述量が多く、複雑な手描き表現や豊かなフレーム絵を短時間で増やす方法ではない。今回の動きはキャラごとの単体 SVG に移動・回転・伸縮などを与える構成で、動作ごとに複数の新しい絵を描いたものではない。

多層背景は遠景・門や柱・手前の人物や岩を分け、視差を付けた。霧は外部画像を使わず、GL Compatibility で動く独自シェーダで作った。元作品や外部の画像生成サービスは使っていないため、それらの検索品質・生成待ち時間を今回比較したとは言えない。

### BGM・SE

`scripts/dev/generate_audio.py` で BGM 8曲と SE 7音を生成した。BGM はタイトル、各5階、番人、結果で、旋律、速度、調、主楽器、打楽器の密度を変えた。単一の正弦波だけにせず、倍音、FM の鐘、撥弦、リード、パッド、低音、ノイズの打楽器、左右の反射音を組み合わせた。

固定シードと音符列で再現でき、場面ごとの長さ・音量・楽器をコードで変更できる点は便利だった。外部録音の権利確認やダウンロードは不要だった。一方、PCM の非無音・非クリッピングや音声付き動画を確認しても、旋律の良さ、聞き疲れ、SE と BGM の聴感上の釣り合いは保証できない。音楽の聴感評価は未検証として残した。

### フォント・権利表記

既存 `games/cardbattle/assets/fonts` の Noto Sans JP と OFL 全文をコピーした。UI では太さ500の `FontVariation` を設定し、ロゴは同じフォントの字形を SVG パスにした。新しい素材源を増やさず、日本語の字形とライセンスを揃えられたのが便利だった。ただし、同梱しただけでは全 Label に適用されず、演出用 Label には明示指定が必要だった。

フォントの素材源:
https://fonts.google.com/specimen/Noto+Sans+JP

画像・音声の生成方法、生成器、独自制作であること、フォントのライセンスは `assets/CREDITS.md` に記録した。配布物への CREDITS・OFL 同梱も確認した。生成物を第三者の CC0 素材と表記することはしていない。

### アニメーションの検証

7キャラについて待機・移動・攻撃・被弾・消滅・登場の6動作を対象にした。動作ごとに7列×3時点の gallery を作り、`AnimationPlayer.seek()` で再生時間の0%、45%、95%へ移動して停止させ、開始・途中・終盤を同時に比較した。消滅を含めて比較できるよう、厳密な100%ではなく95%を終盤にした。

これで全キャラの姿勢変化、枠からのはみ出し、動作の違いを確認した。攻撃・被弾・成長・階段・獲得・消滅の演出は、ゲーム画面上の途中状態も別撮影した。実入力動画では探索・戦闘・敗北時のつながりを確認した。ただし静止した3時点は、動作全体の滑らかさや全キャラの実時間の印象を完全に評価するものではない。

### ログと証拠の扱い

ローカルの検証ログは全文を警告・エラー・リーク文言で調べ、終了コードと成功マーカーも確認した。CI の描画ログには既知の llvmpipe の V-Sync 警告があり、ゲームのエラーと区別した。「すべての環境で警告行が一切ない」とは扱っていない。

Web 確認コミットは `2c07b64`。最終 `150f8e0` との差分はローカル録画用 `demo.gd` の終了処理だけで、製品コードは同一だった。この点も PR 本文に明記した。Web セッションは終了後に `down` した。

## 6. Godot 固有のハマりどころと回避策

| ハマったこと | 今回の回避策 |
|---|---|
| `process_frame` を待ってから撮っても、別の階の PNG が同じ描画内容になった | `RenderingServer.frame_post_draw` と `RenderingServer.force_draw(false)` を使って描画と同期した。出力ハッシュと各階 HUD を照合し、ファイルの存在だけを成功条件にしなかった。 |
| Node2D 配下の演出 Label が画面の Theme を継承せず、Linux で日本語が四角になった | `add_theme_font_override` で同梱 Noto Sans JP を明示した。macOS の代替フォントに助けられていた問題を CI の PNG で検出した。 |
| キャラの `z_index` が UI より高く、持ち物画面の前に主人公が出た | モーダルと拡大地図の描画順を明示した。PNG で重なりの解消を確認した。 |
| `queue_free()` 直後はノードがまだ有効で、モーダルを同一フレームに二度外してしまった | 親から外した時点で参照を null にし、フォーカスを戻す対象がツリー内にいることを確認した。 |
| 結果の集計中にタイトルへ戻ると、Tween が破棄された Label へ書き込んだ | 集計表示ノードの `create_tween()` で、そのノードの寿命に結び付けた。早い画面離脱を入力検証に残した。 |
| 左スティックの X/Y を各イベントで即移動へ変換すると、先の軸で待機時間に入り斜め移動できなかった | `_input` では軸イベントから一手を確定せず、`_process` で合成した入力ベクトルを使った。二軸の実イベントで再検証した。 |
| 長文ログが折り返しによって固定矩形を越えた | 固定高の `ScrollContainer` と最新行への追従にした。画面外へのはみ出しを抑えた。 |
| `AudioStreamPlayer.stop()` だけでは終了時に WAV 再生参照が残る場合があった | ストリーム参照を外し、音声出力遅延を考慮した実時間と複数フレームの排出待ちを設けた。通常終了は await、エンジン主導の短時間終了では終了通知中の同期待ちで補い、両方のログを確認した。 |
| 操作録画の最後に `main.queue_free()` したため、末尾の1フレームが灰色になった | 音声の解放待ちは残し、画面は SceneTree 終了時に解放させた。終了直前の実フレームを抽出して確認した。 |
| サンドボックス内では `user://` の ObjectDB Snapshots ディレクトリ作成で起動が失敗した | ログの絶対パス指定や self-contained mode だけでは解消しなかった。検証コマンドを承認された通常権限で実行した。システム設定の変更はしなかった。 |
| headless では描画の良し悪しが検証できない | ロジックには headless、表示にはウィンドウを開く撮影、CI の Xvfb + llvmpipe、Web の SwiftShader を使い分けた。 |
