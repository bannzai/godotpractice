# cardbattle 開発の振り返り

対象はissue #8、オリジナルTCG「星環の決闘」。実装ブランチは `game/cardbattle`、最終実装コミットは `a3b01d3`。以下は今回実行した作業と確認結果の振り返りであり、未実施の検証は区別して記載する。

PR: https://github.com/bannzai/godotpractice/pull/18

## 1. 開発の進め方

1. 作業指示書、AGENTS.md、PROJECT.md、issue #8、既存の雛形と規約を読んだ。変更範囲、30種以上のカード、40枚デッキ、対CPUの決闘、入力・演出・書き出し・CIの完了条件を整理した。
2. ルールの解釈を知見ファイルに記録し、最初のコミットとdraft PRを作成した。生け贄は導入せず、召喚ターンの攻撃を認めるが先攻初ターンは攻撃不可、罠は攻撃時に自動発動とした。
3. カード定義・純粋な決闘ロジック、素材準備、selfcheckをサブエージェントに分担した。本体はタイトル、対戦盤、カード詳細、入力、演出、画面遷移を実装した。先にカードと状態のAPIを合わせたことが並行作業に効いた。
4. CardCatalogに30種と2デッキ、DuelStateに戦闘とCPU、autoloadのSessionに決闘状態を置いた。UIはルールAPIの結果イベントを受けて音とアニメーションを再生する構成にした。
5. lint・起動・ロジック検証を通し、実描画と入力を接続した。レビューでCPUのドロー名が漏れる問題、CPUの番に人間の操作から攻撃APIが呼べる問題を見つけ、表示と手番のガードを修正した。
6. スクリーンショットで背景の白抜け、細すぎる文字、詳細画像・文章のはみ出しを発見した。リソース参照の保持、可変フォントのウェイト、Controlの設定順を直した。音声終了時の警告は最小再現を作り、停止後にフレームを進める方法で解消した。
7. macOS・Windows・Linux・Webを書き出し、CI artifactを取得してローカルとLinuxの見た目を確認した。段階的にcommit・pushし、PRをready for reviewにした。マージはしていない。
8. 追加指示を受けてputsで確認画像をアップロードし、PR本文へ埋め込んだ。さらに通常のmake runも確認し、撮影用の一時設定を撤去した状態へ戻した。

進め方の反省は、最初にロジックだけでなく「日本語フォント・実描画・音声を含む最小の起動と終了」を通しておくと、統合後に集中した環境依存の修正を早く発見できたこと。PRへの画像添付も最初の撮影時から一緒に行えば、後続の追記作業が減った。

## 3. 欲しかったが無かったツール・skill・スクリプト

- **音声を含むGodot検証の雛形**：音源停止と解放待ちまで含むmovieスクリプトがあれば、終了時警告の最小再現と調査が不要だった。今回のmovie.gdを再利用候補にできる。
- **通常起動の画面保存手段**：make runのメインシーンをそのまま起動し、OSの画面収録権限に依存せずViewportを保存できる共通の観測スクリプトが欲しかった。一時autoloadの挿入・撤去を手作業で行った。
- **撮影からPR画像更新までの一括処理**：PNGと動画末尾の収集、puts upload、公開URL確認、PR本文の該当部分の差し替えをまとめたい。puts自体は使いやすいが、画像と説明の対応・既存本文の保持は別途処理が必要だった。
- **日本語UI付きの初期雛形**：OFLフォント・ウェイト・折り返し・画像サイズ・キーボードとパッドの焦点移動を含む最小シーンがあれば初期不具合を減らせた。
- **知見文書を考慮するCIのゲーム選択**：現行の変更判定はgames外の差分を全ゲーム対象とする。必須のknowledge文書を変更すると9ゲーム全部が走った。文書を該当ゲームへ対応づける仕組みが欲しい。

これらは提案であり、共有skill・共有CIには今回反映していない。

## 4. 素材の準備方法と使い勝手

| 素材 | 用意した方法 | 使いやすかった点・限界 |
| --- | --- | --- |
| 背景・四属性の精霊・カード裏 | CodexでSVGを記述し、Pythonで生成。6 SVG、紺・青緑・金の配色、固定seedの星配置 | 色と形をコードで揃えやすく、再生成可能。絵は図形主体で、30種それぞれに固有のイラストを作ったわけではない |
| BGM | 正弦波合成による16秒のオリジナル曲。22,050Hz・16bit・mono WAV。終端を越える残響を先頭へ重ねた | 外部サービスや既存楽曲が不要で再現可能。録音楽器の表現力はなく、音楽的な聴取評価は未実施 |
| SE | 同じPython生成器でドロー・召喚・攻撃・破壊・ダメージ・勝利の6種類を合成 | 短い音の長さ・包絡・音量を制御しやすい。波形がクリップしていないことは確認したが、耳での評価とは別 |
| 日本語フォント | Google FontsのNoto Sans JP、OFL全文を同梱 | Linuxでも日本語を表示できる。可変フォントの初期ウェイトが100で薄く、明示的な太さの指定が必要だった |

生成器は `games/cardbattle/scripts/dev/generate_assets.py`、記録は `assets/CREDITS.md`。最大振幅はBGM約0.212、SE最大約0.508。フォントのOFL文書とCREDITSはexportのinclude_filterにも追加した。

画像生成API・Gemini・外部BGM/SE素材サイトは使用していないため、それらの使い勝手を今回の経験として比較することはできない。独自生成物を根拠なくCC0とせず、生成方法と第三者素材を使っていないことを記録した。

フォント源: https://github.com/google/fonts/tree/main/ofl/notosansjp

## 5. 動作確認の方法と効いた点・足りなかった点

- **headless / selfcheck**：15,819検証成功。カード定義、40枚・同名3枚制限、フェイズ、召喚、攻守戦闘、魔法・罠、勝敗、CPUの優先順位を検証した。固定seed40局は最大94操作で終局し、カード総枚数の保持も確認した。ロジックの境界条件には有効だが、文字・画像・操作感は評価できない。
- **screenshot.gd**：タイトル・遊び方・初手・対戦・召喚途中・攻撃途中・勝利・敗北の8 PNGを目視した。キー・パッド・マウスのイベント投入に加え、一部はButtonのpressedを直接発火し、既知の盤面を作ってルールAPIを通した。全操作を人間と同じ入力だけで最初から最後まで遊んだ試験ではない。
- **アニメーション**：召喚・攻撃開始後0.18秒付近を撮り、対象カードと演出位置を確認した。演出終了を待って勝敗・再戦の状態も確認した。ドロー・破壊・ライフ減少も実装しているが、全演出の全フレームを動画で網羅評価したわけではない。
- **movie**：起動からタイトルまで約5秒の音声付き1280×720動画を生成。0.5秒ごとの連続フレームと末尾PNGを目視した。起動直後の白抜けや黒画面の確認には効くが、操作を伴う決闘全体の録画ではない。
- **CI artifact**：最終CIは全ジョブ成功。cardbattle-screenshot-and-movieを取得し、Linuxのllvmpipeでも8 PNGと動画フレームを目視した。日本語フォント同梱とOS差の確認に効いた。既存Makefileで除外しているV-Sync非対応警告だけはLinux描画ログに出る。
- **make run**：エディタなしのウィンドウ生成を確認した。OS撮影は権限不足で失敗したため、通常起動に一時的な観測autoloadを追加し、Viewport画像を保存してタイトルを確認した。撮影処理は撤去し、追跡ファイルに差分を残していない。
- **webtunnel**：今回は使っていない。Webは書き出しまでで、ブラウザでの実行確認は未実施。Windows/Linuxの配布バイナリを各OSで対話操作する試験、物理ゲームパッドの機種別試験も未実施。

PR画像はputsの出力Markdownを貼り、公開URLから画像を取得し直して元PNGとのSHA-256一致まで確認した。最初は画像添付を実施しておらず、追加指示後に実施した。

## 6. Godot固有のハマりどころと回避策

| 現象 | 今回の回避策 |
| --- | --- |
| headlessでは表示の崩れを検出できない | ロジック検証と描画付き撮影を分ける |
| _draw内だけのloadで画像が白くなる | 描画するTextureをpreloadした定数で保持したところ解消 |
| 子カードのthemeがnullになる | 親から継承したフォントをget_theme_default_font()で取得 |
| TextureRectとLabelのサイズが期待より大きい | expand_mode・フォント・折り返しを先に設定。親追加後にもサイズを適用し、必要な箇所は遅延適用 |
| 日本語可変フォントが薄い | サポート軸を調べ、FontVariationにname_to_tag("wght")の整数タグと500を指定。文字列キーで薄いままの描画を実測したが、一般的に文字列指定が無効とは断定しない |
| AudioStreamPlayerを止めても終了時にリソース警告 | stopとstream=nullの後、約0.2秒フレームを進める。Movie Makerではsleepだけでは解消せず、専用movie.gdで末尾8フレームを解放待ちにした |
| --quitの起動検査で音源が残る | 描画なしの起動ではBGMを開始しない。遅延再生が終了準備後に再開しないフラグも設けた |
| macOS全画面切替の直後に判定すると失敗 | F11 / STARTの各操作後に1秒待って確認 |
| WAVを含むmovieのフレーム数 | スクリプトは150フレームを数えるが、エンジンのログとmp4は151フレーム・約5.033秒。完全に150枚だけの出力とは報告しない |
| OFL文書が自動で配布物に入らない | 全export presetのinclude_filterへ明示し、保存ログで同梱確認 |

音声解放の上流情報: https://github.com/godotengine/godot/issues/76745

環境側の問題もあった。sandbox内ではGodotの標準ユーザーデータ領域の作成が拒否され、通常権限で検証した。--log-fileを相対指定した調査ではuser配下の意図しない場所へ解決されたため、以後は作業ディレクトリ内の絶対パスを使用した。putsはKeychainアクセスに通常権限が必要で、LLVMのdefault.profrawも生成したため、一時ディレクトリで実行する運用が扱いやすかった。

追加指示のルートmake runは、最後にmainを確認した時点では未反映だったため、origin/mainのmergeは実施していない。この振り返りの作成に合わせた新規のmain確認や取り込みは行っていない。
