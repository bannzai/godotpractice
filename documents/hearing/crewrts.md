# こもれび回収隊 開発ヒアリング

対象は issue #10、PR #21。今回実行した内容と、実行していない検証を区別して記録する。

## 1. 開発の進め方

1. 作業指示書、AGENTS.md、PROJECT.md、issue #10、既存の雛形とCIを読み、変更範囲と受け入れ条件を確認した。
2. ゲームモデル・素材準備・HUDを独立したサブエージェントへ分担し、本体側で3Dの庭、ロボット、カメラ、入力、音声との接続を実装した。モデルの公開APIを先に決めたことが並行作業に効いた。
3. ゲーム状態は `Expedition` autoload に集約した。30体の仲間、2種類の能力差、投擲、笛、解散、必要人数による運搬、敵、増員、時間切れ・全滅・クリアを先に成立させた。描画とHUDはモデルを読む構成にした。
4. `make test` と代表画面の撮影を通し、基本実装をコミット・pushしてdraft PRを作成した。実際には基本実装の確認後までPR作成が進まなかったので、次回はより小さい実装単位で早くdraftを作る余地がある。
5. selfcheckだけでなく実入力イベントを流す統合テストを追加し、矢印キーの定数違いとパッドのメニュー決定操作不足を修正した。独立レビューでは笛の表示範囲と実際の効果範囲の不一致を見つけ、同じ定数に合わせた。
6. 実描画の性能、録画、デスクトップ3種とWebへの書き出しを検証した。ローカルで通った撮影がLinux CIでは音声解放の警告で失敗したため、CIのログとartifactを取得して終了処理を修正した。
7. 最終CIの全成功とLinuxのPNG・動画を目視確認し、PRをready for reviewにした。マージはしていない。
8. 追加指示を受け、putsで検証画像をPRへ掲載した。さらにゲーム側の `make run` を実際に起動し、通常終了まで確認した。ルートのrun targetは最後のmain取得時点では未導入だったため、mainのマージは実行していない。

詰まった点は、ゲームロジックよりも、サンドボックス下でのGodotのログ・設定保存、描画権限、終了時の音声解放に多かった。共有ファイルや元のGodot.appを変更せず、ゲーム内の一時ディレクトリと専用検証スクリプトで解決した。

## 2. 実際に使ったツール・skill・コマンド

- `godot-development`: ローカルにSKILL.mdがなかったため、指示されたcastleのGitHub上のSKILL.mdとpitfallsを `gh api` で取得して参照した。雛形は既存のものを利用し、scaffoldやexport templatesのインストールスクリプトは実行していない。
- `game-asset-search`: 素材の採用条件・記録手順を参照し、素材担当でクレジット記録、親側でも `check-credits.sh --assets games/crewrts/assets` を実行した。今回の画像・音声は外部素材検索で集めたものではない。
- Godot 4.7、GDScript、`gdlint`、`make test` / `make screenshot` / `make movie` / `make build-all` / `make build-web`。一括コマンドはルートから `GAMES=crewrts` を指定した。
- `make -C games/crewrts run`。エディタなしのウィンドウ起動、bootログ、通常の終了要求によるexit 0を確認した。
- Python標準ライブラリ: 音声合成、ファイル整備、公開画像のSHA-256照合、PR本文への画像挿入。
- `ffmpeg`: AVIからmp4への変換、動画の1秒ごとのフレームと末尾フレームの抽出、音量・輝度の検査。
- `puts upload <画像パス>`: 代表画面8枚、動画の末尾フレーム、追加のrun確認画像をアップロードし、出力MarkdownをPR本文へ埋め込んだ。
- `gh issue view`、`gh pr create --draft` / `edit` / `ready`、`gh run view` / `watch` / `download`、gitのcommit・push・fetch。PR本文はファイル経由で更新し、既存画像を保持した。
- `rg`、ログ全文のWARNING/ERROR検査、電話番号の差分検査スクリプト。
- macOSでの `codesign`、SwiftのCoreGraphicsによるウィンドウID取得、AppKitの `NSRunningApplication.terminate()` による対象プロセスだけの通常終了。`screencapture` も試したが画像取得には失敗した。

## 3. 欲しかったが無かったツール・skill・スクリプト

- **Godotのサンドボックス用起動準備**: 作業ディレクトリ内のログ、self-contained mode、既存templatesの参照、コピーしたmacOSバイナリの署名をまとめるスクリプト。今回は個別に準備した。
- **通常起動の撮影と終了**: `make run` のメインシーンを変えずに起動・録画・対象PIDの特定・通常終了・フレーム抽出まで行う道具。OSの画面撮影が失敗した後、録画オプションだけを追加する一時ラッパーとSwiftで補った。
- **Godot向け入力統合テストの雛形**: キー・パッド・マウスの実イベント、メニューのフォーカス、休憩中の時間停止、F11往復をまとめて検査するもの。今回の `integration.gd` を汎用化できる。
- **途中動作を録画するシナリオ検証**: 移動→投擲→運搬→戦闘→回収の連続動画を再現する仕組み。状態別PNGだけより、移動や演出の時間的な違和感を見つけやすい。
- **PR検証画像の更新スクリプト**: 撮影→puts→公開画像の一致確認→既存本文の該当画像だけ更新を一括化するもの。今回はMarkdown編集と確認を都度行った。
- **CIの対象選定の改善**: ゲーム別知見文書の更新だけでも全9ゲームが対象になった。対象ゲームへ絞れれば反復確認が軽くなる。共有CIは今回変更していない。

## 4. 素材の準備方法と使い勝手

### 画像・3D・UI

外部のキャラクター画像、背景画像、モデル、テクスチャは採用していない。球・円柱・箱などのGodotプリミティブをコードで組み合わせ、庭、基地、ロボット、結晶、敵を作った。UIもControlとStyleBoxで生成した。画像生成AIは使っていない。

配色と形をコードで揃えやすく、インポートや外部素材のライセンス調査を減らせた。一方、モデルや手描き素材のような細部は出しにくく、顔・敵への取り付き方・輪郭の読みやすさには実描画を見た調整が必要だった。

### BGM・SE

`generate_audio.py` でmath・waveなどから独自合成した。BGMは16秒のステレオWAV、SEは笛・投擲・運搬完了・敵撃破・仲間喪失の5種類。外部録音や既存曲は取り込んでいない。生成し直したSHA-256の一致、無音・クリッピングの有無を素材担当が検査した。

APIキーも外部音源探しも不要で、再生成や長さ・音程の調整が容易だった。音楽の完成度や長時間聴いたときの飽きにくさは、数値検査だけでは評価できない。今回、耳で通して聴く品質評価を完了したとはいえない。動画の音声トラックが無音でないことはffmpegで確認した。

### フォント

Google Fontsの公式リポジトリから静的TTFのM PLUS Rounded 1c Regularを取得した。日本語文字の確認、OFL全文・著作権表示の保持、CREDITSへの記録、exportでの同梱を行った。

日本語表示をOSフォントに依存させず、macOSとLinuxの見た目を揃えるのに有効だった。OFL.txtはGodotのリソースとして自動同梱されると考えず、include_filterへ明示する必要があった。CC0素材サイト、画像生成サービス、外部BGMライブラリは今回比較していない。

## 5. 動作確認の方法と限界

- **headless selfcheck**: 人数不足、種類差、報酬の二重取得防止、戦闘、時間切れ、全滅、障害物回避、敵を残した通常ステージでのクリア経路を検査した。描画なしでゲームの成立を速く確認できた。
- **入力統合検証**: 実際のInputEventを投入し、headlessと実ウィンドウで検証した。F11は実ウィンドウで往復確認した。物理ゲームパッドを人が操作した確認ではない。
- **screenshot.gd**: タイトル、プレイ、投擲、笛、運搬、戦闘、成功、失敗の8枚を撮影した。日本語やHUDの崩れと、途中姿勢の確認に効いた。結果画面には撮影用の状態投入もあるため、そのPNGだけをクリア可能性の証拠にはしていない。
- **movie**: 起動からタイトルの5秒を録画し、フレーム抽出で確認した。最後のフレームだけ空になる問題は、末尾1秒前の輝度検査では拾えず、実際の最終フレームを見て修正した。
- **CI artifact**: LinuxのPNG8枚とmp4をダウンロードし目視した。ローカル成功だけでは見つからなかった終了時の音声解放警告を検出できた。
- **性能**: 実描画で30体と敵2体、準備120フレーム後の600フレームを計測。M4 Maxで平均581.5fps、p95 3.56ms。CIのソフトウェア描画や他GPUで60fpsを保証する測定ではない。
- **webtunnel**: 使用していない。Webはexport成功まで。ブラウザ上のプレイは未検証。

アニメーションは、揺れ・跳ねを伴う隊列、投擲の弧、笛の拡大リング、運搬・戦闘中の姿勢をPNGで確認し、タイトル上の動きは録画フレームでも確認した。プレイ全体を連続録画して動作の自然さまで評価したわけではなく、ここは今回の検証の限界。

## 6. Godot固有のハマりどころと回避策

- 投擲の着地でsin(PI)の丸め誤差が残った。終了時にpositionを着地点へ確定してから付着状態に変えた。
- headlessでは見た目が検証できない。描画付きの撮影・録画を別に実行した。
- user://のログ保存・ローテーションがサンドボックス内で失敗し、クラッシュする場合があった。`--log-file` でゲーム内tmpへ保存した。
- export時のeditor_settings保存は作業ディレクトリ外に向かった。Godotの一時コピーと `_sc_` によるself-contained modeで回避した。コピーしたmacOSバイナリはそのままだと起動時に終了し、ad-hoc署名後に動いた。
- macOSの既存export zipをGodotがゴミ箱へ移動しようとして失敗した。再生成可能な成果物だけをexport前に除去した。
- WAV再生中の即時終了でリソース解放警告が出た。headlessではBGMを開始せず、撮影・通常終了では停止後0.15秒、録画では終了6フレーム前の停止を設けた。
- 録画終了前にシーンを削除して1フレーム待つと空の画面まで収録された。音声だけ先に停止し、シーンは終了まで保持した。
- ui_acceptの既定割当には今回パッドのAがなく、プレイできても結果から再開できなかった。決定と十字キーをInputMapへ明示し、定数照合と実入力の両方で検査した。
- マウスイベントの座標とOSポインターの再取得を混ぜると、実ウィンドウの入力検証が安定しなかった。InputEventMouseMotion.positionを保持して照準を計算した。
- Linux llvmpipeのV-Sync非対応警告は既存Makefileが明示除外するドライバ由来の警告。音声解放などゲーム由来の警告は除外せず修正した。
