## 1. 開発の進め方

1. **既存仕様と画面を先に確認した。** 作業指示書、AGENTS.md、PROJECT.md、issue #9、既存の知見、前回のヒアリングを読み、変更前のスクリーンショットを撮影した。巻き込みの体積計算、189個の配置、3分制限、反発と脱落、キーボード・ゲームパッド入力を維持する方針を決めた。前回のヒアリングが main に無かったため、別ブランチのファイルを GitHub Contents API で取得した。
2. **早期に draft PR を作り、担当ファイルを分けた。** サブエージェントへモデルとアニメーション、HUD と SVG、音源生成を分担した。親エージェントはゲーム本体への接続、パーティクル、衝突演出、終了処理、検証を担当した。同じファイルを同時に編集しないよう、分担を先に決めた。
3. **独立モデルと共通の表示方針を作った。** 主人公、アヒル、ロボット、汽車、植木を別の3Dシーンにした。耳・くちばし・アンテナ・車輪・葉などの形と可動部で種類を区別し、それぞれに6状態の AnimationPlayer を用意した。背景は窓の奥の山・雲、カーテン、家具、小物の層を増やし、HUD は同じフォント・配色・Theme に統一した。
4. **通常のゲーム処理へ演出を接続した。** 回収、成長の節目、反発、勝利にパーティクルと Tween を加え、反発時の短い停止・画面揺れ・フラッシュを実装した。通常状態のアニメーション指定が単発の巻き込み・衝突アニメーションを途中で切っていたため、開始イベントで一度再生し、終了まで待機・移動に切り替えないようにした。
5. **撮影と録画を見ながら調整した。** モデル一覧の白飛びと黒い三角形は照明・影の設定を見直して解消した。連続回収時の数値が重なる問題は、短時間の加算をひとつの表示に合算して解消した。結果画面へカメラの揺れが残る問題は、勝敗確定とリセット時に補正を戻して直した。キーアートも実際の主人公の配色と耳に合わせた。
6. **録画シナリオを実入力へ置き換えた。** Enter とスティックイベントで通常の移動・衝突・回収を通すシナリオを作った。初期案は「40個以上集める」という固定条件のため、少ない個数で大きな物を集めてクリアしても失敗扱いになった。ゲーム本来の目標直径、勝利状態、付着数との整合で判定するようにした。遅すぎる入力では25秒以内にクリアできなかったため、前半は短い停止を挟んで成長を見せ、後半は通常速度で進めるよう調整した。
7. **音声付きの終了を診断した。** headless の検証が通っても、Movie Maker のフレーム指定終了で音声リソースが残った。終了引数がスクリプトに渡らないことを実測し、録画入口から停止予定フレームを別途渡す方式にした。診断中に、圧縮 WAV のバイト数をサンプル数と誤認して曲が途中でループする別の不具合も見つけ、修正した。
8. **ローカル、CI、Web の確認を閉じた。** 全エクスポート、通常起動、実時間の性能測定、Web の実操作を行い、画像を puts でアップロードした。CI の画像と動画も取得して目視した。自動レビューで、検証用フォルダがない場合の画像保存失敗が指摘されたため、起動確認スクリプトで保存先を作成するよう修正し、フォルダのない独立コピーで再検証した。

進行上は、素材制作の並行作業が有効だった。一方で、Godot の描画付き検証は同じマシン上で重ねず、順番に実行した。時間を使ったのはモデル制作だけでなく、終了時の音声解放、録画の経路調整、証拠画像の整理・アップロード・CI 再確認だった。

## 4. 素材の準備方法と使い勝手

### 3Dモデルと背景

主人公、アヒル、ロボット、汽車、植木は、種類ごとに独立したメッシュ構成とマテリアルを持つシーンとして制作した。単なる色違いにせず、顔、翼、腕、車輪、葉などの形と動く部位を変えた。背景の部屋・窓外・家具もコードと Godot のプリミティブを使った。

この方法は、別ツールの操作や素材のダウンロードを挟まず、小さな形の修正とゲームへの組み込みを繰り返せる点がよかった。モデル単位で担当を分けられ、AnimationPlayer のトラックも同じシーンに収められた。一方で、部位が増えるほどノード・メッシュ・描画の負荷が増える。今回の作風には合っていたが、複雑な造形や骨格アニメーションまで同じ方法が適切かは試していない。

### 画像と UI

ロゴ、キーアート、時計、収集数のマーク、達成章を、それぞれ別の SVG としてコードで制作した。珊瑚色、青緑、クリーム色を共通に使い、Theme と合わせた。既存の玉のマークは引き継いだ素材であり、今回の主要な UI 画像は別ファイルで追加した。

SVG は配色と寸法を合わせやすく、独立した小さな UI 部品に向いていた。反面、キーアートと3Dモデルを別担当で作ると、主人公の色や耳の有無がずれた。両方を並べて確認し、実モデルに合わせて SVG を直す必要があった。画像生成モデルは使っていないため、今回の作業から画像生成サービス同士の比較はできない。

### BGM と SE

Python 標準ライブラリで木琴、撥弦、鐘、低音、ノイズ系の打楽器を数式合成した。既存曲や外部の録音素材は使っていない。

| 場面 | 用意した音楽 |
| --- | --- |
| タイトル | 木琴と撥弦を中心にした約12秒の3拍子 |
| 通常プレイ | 撥弦、低音、ブラシ系打楽器を含む約15秒のループ |
| 残り30秒 | テンポと刻みを変えた約12.8秒のループ |
| 成功 | 鐘を含む約8.73秒の曲 |
| 時間切れ | 音数と編成を抑えた約11.71秒の曲 |

SE は回収、衝突、成長、成功、失敗を別 WAV にした。互換用の既存ファイル名 `music.wav` は、通常プレイ曲と同じ内容で残した。

固定シードと決定的な処理により、再生成2回の SHA-256 が一致した。`--verify` でも保存済み WAV と生成結果を照合し、非無音、非クリッピング、端点ゼロ、BGM の長さを検査した。最大ピークは0.780以下だった。波形・音域・編成を調整しやすく、生成元をリポジトリに残せる点はよかった。

ただし、これらは音の良さや聴き分けやすさを保証する検査ではない。聴感評価は未検証である。また、ソース WAV が正しくても Godot のインポート後には圧縮形式が変わるため、ゲーム内の再生設定まで別に確認する必要があった。

### フォントとクレジット

フォントは第1ラウンドから同梱済みの M PLUS Rounded 1c Medium を再利用し、今回の Theme にも設定した。今回新たにダウンロードしたものではない。既存の CREDITS には Google Fonts の配布元、OFL-1.1、著作権者が記録され、OFL.txt も同梱されている。

既存クレジットに記録された配布元:

https://fonts.google.com/specimen/M+PLUS+Rounded+1c

フォントを同梱したことで、macOS と Linux の OS フォント差に頼らず日本語を表示できた。今回制作した画像・モデル・音源はオリジナル生成物として CREDITS に記録した。第三者素材の CC0 と混同せず、生成方法と由来を残した。CC0 素材サイトからの取得との作業時間・品質の比較は、今回は行っていない。

## 5. 動作確認の方法と、効いたこと・足りなかったこと

### headless の検証

`make test GAMES=rollball` で lint、インポート、起動、selfcheck、実シーンの integration、通常終了とフレーム指定終了を実行した。既存の受け入れ条件を保ちながら表示だけを差し替える際の基準になった。

実シーンの integration では、通常移動と接触で70個を集めて直径3.204mに到達し、無操作では180秒で時間切れになることを確認した。キーとゲームパッドの入力イベント、結果メニューの操作も検証した。headless は速く繰り返せる一方、描画崩れや実際の音声再生の問題は検出できない。Dummy 音声では再生を省く経路もあるため、「headless で終了警告がない」だけでは音声解放の証拠にならなかった。

### スクリーンショットとアニメーション

`make screenshot GAMES=rollball` で29枚を撮影した。内訳は5画面、2つの遷移途中、4つの演出途中、モデル一覧の6状態×3時点である。

モデル一覧には5種類を並べ、待機・移動・巻き込み・衝突・お祝い・時間切れについて、0%、50%、95%の姿勢を撮影した。これはタイムラインの姿勢を指定して描画する検証であり、全フレームを連続再生した動画そのものではない。開始姿勢への復帰、部位の変位、つぶれや傾き、種類ごとの見分けやすさ、影や照明の崩れを確認するのに効いた。

演出の撮影では、パーティクルや HUD を明示的に発生させて途中を切り出した。時間切れ画面の撮影にも専用の状態操作を使った。したがって、これらの画像だけで通常操作から到達できることを証明せず、integration・実入力録画・Web 操作と組み合わせた。

撮影時はゲームを一時停止して複数の描画完了を待ち、ソフトウェア描画の待ち時間中に短い演出が終わるのを防いだ。ローカルと CI の元画像・確認用一覧を目視し、モデル一覧の白飛び、黒い三角形、HUD の重なり、遷移後に残るカメラ補正を直した。

### 起動動画と実入力のプレイ録画

`make movie GAMES=rollball` は操作なしの5秒録画で、起動直後の黒画面や描画崩れ、音声を録音したフレーム指定終了の警告を検査した。

別の `movie-play` は、ゲーム状態・位置・直径を直接書き換えず、キーとスティックの入力イベントを762件送って録画した。進む方向は回収可能な物体を選ぶ既存処理から求めるが、移動と衝突は通常のゲーム処理を通している。最終動画は30fps・767フレーム・約25.57秒で、14.68秒時点に34個・直径3.210mでクリアした。

mp4 は ffmpeg で2秒間隔の一覧と末尾フレームにし、タイトル、段階的な成長、クリア、結果画面の表示完了を目視した。ffprobe で尺と映像・音声トラックも確認した。細かなカクつきやすべての中間姿勢を2秒間隔の静止画だけで保証することはできないため、モデルの3時点撮影と実時間の性能測定を併用した。

### 通常起動と性能

`run_smoke.gd` で実キー移動、F11 による全画面と復帰、Esc によるタイトル復帰、通常の閉じる要求を実行した。自動レビューの指摘後は、検証用フォルダがない独立コピーを用意し、必要なインポートを済ませてもフォルダが存在しないことを確認してから実行した。exit 0 で保存先と4枚の画像が作成され、通常終了まで進んだ。macOS の既知の入力メソッド通知が1件出たが、終了時リークは無かった。

性能は Movie Maker の固定fpsや headless の処理速度を使わず、描画付きで実時間のフレーム間隔を測った。Apple M4 Max、1280×720、GL Compatibility、VSync 無効、Dummy 音声で、189物体の非操作時は平均96.96 FPS・p95 12.658ms、通常成長中は平均102.95 FPS・p95 12.943msだった。部位と影を増やした分、前回より負荷は増えている。

### CI artifact

## 6. Godot 固有のハマりどころと回避策

### フレーム指定終了の引数を取得できなかった

Godot 4.7 では、エンジンが消費した `--quit-after` が `OS.get_cmdline_args()` に残らなかった。引数を取得できているつもりで実装した停止処理が動かず、最後のフレームまで音声が再生されていた。

録画入口が `--quit-after N -- --audio-stop-at-frame N` を渡し、スクリプトは `OS.get_cmdline_user_args()` から後半を読むようにした。12フレーム前に音声を停止して参照を外し、非常に短い指定では再生自体を始めない。通常の閉じる操作は音声停止後に8フレーム待つ。音声付きで裸の `--quit-after` を直接実行する場合まで自動対応できたわけではなく、追加引数が必要なことを README と PR に明記した。

### stop だけでは音声の解放が間に合わなかった

Movie Maker の終了で AudioStreamPlaybackWAV と AudioStreamWAV が残った。Ogg に変換しても、WAV の再生方式を STREAM に変えても、有効に再生を続けた条件ではリークが再現した。形式の交換では解決せず、音声を止めてからエンジンに複数フレーム処理させる必要があった。音声の Tween も止め、プレイヤーの stream 参照を外す処理へまとめた。

### 圧縮 WAV のバイト数とサンプル数を取り違えた

元の WAV は無圧縮でも、Godot のインポート後は QOA だった。`data.size()/2` をループ終端に使うと、12秒のタイトル曲が約2.43秒で途中ループした。ループ終端はサンプル数なので、`roundi(stream.get_length() * stream.mix_rate)` から求めるように修正した。

### アニメーションの状態指定が毎フレーム割り込んだ

移動量から待機・移動を毎フレーム指定すると、単発の巻き込み・衝突アニメーションを上書きする。単発状態の間は通常状態への切替を保留し、再生開始も回収・衝突イベントで一度だけ行うようにした。状態をまたぐと前の姿勢が残るため、各トラックの基準姿勢の復帰も必要だった。

### 結果画面にカメラの揺れが残った

プレイ状態から外れると通常の揺れ更新が止まり、Camera3D の補正が残った。勝敗確定とワールドのリセット時に水平・垂直の補正をゼロへ戻した。

### 一覧撮影の照明と短い演出の撮影時刻

元の部屋の指向性ライトは離れたモデル一覧にも届き、専用ライトと重なって白飛びした。元のライトを無効にして専用照明へ切り替え、背景面の影と影距離も調整した。

また、描画完了を待つ間にもゲームを進めると、短いパーティクルやフラッシュが撮影前に終わる。撮影時にゲームを一時停止し、`RenderingServer.frame_post_draw` を複数回待ってから画像を保存した。フォントの描画が落ち着くまで待つ用途にも使った。

### Git の ignore はエクスポート除外にならなかった

検証用 PNG、音声の診断ファイル、診断スクリプトがローカルのエクスポートへ入っていた。Git 管理外であっても Godot のリソース対象にはなり得る。4つのエクスポートプリセットに `exclude_filter="tmp/*,build/*"` を設定し、再ビルドのログ全文で一時ファイルの同梱が消えたことを確認した。

### 起動確認だけでは保存先が作られなかった

インポートや撮影用の make target は検証用フォルダを作るが、通常の `run` は作らない。Image.save_png は親ディレクトリを自動作成しないため、`run_smoke.gd` の初期処理に DirAccess による作成と失敗判定を追加した。既存の検証フォルダがある環境だけで試していると見落とす問題だった。

### 検証スクリプトの基底クラスと通知定数

SceneTree を継承した検証スクリプトでウィンドウの閉じる通知を送る際、Node の通知定数を無修飾で参照するとスコープの問題が出た。`Node.NOTIFICATION_WM_CLOSE_REQUEST` と明示して、通常の閉じる経路を呼ぶようにした。

### エンジンの異常と実行環境の制約を分けた

sandbox 内では Godot の標準ユーザーデータ領域への書き込みが拒否されて abort する場合があり、許可されたローカル検証として実行し直した。CI の llvmpipe では V-Sync の変更不可通知、macOS では入力メソッドの通知が出る場合があった。既知の通知だけを区別し、その他の WARNING / ERROR と終了時リークはログ全文で検査した。

Godot が exit 0 でも終了時にリソース残存を報告することがあるため、プロセスの終了コード、必要な成功メッセージ、成果物の存在、ログ全文の確認を組み合わせることが重要だった。
