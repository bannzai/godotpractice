# deckrogue 開発ヒアリング

対象は Godot 4.7 / GDScript で制作した「燈火の巡礼」。実装、ローカル検証、CI、PRへの画像添付、エディタなしの起動確認までを振り返る。以下は今回実施したことと、その結果から欲しくなった道具を分けて記録したもの。このファイルは依頼どおりコミットしない。

## 1. 開発の進め方

最初に作業指示、AGENTS.md、PROJECT.md、issue #6、関連ルールを読み、変更可能な範囲と完了条件を確認した。Godot、gdlint、ffmpeg、エクスポートテンプレートの有無を調べ、開発知見の文書を先に作って draft PR を開いた。

戦闘ロジックと素材を別のサブエージェントへ委譲し、自分は画面、入力、音声制御、スクリーンショット・録画を担当した。並行作業の前に、ゲーム状態のAPI・シグナル、素材のパス・サイズ・フォントを合わせた。これにより、素材や戦闘ロジックの完成を待たずに画面側を進められた。

ゲーム状態を autoload の Run、カード定義をカタログに集め、画面と効果処理が同じデータを見る構成にした。タイトル、分岐マップ、戦闘、報酬、イベント、休憩、ボス、勝利・敗北から再開までをつなぎ、18種類のカードと3種類の遺物を組み込んだ。固定seedで実行を再現できるようにしてから、正常な攻略と敗北の両方を検証した。

詰まった点と解決は次のとおり。

- 使用中のカードを先に捨て札へ移すと、山札が空のドロー効果でそのカード自身を引き直せる。効果解決後に捨て札・廃棄へ移す順序にした。
- 手札を枚数に応じて縮めると、追加ドロー時に日本語の名前・効果文がはみ出した。カード幅を174に固定し、横スクロールとフォーカス追従に変更した。
- カードのホバーで共通ボタンの暗い背景が適用され、暗い文字が読めなくなった。通常・ホバー・押下それぞれのカード用背景を定義した。
- 被弾色の上でダメージ数字が読みにくかったため、白文字、輪郭、描画順、表示時間を調整した。捨て札演出はスクロール領域で途中が切れたため、領域外へ表示用カードを作って移動・縮小させた。
- Godotはサンドボックス外のユーザーデータやエディタ設定へ書き込むため、通常権限ではimportの終了コードが0でもERRORが出た。起動検証では異常終了もあった。必要な検証を権限付きで実行し、終了コードだけでなくログ全文を確認した。
- 音声再生中の即終了でリソース解放警告が出た。headless・静止画撮影では再生自体を止め、録画では終了前に音源停止と待ち時間を入れた。

ロジック検証、画面検証、録画、全プラットフォーム向けエクスポートを終え、CIの最終結果と映像artifactを確認した。最終CIは28ジョブすべて成功。知見文書も共有物変更として判定されるため、deckrogue以外を含む9ゲームの検証が動いた。共有CIの修正は行わず、改善案だけ知見文書へ残した。

PRは次のとおり。依頼された代表画面と録画末尾の計7枚を本文へ添付済み。マージは実施していない。

https://github.com/bannzai/godotpractice/pull/15

## 2. 実際に使ったツール・skill・コマンド

| ツール・skill | 今回の用途 |
|---|---|
| godot-development | 起動・検証・エクスポートと既知の問題を確認。ローカルに見つからず、GitHub上のSKILL.mdとpitfalls.mdを取得して読んだ。今回は既存テンプレートを使い、導入スクリプトは実行していない |
| game-asset-search | 素材の扱いとクレジット記録に適用。`check-credits.sh`で記録漏れを確認。画像・音楽の外部素材検索は採用しなかった |
| サブエージェント | 戦闘・selfcheckと素材生成を並行実装。追加のUI確認でも入力設定や表示上の問題を見つけた |
| Godot CLI / Make | `make test GAMES=deckrogue`、`make screenshot GAMES=deckrogue`、`make movie GAMES=deckrogue`、`make build-all GAMES=deckrogue`、`make build-web GAMES=deckrogue`、`make -C games/deckrogue run`を実行 |
| gdlint | GDScriptのlint。`make test`に含めて実行 |
| Python標準ライブラリ | SVG・WAV生成、固定seedでの再生成一致、XML・PCM読込、画像ハッシュの確認 |
| ffmpeg | MovieMakerのAVIをmp4へ変換。時点を指定した静止画抽出、輝度・音量の確認、PR用の末尾フレーム生成 |
| Git / gh | コミット・push、draft PR作成・更新・ready化、CI結果確認、artifactダウンロード。skillの取得には`gh api`も使用 |
| puts | `puts upload`で代表画面と録画末尾をアップロードし、出力されたMarkdownをPR本文へ挿入 |
| curl / SHA256 | 公開画像の取得と元画像との一致確認。別のHTTP取得方法で403が出た際も、curlで実物を取得して判定した |
| rg / apply_patch | コード・ファイル探索、ログ全文のWARNING / ERROR検索、ファイル編集 |
| JXA / CoreGraphics / lsof | `make run`で開いたGodotのPID、作業ディレクトリ、対象ウィンドウの存在を確認 |

Godot本体は `/Applications/Godot.app/Contents/MacOS/Godot` を使用した。Godotを`--verbose`で起動し、終了時に残った音声リソースの特定にも使った。putsは通常権限ではKeychainへのアクセスが失敗し、権限付き実行でアップロードできた。

ブラウザ自動操作、webtunnel、画像生成API、外部の音楽生成サービスは今回使用していない。

## 3. 欲しかったが無かったツール・skill・スクリプト

ここでいう「無かった」は、今回すぐ使える形で見つからず、個別実装やコマンドの組み合わせが必要だったものを指す。

- **Godot検証用の共通スクリプト**：入力イベントによる操作、固定seedの攻略、場面の切り替え、撮影をまとめて記述できるもの。今回はselfcheckとscreenshot.gdに個別実装した。タイトルから勝敗までの一連の操作を映像にも使い回せると便利。
- **アニメーション区間の録画と撮影**：カード使用・被弾・捨て札などの開始を検出し、その前後だけ録画・連続撮影する機能。秒数で待つ方法は描画環境によって写る瞬間が変わり、適切な待ち時間を調整する手間があった。
- **音声付き録画の安全な終了テンプレート**：終了数フレーム前に音声を止め、解放を待って終了する仕組み。今回のmovie.gdをgodot-developmentへ再利用可能な例として追加できる。
- **InputMapの実イベント検査例**：キーの登録有無だけでなく、KEY_LEFT等からイベントを作って意図したアクションに対応するか調べるもの。今回の左右キーの取り違えを早い段階で検出できる。
- **日本語UIの代表的な表示条件を撮る仕組み**：長いカード名、大量手札、ホバー、フォーカス移動、状態異常の同時表示をまとめて確認したい。通常の戦闘画面1枚だけでは問題を見落とした。
- **PR画像更新スクリプト**：代表PNG・録画末尾の生成、putsアップロード、本文の検証欄への挿入、公開画像とローカル画像の一致確認までをまとめたい。現状はアップロード結果と本文を個別に管理した。
- **macOSの実ウィンドウ確認スクリプト**：起動PIDとウィンドウを対応付け、画面収録権限の有無を最初に調べてから撮影するもの。今回はJXA、CoreGraphics、lsof、screencaptureを組み合わせて調べた。
- **skillがローカルに無い場合の取得経路**：指定ファイルと参照文書をCLIで取得する方法が共通化されていると、URLの取得失敗から別の手段へ切り替える手間が減る。

画像・音声生成についても、固定seedでの生成とハッシュ一致、クレジット点検を一組の例としてgame-asset-searchへ追加すると再利用しやすい。これらは提案であり、今回共有skillへの変更は行っていない。

## 4. 素材の準備方法と使い勝手

| 種類 | 準備方法 | 良かった点 | 不足・注意点 |
|---|---|---|---|
| 背景・キャラクター・カード・アイコン | オリジナルのSVGコードを作成し、Pythonスクリプトから13点出力 | 配色・形状・サイズをまとめて調整でき、差分確認と再生成が容易。元作品の画像を持ち込まずに統一感を出せた | 絵の表現は簡略化される。小さなSVGを大きく表示すると、Godotのインポート時のラスタライズ解像度に影響される |
| BGM | Pythonのmath・random・struct・waveで探索・戦闘・ボス用の3曲を独自合成 | 場面ごとの音を外部サービスなしで用意できた。固定seedで同じファイルを再生成できる | 作曲・音色の表現には限界がある。全曲を聴いて音楽としての品質を評価したわけではない |
| SE | 同じ仕組みでカード・攻撃・防御の3種類を合成 | 短い効果音は生成条件を変えて調整しやすく、アプリ側の呼び出しと対応させやすい | 音声トラックの存在・非無音の検査だけでは、SEの聞き分けや聴感上のバランスまでは分からない |
| 日本語フォント | Zen Old MinchoのRegularを同梱。OFL-1.1のライセンス全文も同梱 | 世界観に合う明朝体を使え、OSごとの日本語フォント差を避けられた | 約5.2MBの追加になる。文字数が多いカードでは、フォントがあっても表示領域の設計が必要 |

SVGとWAVの計19点は固定seedで再生成し、SHA256が一致すること、SVGがXMLとして読めること、WAVがPCMとして読めることを確認した。WAVは16bit・モノラル・22050Hz。BGMの長さは探索20秒、戦闘15秒、ボス約13.33秒。

フォントの配布元情報：

https://fonts.google.com/specimen/Zen+Old+Mincho

素材ごとの情報をCREDITS.mdへ記録し、OFL.txtとともにエクスポートのinclude_filterへ指定した。クレジット確認スクリプトも成功した。画像生成APIや外部BGM素材サイトは使っていないため、それらの品質・検索性・費用に関する実体験はない。

## 5. 動作確認の方法と、効いた点・不足した点

| 方法 | 使用と結果 | 効いた点・限界 |
|---|---|---|
| headless / selfcheck | 使用。lint・import・起動・selfcheckを含む`make test`成功 | カード全効果、ダメージ、防御、状態異常、山札・捨て札・廃棄の保存、報酬、遺物、休憩、勝敗と再開、seed再現性を検査。描画の見やすさは分からない |
| screenshot.gd | 使用。描画ありで19枚生成し目視 | 通常画面だけでなく、大量手札・ホバー・スクロール・状態異常も確認できた。文字のはみ出しや色の問題を発見できた |
| movie | 使用。30fps・150フレームの起動録画をmp4へ変換 | 起動直後の黒画面・描画崩れの確認に使った。全プレイを録画したものではない |
| CI artifact | 使用。最終CIの19枚のPNG、mp4、ログをダウンロードして確認 | Linuxの描画結果も確認できた。PNG全19枚と録画の1・3・5秒付近の抽出画像を目視した |
| webtunnel | 未使用 | PROJECT.mdにSecrets・WebGL対応の前提が未整備と記載されていたため。Webエクスポートは成功したが、ブラウザ上の実行は未検証 |
| make run | 使用。bootログ、対象PID・作業ディレクトリ・ウィンドウの存在を確認 | エディタなしで起動したことは確認できた。ただしmacOSの画面収録権限が無く、そのウィンドウのタイトル画面を直接撮影・目視するところまでは検証できなかった |

selfcheckは単なるロード確認ではなく、固定seedで通常の選択・カード使用・ターン終了を行い、8階層からボス勝利まで進めた。無抵抗での敗北とタイトルからの再開も確認した。複数seedで選択・報酬・結果が再現することも調べた。失敗時は明示的にエラーと終了コード1を返す形にした。

screenshot.gdはキーボード・ゲームパッドの入力イベントを送って、開始、ノード選択、ターン終了、デッキ・地図の開閉を確認した。大量手札と状態異常の同時表示だけは、撮影用の状態を一時投入して元に戻した。物理ゲームパッドは使用しておらず、接続・機器固有の挙動は未検証。

アニメーションはTweenの途中でタイマーと描画フレームを待ち、ドロー・カード使用・被弾・捨て札の各場面を静止画にして目視した。この方法で被弾数字の見にくさとスクロール領域による捨て札演出の切り取りを見つけ、修正後に再撮影した。ただし連続した動きの滑らかさ、全タイミングでの重なり、操作連打中の見え方までは静止画だけでは判断できない。起動movieはこの戦闘アニメーションを通して再生する検証の代わりにはならない。

movieは動画プレイヤーで全尺再生したのではなく、ffmpegで冒頭・中間・末尾のフレームを取り出して確認した。輝度の検査と音声トラックの非無音確認も実施したが、全BGM・SEの聴感評価は未実施。終了コードだけで成功とせず、各ログ全文をWARNING / ERRORで検査した。

macOS・Windows・Linux・Webへのエクスポートはすべて成功した。Windows・Linuxのエクスポート成果物を各OSの実機で起動した検証は行っていない。macOSの`make run`では画面収録権限が無いことをCoreGraphicsで実測し、既に目視済みのscreenshot.gdのタイトル画像と、今回直接撮れなかった実ウィンドウを区別して報告した。

## 6. Godot固有のハマりどころと回避策

- **音声を再生したまま即終了すると解放警告が残る**：headlessの`--quit`でAudioStreamPlaybackWAVのリークが発生した。`_exit_tree`でstopして参照を外すだけでは解消しなかった。headlessは再生しない、静止画撮影は音量だけでなく再生を停止する、録画は終了10フレーム前に停止する構成で解消した。警告を除外して成功扱いにしたわけではない。
- **InputMapの整数値を誤ると、登録済みでも違うキーになる**：左右キーの設定値を取り違えていた。公式の列挙値を確認し、selfcheckでKEY_LEFT等からInputEventKeyを作ってevent_is_actionで実際の対応を検査した。
- **ScrollContainerは領域外を切り取り、フォーカス移動だけでは期待どおりスクロールしないことがある**：手札・デッキにfollow_focusを設定した。捨て演出はスクロール領域外の表示用ノードで行った。
- **ボタンの見た目は通常状態だけ設定しても足りない**：共通テーマのホバー・押下スタイルが残り、カードの文字色と衝突した。状態ごとのスタイルを揃えて撮影した。
- **SVGも表示時の解像度を考える必要がある**：64pxのアイコンを190px程度に拡大すると、インポート時のラスタライズの影響が見えた。キャラクターなどは表示サイズ以上の原寸で作り、原寸と用途を最初に揃えるのがよい。
- **日本語表示とライセンス文書はエクスポート後も成立させる必要がある**：フォントをテーマへ明示指定し、OSのフォールバックへ依存しないようにした。CREDITSとOFL全文もエクスポート対象へ含めた。
- **CLIの終了コードだけではインポートの異常を見逃す**：ユーザーデータ・エディタ設定への書込みが拒否され、exit 0でもERRORが出た。権限と保存先を確認し、ログ全文を調べて判定した。
- **headless成功は描画成功の証明にならない**：UIの文字、ホバー、クリッピング、描画順の問題は描画ありのスクリーンショットで見つかった。ロジックのselfcheckと実レンダラの画像確認を両方用意する必要があった。

音声終了時のリソース解放については、調査時にGodot側の既報も参照した。今回の回避策はローカルとCIで確認した結果に基づく。

https://github.com/godotengine/godot/issues/76745
