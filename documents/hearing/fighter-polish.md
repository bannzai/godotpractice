## 1. 開発の進め方

### 進めた順序

1. 作業指示書、AGENTS.md、PROJECT.md、issue #4、第1ラウンドのknowledgeとhearingを読んだ。99秒・2本先取、12通常技、ガード、コマンド必殺技、CPU、キーボード／パッド入力を維持する範囲を確認した。ボス・NPC・アイテムは存在しないため追加せず、音楽が盛り上がる場面には最終ラウンドを割り当てた。
2. 変更前の通常起動と23枚のスクリーンショットを確認した。早い段階で方針をknowledgeに記録し、draft PRを作成した。
3. キャラクターの素材・アニメーション、音声、操作録画をサブエージェントへ分担した。担当ファイルを分け、メイン側では多層背景・ロゴ・HUD・Theme・粒子・画面遷移・統合を進めた。検証の最後には、CI artifactの目視と他ゲームの失敗原因調査も独立して分担した。
4. 蒼をスカーフ付きの軽装、燈を大きな籠手と肩鎧の重装として描き分けた。各キャラの独立SVGシートとSpriteFramesを生成し、AnimatedSprite2Dを既存の戦闘状態へ接続した。技の判定や性能を変えず、戦闘側の時間から表示フレームを決めた。
5. 空・街・闘技場・霞の4層背景、タイトルのロゴとキーアート、HPの数値補間と減少跡、ダメージ数字、ヒット・ガード・KOの粒子、画面揺れ・フラッシュ・フェード、ボタンの反応を追加した。音楽はタイトル・通常対戦・最終ラウンド・結果の4曲へ分けた。
6. selfcheck、連続フレーム撮影、29秒の操作録画で不具合を探して修正した。修正後は画像と動画を撮り直し、通常終了と `--quit-after` の終了、各OS向けエクスポートも確認した。
7. pushしたブランチをwebtunnelで開き、CPUとの通常の対戦から結果まで進めた。Webでのみ見つかった再戦ボタンの欠字を修正し、再度Webとローカルで確認した。最後にCI artifactを目視し、PUTSで画像66枚とプレイ動画を公開してPRへ掲載、知見を追記し、PRをレビュー可能にした。

### 詰まった点と解決

- **最初の通常起動がsandbox内で異常終了した。** Godotが必要とするユーザーデータやキャッシュへのアクセスが制限されていた。許可されたmacOSの実行環境で同じ起動経路を使い、タイトル画像と `fighter run OK`、exit 0を確認した。
- **KO姿勢が別の動作に混ざった。** 回転したKOの絵がスプライトシートのセル境界を越えていた。姿勢をセル内部に収め、全352セルの透明な外周を機械検査するようにした。空中の影も床から浮いていたので、キャラの画像から分離して床の高さに描いた。
- **終了時の音声リソースが残った。** 通常の終了通知だけでは `--quit-after` を扱えず、固定fpsのフレーム待ちもミキサーの実時間の解放待ちにならなかった。音声停止、stream参照の解除、ネイティブの終了時の250ms待機を組み合わせ、両経路を再検証した。
- **Webで再戦ボタンの「↵」が欠字になった。** macOSとLinuxの画像では表示できていたが、Webでは四角い欠字になった。文言を「もう一度対戦」に変更し、Webの結果画面を撮り直した。
- **PUTSのKeychain読み取りが失敗・待機した。** 最初の実行はOSStatus -25291で失敗し、別の実行環境でも読み取りが完了しなかった。新しいキーは発行せず、設定済みのGitHub画像用R2認証をPUTSが対応する環境変数へ渡してアップロードした。認証情報の値はログやファイルへ残していない。
- **最終の文書更新で、変更していないcrewrtsのCIだけ失敗した。** artifactのログでは撮影とGodotの終了はexit 0だが、終了時にObjectDBとresourceのリークが出ていた。直前の成功実行とコード差分を確認してから再実行し、全28ジョブが成功した。他ゲームのコードは変更していない。漏れた型が分からず、音声由来とは断定していない。

## 4. 素材の準備方法と使い勝手

### キャラクター画像とアニメーション

`generate_characters.py`で、蒼・燈それぞれの独立SVGシートとSpriteFrames、別構図のポートレートを生成した。各キャラ22動作×8フレームで、合計352セル。顔、体格、装備、服装のパスを分け、色の違いだけに頼らないデザインにした。

手続き生成は、輪郭や関節位置、セルの余白を修正して全フレームへ反映する作業に向いていた。ソースから同じ出力を作り直せるため、再現性の検査もしやすい。一方、動きが規則的になりやすく、構図・誇張・中割りの魅力まで自動的に良くなるわけではない。将来の商品制作では、原画や動きの美術調整を加えるかが判断点になる。

### 舞台・飛び道具・UI

`generate_stage.py`で、空・街・闘技場・霞、打撃・ガードの図案、形の異なる2種類の燈波、HP枠・ラウンドの印・タイトルロゴを生成した。背景を4枚に分けたことで移動量を変えられ、パララックスの調整が簡単だった。SVGは配色や寸法を揃える用途に使いやすかった。

ロゴは同梱フォントの文字をfontToolsで輪郭化した。SVGのテキスト表示をOSや閲覧環境へ依存させずに済む。一方、文字の変更時には生成スクリプトを再実行する必要がある。

### BGM・SE

`generate_audio.py`で、Python標準ライブラリを使って4曲と5種類の効果音を合成した。固定乱数のノイズ、倍音、FM、非整数倍の共鳴、時間による音量変化を組み合わせ、単純な正弦波だけの音から音色を増やした。

| 場面・用途 | 準備方法 |
| --- | --- |
| タイトル | 96 BPM。ベル・パッドを中心とした構成 |
| 通常対戦 | 128 BPM。ベースと打楽器でリズムを付けた構成 |
| 最終ラウンド | 160 BPM。ブラス系の音色などで強さを変えた構成 |
| 結果 | 112 BPM。ベルなどを使った別の旋律 |
| 効果音 | 打撃・ガード・必殺技・決定・KOを別のWAVとして生成 |

外部の録音・楽曲・音色サンプルの調達が不要で、同じ条件から再生成できる点は扱いやすかった。非無音・クリップの有無・音量・再生成一致は確認できたが、実際に耳で聴いた評価はしていない。聴感上の完成度、ループの自然さ、長時間聴いた時の印象までは数値検査で保証できない。

### フォント・出典・クレジット

第1ラウンドから同梱されていたNoto Sans JPを継続利用した。今回、新しいフォントをダウンロードしたわけではない。OFL全文を保持し、配布物へクレジットとともに含める構成を維持した。

フォントの取得元として記録されているページ：

https://fonts.google.com/specimen/Noto+Sans+JP

https://github.com/google/fonts/tree/main/ofl/notosansjp

画像・音声は独自制作として制作方法と生成条件をCREDITSへ記載し、生成物であることを理由にCC0とは扱わなかった。`check-credits.sh`は成功した。最終の再生成比較では、SVG・tres・WAVの30ファイルが変更前と同じハッシュになった。

今回は外部の画像・BGM・SE素材集や画像生成APIを利用していないため、それらの検索効率や作風の揃えやすさを、実際に比較したとは言えない。

### アニメーションをどう検証したか

各キャラの動作一覧では8フレーム中の開始・途中・終了を横に並べた。これに加え、全352セルの外周が透明であることを検査し、回転や伸ばした手足が別セルへはみ出す問題の再発を防いだ。実際の対戦映像でも動きを確認し、描画用のフレームがヒットストップ中に進まないことや、KO後に倒れきることを検査した。

操作動画は2秒間隔で一覧化したが、それだけでは短い技の途中を飛ばしてしまう。ジャンプと必殺技の周辺は0.1秒間隔でも抽出した。KOセルの混入と空中の影の問題は、静止画と細かい時間間隔のフレームを組み合わせて確認・修正した。すべての動画フレームを目視したわけではなく、滑らかさの確認にはこの抽出間隔による限界がある。

録画では15秒と22.5秒以降、CPUが体力で上回っている時だけ残り時間を0.05秒へ短縮した。HP・ダメージ・勝敗を直接置き換えず、実際の時間切れ判定で結果まで進めるための仕組みで、通常ゲームとエクスポートには入らない。99秒を実時間で待った映像ではないことをREADMEとPRに明記した。

録画の音量は、29秒の操作動画が平均−26.0dB・最大−6.7dB、5秒の起動動画が平均−25.6dB・最大−12.9dBだった。これは録音・非無音・過大なピークを検査する材料であり、音楽の聴感評価の代わりではない。

物理コントローラーの実機操作は未検証。キーボードとパッドの入力経路はGodotのイベント注入で検証した。Windows上の手操作も行っていない。ゲームとして長く遊んだ時のバランスや面白さを網羅的に評価した作業ではない。

## 6. Godot固有のハマりどころと回避策

### 今回の追加・修正で確認したこと

| 問題 | 回避策 |
| --- | --- |
| AnimatedSprite2Dを独立した時間で再生すると、ヒットストップ中も絵だけが進む | 戦闘側の発生・持続・硬直時間から表示フレームを選ぶ。被弾の開始位置は命中ごとに更新し、KOだけは入力停止後にも演出時間を進める |
| スプライトシート内のKOの回転が隣のセルへ越境する | 回転後もセル内に収まる姿勢へ修正する。Godotがインポートした画像で全セルの透明な余白を検査し、連続画像でも確認する |
| キャラと同じ画像に入れた影がジャンプで浮く | 影を分離し、キャラの高度にかかわらず床の高さへ描く。高度に応じて影の大きさと濃さを変える |
| KOで戦闘時間を止めると、被弾フラッシュも残る | ラウンド終了時に被弾・ガードのフラッシュを解除する。HPの数値と減少跡もKO時は0に揃える |
| `AudioStreamPlayer.stop()`直後でもミキサー側のリソースが残る | 音声開始を抑止し、音量Tweenを止め、playerを停止してstream参照を外す。解放待ちを入れて通常終了とエンジン側の終了を別々に確認する |
| `--quit-after`では通常のウィンドウ終了通知を通らず、`OS.get_cmdline_args()`にもそのオプションが残らない | 終了前処理を通常通知だけに依存させない。共通の `_exit_tree` にも停止・解放処理を置く |
| `--fixed-fps`でのフレーム待ちは、ミキサーの実時間の待機を保証しない | ネイティブ版の終了時には250msの実時間待機を置いた。Webではブロッキング待機を行わない。これは今回の構成で検証した対策で、どのプロジェクトでも250msで十分とは断定しない |
| SceneTreeの検証スクリプトでメインシーンを早くpreloadすると、autoload参照がまだ使えない | `_initialize`から遅延実行した検証処理内でメインシーンをloadする |
| 検証用PNGがプロジェクト内のリソースとして再インポートされる | import targetで検証用ディレクトリに `.gdignore` を作り、画像一覧や録画用の一時成果物をGodotの探索対象から外す |
| ローカルの代替フォントが、同梱フォントの欠字を隠す | Webエクスポートでも実際にUIを撮影する。今回は「↵」を除いた文言へ変更した |

GL Compatibilityは維持した。今回必要な表現はCPUParticles2D、Tween、CanvasItemシェーダで実現できた。レンダラを変えたり、高度な照明の仕組みを導入したりする必要はなかった。

### 第1ラウンドから引き継いだ注意点

可変フォントの太さには `name_to_tag("wght")` の整数タグを使うこと、WAVのループ終端をimport設定で指定すること、型付き配列の状態投入には `assign()` を使うこと、Area2Dの接触検査では物理フレームの更新を待つことは、既存knowledgeと実装を参照して維持した。これらをすべて今回ゼロから発見・修正したわけではない。

### Godotを外部ツールから扱う時の注意点

webtunnelの資料にあった例の8080番へ最初に接続して失敗したが、このリポジトリのcaller workflowは8000番を使っていた。実ファイルを確認して接続先を直した。また、runnerの再作成でCDPのIPが変わった後もagent-browserの専用セッションが旧IPを保持していたため、そのセッションだけを閉じてから接続し直した。

GodotのWebシェルは起動成功後に `#status` 要素を取り除くため、HTTP応答だけでなくその状態と実スクリーンショットを確認した。CDPへの接続は成功しても、ゲームが起動済みとは限らない。Webの描画確認、ネイティブの終了処理、headlessのロジック検証をそれぞれ実行したことで、単独の方法では見つからない問題を補えた。
