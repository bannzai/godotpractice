# kartrace 手直しラウンド ヒアリング

## 1. 開発の進め方

### 着手前の把握

1. `AGENTS.md`、`documents/PROJECT.md`、issue #38、前ラウンドの PR #53、既存の `documents/knowledge/kartrace.md` を読んだ。main にないヒアリング文書は GitHub API で対象ブランチから取得した。
2. `make kartrace-run` で既存版を実際に起動し、タイトル、コース選択、レース中のそれぞれで「次に何をすればよいか」「他ゲームと見分けられるか」を確認した。
3. 近い役割の他ゲームのタイトル、ステージ選択、プレイ中の画面を集めた。既存版は、淡い配色、丸い共通パネル、画面下の一行操作ガイド、手続き SVG という共通要素が強く、レース固有の情報や素材が弱いと判断した。
4. 素材探索、現行実装の構造調査、過去仕様の調査を並行し、変更範囲を `games/kartrace/` と `documents/knowledge/kartrace.md` に固定した。早い段階で draft PR #74 を作り、途中経過を commit・push した。

### 実装した順序

1. Potta One と80年代アーケード向けの色を入れ、タイトルを「ドライバー選択」と「次はガレージ」の二つの役割へ分けた。選択中のカード、決定操作、選択後の行き先が同時に見える構成にした。
2. コース選択をガレージの壁ポスターへ置き換えた。走れるコースは点滅とプレビューで示し、残りのポスターには選べない理由を直接表示した。
3. コース、山、設備、カートを `SurfaceTool` / `ArrayMesh` の低ポリ頂点カラーへ変更し、空のグラデーション、紫の路面、原色の縁石を追加した。CC0 の観客とゴール看板だけをドット絵 Sprite3D として配置した。
4. レース HUD を、アナログ速度計、ギア、周回、時間、アイテムへ組み直した。順位は画面上のパネルから外し、コース脇の3D電光掲示板へ移した。画面下の共通操作ガイド行は撤去した。
5. 初回だけ表示する「アクセル、ハンドル、ドリフト」の3段階チュートリアルを追加した。時間経過ではなく、通常プレイと同じ入力を実際に受け取った時だけ次へ進み、Enter / A または Escape でスキップできるようにした。
6. 既存 BGM / SE を維持しながら、ガレージのネオン環境音とレース中の観客環境音を決定的な Python 生成器へ追加した。
7. selfcheck、実入力統合テスト、37場面の `screenshot.gd`、3車種のアニメーション一覧を追加・更新し、見つかった不具合を直した。
8. ローカルの全検証後に webtunnel で Web 版を実操作し、CI artifact を目視した。変更前後、他ゲームとの識別、アニメーション、Web実操作を比較画像へまとめ、puts で PR 本文へ添付した。

### 詰まった点と解決

- 完成済みのレース素材一式で、CC0、必要な画風、必要な部品を同時に満たす候補がほとんどなかった。用途を「観客」と「ゴール看板」まで小さく分解し、大部分は頂点カラーで自作する方針へ変えた。
- `JoypadMotion` は一度傾けても複数フレーム届くため、タイトルの車種が一度に複数移動した。軸が中央へ戻るまで再入力を受けないラッチを入れ、複数の対応軸を回帰テストした。
- 復帰地点のY座標が路面と同じで、カートが路面下へ沈む場合があった。路面の高さに上向きの余白を足し、復帰後の位置を selfcheck で検証した。
- 被弾時に速度だけを落としていたため、被弾後もドリフト蓄積が残った。ドリフト時間、入力、向きをまとめて初期化し、実入力統合テストを追加した。
- webtunnel では最初に8080番ポートを開いて接続できなかった。caller workflow の実際の配信ポートが8000番だと確認して修正した。また、CDP の ArrowUp 長押しで加速が継続しなかったため、同じゲーム入力へ割り当てた `W` の長押しで実操作を継続した。
- CI は変更していない citybuilder のスクリーンショット終了時リーク検知だけが2回不安定に失敗した。kartrace の全ジョブと artifact が正常なこと、citybuilder に差分がないこと、ログ上の失敗箇所を確認し、範囲外のゲームは変更しなかった。失敗ジョブの3回目で全ジョブが成功し、最終文書コミット後の新しい CI も64ジョブすべて成功した。

## 2. 使ったツール・skill・コマンド

### skill と補助ツール

- `godot-development`: Godot 4.7 の起動、sandbox 用環境、import、headless 検証、export、ログの見方を確認した。
- `game-asset-search`: CC0 / Public Domain / OFL に候補を絞り、配布ページ、アーカイブ、採用ファイル、クレジットの対応を確認した。付属の `check-credits.sh` でも `assets/CREDITS.md` を検査した。
- `webtunnel`: GitHub Actions runner 上の Web エクスポートを software WebGL で起動し、Tailscale / CDP 接続、Godot座標とブラウザ座標の扱い、終了処理に使用した。
- `agent-browser`: `kartrace` という専用セッションとCDP接続を使い、タイトルから結果画面まで通常のキー入力で操作し、DOM、コンソール、ページエラー、スクリーンショットを取得した。
- `pr-attach-screenshots`: PNG と動画末尾を puts へまとめて渡し、PR本文の画像区間だけを更新した。最後の再実行では `UPLOADED=0`、`REUSED=8`、`BODY_CHANGED=0` となり、公開URLとローカルのSHA-256一致も再確認できた。
- `commit` / `commit-create-pr`: 公開リポジトリ向けの差分、秘匿情報、個人情報、commit構成、draft PR本文の確認手順として使用した。

### 主なコマンド

- Godot / Make: `make import GAMES=kartrace`、`make test GAMES=kartrace`、`make screenshot GAMES=kartrace`、`make movie GAMES=kartrace`、`make -C games/kartrace movie-play`、`make build-all GAMES=kartrace`、`make build-web GAMES=kartrace`、`make kartrace-run`
- lint: `gdlint`。直接の入口は `make lint` と `make test` を使用した。
- 動画・画像: `ffmpeg` / `ffprobe` で動画情報、連続フレーム、末尾フレームを確認し、ImageMagick の `magick montage` で37画面、アニメーション、変更前後、識別テストの一覧を作った。
- 素材生成: `python3` の決定的な生成スクリプトで WAV を作り、再生成前後の SHA-256、サンプルレート、量子化ビット数、チャンネル数、長さ、ピーク、RMS を検査した。
- Git / GitHub: `git diff`、`git status`、`git log`、`gh issue view`、`gh pr create/edit/ready/checks/view`、`gh api`、`gh run view/watch/rerun/download` を使用した。
- 配布と照合: `puts ls`、`puts upload`、`curl`、`shasum`。実際のアップロードと検証は `pr-attach-screenshots` のスクリプト経由で行った。
- 調査: `rg` で対象ファイル、禁止フォント、共通操作ガイド、WARNING / ERROR、変更範囲を検査した。

## 3. 欲しかったが無かったツール・skill・スクリプト

- ゲーム内の役割を入力すると、CC0 配布ページのライセンス表記、配布アーカイブ内のファイル、採用候補のハッシュ、`CREDITS.md` の雛形まで一度に照合するツール。`check-credits.sh` は記録後の整合確認には効いたが、探索中のページとアーカイブの照合は手作業だった。
- 各ゲームの「タイトル、ステージ選択、プレイ中」を同じ大きさで収集し、ゲーム名付きの識別テスト画像を作るスクリプト。他PRの公開画像を探してダウンロードし、手動で並べた。
- `screenshot.gd` の出力へ場面名を付け、全PNGの欠落、解像度、黒画面、代表色、ログを検査し、目視用 contact sheet まで生成する共通スクリプト。今回は37枚の一覧を ImageMagick で都度作った。
- 3Dモデルについて「車種 × idle / drive / drift / boost / hit / celebrate × 開始 / 中間 / 終了直前」を宣言すると、撮影と一覧生成を行う Godot 用テスト補助。今回の撮影コードは kartrace 固有になっている。
- webtunnel の起動、CDP取得、Godotキャンバス座標からブラウザ座標への変換、キー入力シナリオ、画面収集、録画取得、終了確認を一つにした Godot Web E2E ランナー。現状のskillには必要な部品はあるが、ゲーム固有の一連操作は手動で組み立てた。
- `documents/knowledge/<slug>.md` の変更を対応するゲームだけのCIへ割り当てる変更ゲーム判定。現在はゲーム固有の知見だけを更新しても21ゲーム・64ジョブが走り、今回のように無関係なゲームの不安定な終了警告へ影響される。
- CI run ID とゲームslugを渡すと artifact を取得し、ログ全文検査、PNG一覧、動画末尾抽出、目視用一覧作成まで行うスクリプト。現在は `gh run download`、`rg`、`ffmpeg`、`magick` を個別に実行した。

## 4. 素材の準備方法と使い勝手

### 画像と3D表現

- 観客には OpenGameArt の「Summer Otters w/ Signs」、ゴール看板には「2.5D Racing Resources」を使用した。どちらもCC0として配布ページの表示と配布物を照合し、取得元URL、ライセンス、加工内容を `assets/CREDITS.md` に記録した。画像そのものを描き直さず、Godot の region で必要なコマを切り出し、nearest filtering と billboard で表示した。
- CC0素材は作者固有のドット表現を少量入れられ、手続き図形だけの画面より特色が出た。一方、配布ページのライセンスとダウンロードしたアーカイブの中身が本当に対応しているかを人間が確かめる手間が大きい。完成済み素材一式を探すより、画面内の小さな役割へ分けて探す方が早かった。
- カート、コース、山、設備は `SurfaceTool` / `ArrayMesh` と頂点カラーで生成した。外部テクスチャとUVが不要で、配色をコードから一括調整でき、再生成性と3D全体の一貫性が高い。一方、面の向き、裏面、頂点色の付け忘れ、全カメラ角度でのシルエットは画像素材より確認箇所が多い。
- 前ラウンドの手続き SVG は、権利確認が不要、差分が読める、決定的に再生成できる点が扱いやすかった。ただし、同じ太線、角丸、配色、部品構成を複数ゲームへ使うと題材が違っても同じ見た目になりやすかった。今回はドット絵を限定的に使い、残りを頂点カラーにすることで、素材集そのままにも共通テンプレートにも見えにくくした。

### フォント

- Google Fonts の公式配布物から Potta One を取得し、TTFとOFL-1.1本文を配置した。公式配布元とライセンスが明確で、採用手順は簡単だった。Godot の import 後に日本語グリフ、文字幅、見出しと小さい補足文の可読性を各画面で確認する必要はあった。
- 禁止された M PLUS Rounded の実ファイルと参照を除き、Zen Old Mincho、Noto Sans JP、無名の `font.ttf` が残っていないことを `rg` で検査した。

### BGM・SE・環境音

- 既存の場面別 BGM / SE は操作感を壊さないため維持し、ガレージのネオン音とレースの観客音だけを既存の Python 生成器へ足した。外部音源の権利確認が不要で、パラメータから同じ WAV を再生成できる点は非常に扱いやすかった。
- 生成後は再生成前後の SHA-256 一致、22050 Hz / 16 bit / mono / 4秒、ピーク、RMS、非無音、非クリップ、Godot import とロードを確認した。数値検査と再現性には強いが、「世界観に合って聞こえるか」という聴感の最終判断は自動化できず、今回は未検証として区別した。
- 画像生成モデルや音声生成サービスは使っていない。今回の割り当てだった「低ポリ頂点カラー + 一部CC0ドット絵」と、既存の決定的な音声生成器だけで構成した。

## 5. 動作確認の方法

### headless とロジック検証

- `make test GAMES=kartrace` で import、`gdlint`、boot check、integration、selfcheck をまとめて実行した。selfcheck には通常の受け入れ条件に加え、初回チュートリアルの入力進行、ゲームパッド軸ラッチ、復帰高度、被弾時のドリフト初期化を追加した。
- headless は状態遷移、計算、入力イベント、終了コード、ログ全文の検証には速くて有効だった。一方、レイアウト崩れ、文字切れ、頂点色、Sprite3Dのにじみや裏面、黒画面は判定できないため、これだけでは完了にしなかった。

### `screenshot.gd` とアニメーション

- `make screenshot GAMES=kartrace` で、タイトル、選択ハイライト、ガレージ、チュートリアル、カウントダウン、走行、各アイテムと効果、ドリフト、ブースト、被弾、復帰、ゴール、結果を撮影した。
- アニメーションは3車種について idle、drive、drift、boost、hit、celebrate の6状態を、開始、中間、終了直前の3フレームで撮った。通常場面と合わせて37枚になり、一覧画像と原寸の代表画面を目視した。単一の静止画だけでなく3時点を並べたことで、ポーズが変わらない、途中で形が崩れる、終了前だけ戻るといった問題を見つけやすくした。
- `screenshot.gd` は多数の状態を決定的に再現するのに効いたが、実際の操作でその状態へ到達できることや、フレーム間の動きの滑らかさは保証しない。この不足をmovieとWeb実操作で補った。

### movie、ローカル起動、CI artifact

- `make movie` の5秒起動録画で、起動直後の黒画面、タイトル描画、終了処理を確認した。`make -C games/kartrace movie-play` では実入力シナリオを録画し、2秒間隔のフレームと末尾を見て、タイトルからレース中までの連続性を確認した。
- `make kartrace-run RUN_ARGS="--script res://scripts/dev/run_smoke.gd"` で実ウィンドウを開き、GL Compatibilityで起動して正常に閉じることを確認した。headlessや録画だけでは拾えないローカルGUI起動経路の確認になった。
- CI run 34104258814 は最終コミットに対する全21ゲーム・64ジョブが成功した。kartrace artifact の37枚、5秒動画の末尾、ログ全文を取得して目視した。Linux + llvmpipeでも見た目と終了時リークが壊れていない確認になった。V-Syncを変更できないというCI描画環境固有の通知は出るが、ゲーム由来のエラーやリークはなかった。
- CI artifact はプラットフォーム差の確認には効いたが、software renderingで実時間より遅く、操作感やデスクトップ固有機能は評価できない。Windows / Linux実機でのプレイ確認も行っていない。

### webtunnel

- browser-session run 34100792975 で `fix/kartrace` の Web エクスポートを起動し、専用の `kartrace` セッションから通常のキー入力だけを送った。車種変更、ガレージ、実入力3段階チュートリアル、アクセル、操舵、ドリフト、Pulse、Turbo、3周完走、結果画面、Escapeでタイトル復帰まで確認した。結果は41.33秒・3位、ページエラー0件で、コンソールはGodotの情報と `kartrace boot` だけだった。
- webtunnel は「画面がある」だけでなく、実際のユーザー入力で最後まで到達できること、WebGL描画、ブラウザのエラーを同時に確認できた。SwiftShaderではゲーム進行が実時間より遅いため、固定時間待機ではなく周回表示と結果画面を撮影して完走を判定した。
- 終了時は長押しキーを解放し、agent-browserを閉じ、webtunnelをdownした。録画の末尾がタイトルへ戻っていることも確認した。実機ゲームパッド、フルスクリーン、デスクトップ固有入力はWeb版では検証できない。

## 6. Godot 固有のハマりどころと回避策

- `SurfaceTool` の頂点カラーは、各頂点を追加する前に `set_color()` し、生成後の `StandardMaterial3D.vertex_color_use_as_albedo` も有効にする。どちらか片方だけでは設定した色が画面に出ない。
- 透明部分を含むドット絵の Sprite3D は、nearest filtering、region、billboardを明示する。遠景や看板と重なる角度では、正面だけの確認ではにじみ、向き、奥行き順を見落とすため、実際の走行カメラから撮影する。
- アナログ速度計を `Control._draw()` で描く場合、速度値を変えただけでは再描画されない。描画ノードを毎フレーム作り直さず、値を更新して `queue_redraw()` を呼ぶ。順位掲示板も既存Labelの文字だけを更新し、表示側からレース状態を変えない。
- `JoypadMotion` は一回の傾きが連続イベントになる。メニューの左右移動は軸が中央へ戻るまでラッチしないと複数項目を飛び越える。キーボードだけでなく複数のゲームパッド軸を入力イベントの回帰テストへ含める。
- 3Dカートの復帰位置は路面のY座標そのものでは不足する。車体の原点と当たり判定を考慮した上向きの余白を加え、復帰直後の座標を自動検証する。
- 被弾やリスポーンのような割り込み状態では、速度だけでなく、ドリフト経過時間、入力フラグ、向き、エフェクトを一つの処理で初期化する。関連状態の一部だけを戻すと、次のフレームで古い状態が再適用される。
- sandbox内の通常Godotは、エディタ設定や `user://` の補助ディレクトリへ書けず失敗することがある。`godot-development` のsandbox向け準備で作業ディレクトリ内に自己完結した環境を用意し、GUI確認だけ許可された通常起動で行った。
- GL Compatibilityのsoftware WebGL / llvmpipe / SwiftShaderでは、描画とゲーム進行が実時間より大幅に遅くなる。実時間の待機秒数ではなく、画面上の周回、結果、`kartrace boot`、終了ログを成功条件にする。
- headlessの終了コード0だけでは、文字切れ、黒画面、Sprite3D、頂点色、アニメーションを保証できない。selfcheck、決定的スクリーンショット、連続フレーム、movie、ローカルGUI、CI artifact、Web実操作を役割ごとに組み合わせる必要があった。
