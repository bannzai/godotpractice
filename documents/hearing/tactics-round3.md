# tactics 開発ヒアリング

対象は issue #41 の戦術RPG「暁の境界」。Godot 4.7／GDScript／GL Compatibilityで、16×12のマップ３章を実装した。実装・検証の記録、成果物、開発知見をもとに振り返る。

PR: https://github.com/bannzai/godotpractice/pull/56

## 1. 開発の進め方

### 何をどの順に作ったか

1. 作業指示書、issueの受け入れ条件、プロジェクトの制約、Godot関連のskillと既存ゲームの実装・検証方法を確認した。ゲーム本体の変更は `games/tactics/`、共有物への提案は `documents/knowledge/tactics.md` に閉じた。
2. 素材・音・キャラクター動作、戦闘ロジック、撮影・録画などの検証スクリプトをサブエージェントへ分担した。担当ファイルを分け、自分はメイン画面、操作、全体の接続と検証を進めた。
3. マップ・配置・兵種を `battle_data.gd`、計算を `battle_rules.gd`、進行と保存をautoloadの `Campaign` に分離した。タイトル→盤面→勝敗→タイトルの流れに、移動、攻撃予測、敵フェーズ、３章の勝利条件、保存再開を接続した。
4. 最初の実装コミット `da9d479` でdraft PRを作成した。この時点で３章と入力検証まで入っており、指示された「最小ループだけで早くdraftを出す」より初回の差分は大きかった。次回はループ成立時点で一度公開すると、進捗と実装の区切りを追いやすい。
5. キャラ別SVG、本体と武器の動作、多層背景、Theme、BGM／SEを統合した。盤面上の小さなキャラでは攻撃動作が伝わりにくかったため、交戦する２人を拡大する画面を加えた。
6. 計算のselfcheckに加え、本番シーンへの実入力テスト、代表画面撮影、28秒のプレイ録画を繰り返した。検出した不具合を修正し、`d37b2e1` で演出・保存・検証を仕上げた。
7. 全デスクトップ／Webエクスポート、CI artifactの目視、webtunnelの実操作を実施した。PNGと動画をputsでアップロードしてPRへ添付し、知見追記を `903a44c` でコミットした。最終CI成功とPR本文の一致を確認し、ready for reviewにした。マージはしていない。

### 詰まった点と解決

- **表示は正常でもクリックが届かなかった。** 背景のControlが入力を消費していた。`mouse_filter` を整理し、合成入力ではOSのポインタ位置ではなくイベント自身の座標を使った。見た目の撮影だけでは見つからず、実入力テストが効いた。
- **正しく保存したデータを再開できなかった。** JSONで数値がfloatとして戻る点を考慮せず、int配列との比較で拒否していた。整数性と範囲を検証してから復元するようにした。
- **移動取消と薬・保存の組み合わせで状態が崩れた。** 満HPで薬を使おうとした時も選択を解除していた。無効操作では選択を保ち、保存前には未確定の移動を取り消すようにした。
- **全員死亡した保存の再開で空配列参照になった。** 生存者の先頭を前提にせず、主人公の定義をIDで取得して結果画面へ戻した。
- **演出を足すと重複表示が出た。** 交戦画面と盤面のダメージ数字が二重に出ていた。録画フレームから発見し、交戦画面表示中の盤面側の数字を抑えた。
- **描画・接続・取得の問題がゲームの問題と混ざった。** macOSのsandbox制約、agent-browserのdaemon待機、artifact本体の転送遅延を別々に調査した。通常権限でのGodot起動、同じChromiumへの直接CDP接続、artifactの分割取得で先へ進めた。
- **利用上限で検証途中に停止した。** 再開時はコミット、取得済み画像、CI状態を確認し、未完了だったWeb実操作から続けた。期限で終了していたwebtunnelを起動し直し、最後は明示的にdownした。

主な実行入口は次のとおり。すべて最終版でexit 0を確認した。

```bash
make test GAMES=tactics
make screenshot GAMES=tactics
make movie GAMES=tactics
make -C games/tactics movie-play
make build-all GAMES=tactics
make build-web GAMES=tactics
make tactics-run RUN_FLAGS='--script res://scripts/dev/runcheck.gd'
```

最後の起動コマンドは、通常のゲーム起動入口にF11操作と通常終了を行う検証スクリプトを渡したもの。物理キーボードを人が操作して閉じたという意味ではない。

## 3. 欲しかったツール・skill・スクリプト

今回そのまま流用できるものを見つけられず、ゲーム固有または一時スクリプトで補ったものを挙げる。現在のskill一覧に存在しないと断定する趣旨ではない。

- **全キャラ・全動作を指定時刻で並べる撮影部品。** キャラ一覧、動作名、開始・途中・終了の時刻を渡すだけで、注記付きPNGと一覧を生成したい。今回は `screenshot.gd` に組み込んだ。godot-developmentへの追加候補。
- **本番InputMapを通す入力・待機の共通部品。** キー、パッド、スティック、マウスを送り、演出完了を待ち、画面と状態を検査する処理を各テストで書いた。移動取消やフォーカスを含むサンプルがあると手作業が減る。
- **通常終了・quit-after・音声ドライバ別の解放検証。** BGM再生中に終了してログ全文を検査する一括処理を、初期雛形に入れておきたい。録画だけでは実音声ドライバの問題を十分に拾えない。
- **証拠の撮影・一覧化・アップロード・PR反映の連携。** 今回はファイルのSHA256とURLを保存する一時スクリプトを作り、変更したファイルだけを再アップロードした。ファイル名から日本語キャプションを付け、公開先の原本一致まで確認できると便利。
- **webtunnelの段階別診断。** HTTP到達、CDP接続、Godot読み込み完了、撮影、実入力を別々に判定し、16:9のゲーム座標変換と終了処理まで面倒を見てほしかった。接続成功でも撮影は失敗し得る。
- **artifactの転送遅延への回復手段。** 一覧APIが正常なのにZIP本体が進まない時、タイムアウト・再開・分割取得・CRC検査を自動化できると待ち時間を減らせる。
- **ゲーム別知見とCI対象の対応。** `documents/knowledge/tactics.md` だけの変更でも共有変更として全10ゲームのCIが動いた。対応するゲームだけを検証する判定を共有物への改善案として記録した。今回その共有コードは変更していない。

## 4. 素材の準備方法と使い勝手

### 画像

`scripts/art/generate_art.py` で43個のSVGを手続き生成した。内訳は10キャラそれぞれの全身・本体・武器の30個、背景４個、地形５個、UI４個。原作の画像・名前・ロゴは使っていない。

味方５人と敵５種は、武器だけでなく頭身、兜、フード、盾、法衣などの輪郭を変えた。本体と武器を別画像にしたことで、同じAnimationPlayerでも振りかぶり・振り抜きを独立して表現できた。

手続きSVGは色や輪郭の修正、透過、再生成、差分確認に向いていた。小さい盤面の可読性も調整しやすい。一方、少ない形だけでは似た人形になりやすく、表情や装備の描き分けは自分で設計する必要があった。今回の切り絵調には合ったが、写実的なキーアートや手描きの連続作画を得る手段として評価したわけではない。

タイトルの人物絵に背景まで含めると矩形の境界が目立ち、拡大すると背後の視差が見えなくなった。人物だけを透過させ、空・遠山・手前の草木を別層にすると収まりがよくなった。

### BGM・SE

`scripts/art/generate_audio.py` で波形を合成し、一時WAVからffmpegでOgg Vorbisへ変換した。BGMはタイトル・盤面・交戦・結果の４曲、SEは攻撃・回復・成長・決定の４種。独自旋律と、倍音を持つ笛・撥弦・持続弦・ベル・打楽器、左右定位を組み合わせた。

コード生成は長さ、音量、音色の組み合わせを調整でき、第三者音源のライセンス調査を減らせた。反面、楽器らしさや曲の展開は自分で作る必要があり、生成しただけで音楽としての完成度を保証できるものではない。PCMへ戻して非無音・非クリッピングを検査したが、この検査だけでは聴き心地や繰り返し聴いた時の疲れを判断できない。

固定seedだけではOggの再生成一致が得られず、ffmpegの出力側にも `-fflags +bitexact` を指定してSHA256を一致させた。中間WAVはassetsに混ぜずtmpへ出した。

### フォント・素材源

Zen Old Mincho Regularを、既存deckrogueに入っていた未改変ファイルからコピーし、OFL全文を同梱した。上流は次のリポジトリ。日本語表示を早く整えられ、ゲームの静かな雰囲気にも合わせやすかった。

https://github.com/googlefonts/zen-oldmincho

画像・音は独自生成、外部素材はこのフォントを利用した。出典、ライセンス、生成方法は `assets/CREDITS.md` に記録した。画像生成APIや外部のBGM／SE素材集は使用していないため、それらとの実使用比較はしていない。

## 5. 動作確認の方法と効いた点・不足した点

### headlessのselfcheckと実入力テスト

`selfcheck.gd` で地形探索、占有、戦闘予測、三すくみ、射程、追撃・反撃、生死、AI、成長、保存データの解釈を検証した。個別計算に加え、seed 7・41・2026で、HPを書き換えず通常APIだけを使って全３章を攻略した。局所的な計算が正しくても、章進行が成立しない問題を防ぐのに有効だった。

`integration.gd` は本番シーンに `Input.parse_input_event` で入力した。タイトル開始、主人公選択、移動、無効な薬使用、取消、パッドA／B／Start、左スティック、マウス、保存再開、通常の敵攻撃による敗北、タイトル復帰を検査した。全員死亡状態の再開は別の検証用状態を作って確認した。保存先は専用の `user://tactics-integration-test.json` に分けた。

headlessは速く、ロジックと操作経路の退行検出に向く。一方、フォントの欠け、レイアウト、効果の見え方は判定できず、描画付きの検証が必要だった。

### screenshot.gdとアニメーション

`_capture_scenes()` で24 PNGを生成した。タイトル、３章、移動範囲、戦闘予測、交戦、操作説明、フェーズ、各効果、勝敗・エンディングを含む。

キャラ動作は10種×７動作（待機・選択・移動・攻撃・被弾・回避・撃破）×開始・途中・終了を、動作ごとの一覧画像にした。`AnimationPlayer.pause()` と `seek(time, true)` で時刻を固定し、本体と武器の位置関係や画面外へのはみ出しを確認した。

全キャラを同じ時刻で比較できる一覧は、確認漏れを減らすのに効いた。ただし３時点だけでは動きの滑らかさやヒットストップの長さまでは分からないため、録画で補った。必殺、成長、結果などの撮影には状態を用意し、画像上端に検証用であることを明示した。これを通しプレイ成功の証拠としては扱っていない。

### movieとプレイ録画

起動movieは30fps・５秒、プレイmovieは実マウス／キーボード入力による28秒・840フレーム。ffmpegで２秒間隔の画像と末尾を抽出し、一覧と必要な拡大画像を目視した。

プレイ録画は、移動、予測、交戦、敵フェーズ、回復の流れと、操作説明・盤面・ダメージ表示の重なりを調べるのに効いた。交戦画面と盤面のダメージ数字の重複は、この確認で修正した。一方、２秒間隔の抽出は短い被弾や必殺を取りこぼすので、効果途中の静止画撮影と併用した。

### 通常描画・終了・エクスポート

macOSの通常描画でタイトルとF11の全画面→ウィンドウ切替を撮影した。通常終了に加え、CoreAudio／Dummyそれぞれで `--quit-after 1/30/120` を実行し、終了時のリーク警告がないことを確認した。ログは全文をWARNING／ERRORで検査した。

macOS・Windows・Linux・Webへのエクスポートは成功した。Windows実機での起動と物理ゲームパッド実機は未検証。エクスポート成功、合成したパッドイベントによる検証、実機での操作確認は分けて報告した。

### CI artifact

CI run 34035423517の `tactics-screenshot-and-movie` を取得し、24 PNGと５秒のmp4の0・2・4秒・末尾を目視した。Linuxの既知のVSync警告以外に、ERRORや終了時リークはなかった。最終run 34046957493も全31ジョブ成功した。間の変更は知見文書だけで、目視したartifactとゲーム本体は同じだった。

ローカルmacOSだけでなくLinuxの描画も確認できる点がよかった。ただしartifactは取得して開くまで手間があり、ZIPの転送が遅延した。Range取得で分割し、ZIPのCRC検査後に展開した。

### webtunnelと証拠の公開

runnerのChromiumでタイトル→選択→移動→戦闘予測→攻撃→敵フェーズ→主人公の自然敗北→タイトル復帰まで実操作した。ゲーム状態のJavaScript書き換えはしていない。実際のWebエクスポート、canvas入力、日本語表示を一緒に確認できた。

agent-browserでは起動状態とcanvas矩形を取得できたが、撮影がdaemonの応答待ちで失敗した。同じChromiumへ直接CDP接続し、`Page.captureScreenshot`、`Input.dispatchKeyEvent`、`Input.dispatchMouseEvent` を使って続行した。16:9ではないブラウザ表示では余白と倍率を考慮してクリック座標を変換した。再開後の検証runは34046896692で、終了時にdownした。

最終的にローカル・録画フレーム・Webの42 PNGとプレイ動画１本をPRに掲載し、公開URLからGETして全43ファイルのSHA256が原本と一致することを確認した。Webで確認できたのは敗北側の実操作ループで、全３章のクリアは通常APIによるselfcheck、勝利・エンディングの見た目は状態を用意した撮影で検証した。

## 6. Godot固有のハマりどころと回避策

| ハマりどころ | 今回の回避策 |
|---|---|
| Controlが盤面のクリックを消費する | 背景・コンテナを `MOUSE_FILTER_IGNORE` にし、ボタンだけが入力を消費する構成に整理 |
| 合成マウス入力とOSのポインタ位置が一致しない | イベントの `position` を使い、実マウスと合成イベントの処理経路を揃えた |
| 方向キーが盤面でなくボタンのフォーカスを動かす | 盤面操作中のボタンフォーカスを無効化 |
| JSONの数値がfloatとして戻る | 整数性と範囲を検証してから復元。陣営・兵種・ID・生存座標の重複も確認 |
| autoloadの状態と画面の一時選択がずれる | 永続状態と移動取消用の一時状態を分離し、保存前に未確定移動を取り消す |
| 戦闘途中の撃破後も反撃・追撃を続けてしまう | 打撃ごとに双方の生存を確認し、継続可否を判定 |
| 全員死亡時の画面再開で生存者の先頭を参照する | 主人公をIDで取得して結果画面へ復帰 |
| 音声停止直後のquitでObjectDB／resourceの解放警告が残る | 音源停止とstream参照の解除後に解放待ちを設けた。通常終了、quit-after、録画終端を別経路で検証 |
| headlessを使っても見た目を確認できない | 描画付きscreenshot／Movie Makerを別に実行。CIはXvfb＋llvmpipeで描画 |
| macOS sandbox内では設定・userデータやウィンドウサービスへのアクセスが制限される | headlessはself-containedのGodotコピーを利用。描画は許可された通常のGodot起動に切り替え、ログを作業ディレクトリへ出力 |
| 実時間で撮影するとアニメーションの同じ瞬間を比較しにくい | pause／seekで時刻固定した一覧撮影と、実時間の録画を併用 |
| 小さい盤面では攻撃動作や武器の振りが伝わらない | 本体・武器を分離して動かし、交戦中はキャラを拡大表示 |
| Web版が非16:9のcanvasに表示される | canvas矩形、ゲームの1280×720、余白、倍率から入力座標を変換 |
| Linuxのソフトウェア描画でVSync警告が出る | 既知の該当行だけを区別し、それ以外のWARNING／ERRORと描画結果を確認 |

最も再利用価値が高いのは、計算のselfcheck、実入力、時刻固定の全動作撮影、実時間のプレイ録画を組み合わせる検証方法だった。一つの方法を増やすより、それぞれが見落とす種類の不具合を別の方法で確認できることが効いた。
