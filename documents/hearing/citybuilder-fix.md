# citybuilder 開発ヒアリング

## 1. 開発の進め方

### 着手前の調査

最初に、既存ゲームの構成、citybuilder の issue と受け入れ条件、過去の PR、各ゲームの `documents/knowledge/*.md` とヒアリング記録を確認した。そのうえで、比較対象となる既存の citybuilder を実際に操作し、変更前の画面も保存した。これは、元ネタの固有表現を持ち込まずに、ゲームの核である「道路・電力・需要を読みながら街を育てる」流れを残せているか判断する基準になった。

見た目は、単なる色替えではなく「青焼きの都市計画図」を一貫した方向性にした。既存の 32 × 32 のシミュレーション盤面、ゲーム進行、保存データ、主要 API は保ち、表示と操作の層から段階的に置き換える方針にした。ロジックと見た目を同時に大きく変えないことで、不具合が出た時に原因を絞りやすくした。

### 実装した順序

1. テーマ、色、背景シェーダー、等角投影のマップを先に作り、全画面の基準となる見た目を固めた。
2. 道路、住宅、商業、工業、発電所など 13 種類の盤面要素を `Line2D` と `Polygon2D` で描画した。外部画像を増やさず、拡大縮小や状態色をコード側で統一して扱える構成にした。
3. 盤面要素ごとに通常、建設、稼働、問題、撤去、選択の 6 状態を用意し、建設の立ち上がり、稼働時の微動、問題時の点滅などを追加した。
4. タイトル、チュートリアル、ゲーム中 HUD、建設プレビュー、オーバーレイ、ポーズ、クリア・破産結果まで、画面遷移と情報の優先順位を整えた。
5. 建設不可の理由、接続状況、需要、税率、月送りなど、プレイヤーの判断に必要なフィードバックを追加・調整した。
6. BGM、環境音、SE を決定的に再生成できる Python スクリプトで作り、フォントとライセンス表記を整えた。
7. ロジック検証、実入力を使う結合検証、代表画面、全盤面要素のアニメーション一覧、動画、デスクトップ・Web エクスポートを順に追加した。
8. スクリーンショットと動画を目視し、情報の重なり、文字切れ、チュートリアル矢印、結果画面、ズーム表示、通知、オーバーレイなどを反復修正した。
9. CI artifact と webtunnel でも別環境の描画・操作を確認し、証跡を PR に添付した。

### 詰まった点と解決方法

- `SubViewport` 内の盤面と通常の `Control` では座標系が異なり、建設プレビューやチュートリアルの矢印がずれた。盤面のローカル座標、ビューポート座標、画面座標の変換箇所を分け、ズームを含めた変換を一元化した。
- 等角投影の線画を 0.5 倍で表示すると、細線や細かな装飾がほぼ消えた。小さな装飾を増やすのではなく、太い輪郭、判別しやすいシルエット、半透明の面で構成し直した。
- チュートリアル中にゲームパッドの B ボタンを押しても、画面上の `Button` が入力を消費してスキップできなかった。UI の処理より先に `_input` で対象ボタンを処理した。
- 結果画面へ遷移した直後にフォーカスを設定しても、後続のフェーズ変更で解除された。遷移を確定する前ではなく、`advance_now` 後に結果画面側でフォーカスを設定した。
- マウスを速くドラッグすると、フレーム間に通過したマスが抜けた。直前のマスから現在のマスまでグリッド上の経路を補間し、途中のマスにも同じ操作を適用した。
- 終了時の録画が灰色のフレームで終わった。終了前に表示ノードを消さず、`SceneTree` が終了するまで最後の正常な画面を残した。
- `warning.wav` というファイル名がログ全文の `WARNING` 検査に誤検出された。意味を保った `alert.wav` に改名し、検査を弱めずに回避した。
- 通常の Godot アプリでは、worktree 配下のインポートや設定ファイルへのアクセスが sandbox の影響を受けた。検証用に自己完結かつ ad-hoc 署名した Godot を worktree 側で使い、リポジトリ内へ入出力を閉じた。
- webtunnel の Tailscale 状態確認が sandbox 内では失敗扱いになった一方、実際のアプリ側 CLI では接続できていた。ラッパーの表示だけで判断せず、実プロセスと接続先を確認した。
- webtunnel の Chromium は 1280 × 656 で、ゲームの設計解像度 1280 × 720 と一致しなかった。Web canvas の実寸を取得し、余白と縮尺を含めてゲーム座標をクリック座標へ変換した。
- 遷移直後に撮影すると、描画更新やダウンロード完了前の画像を拾うことがあった。状態変化を待ち、画像そのものを開いてから次へ進んだ。
- Web 操作動画は約 82.9 MB になり、GitHub からの取得が複数回中断した。今回の完了判定は、同じ操作のスクリーンショットと CI の短い録画 artifact で補った。大きな artifact の再開可能な取得は今後の改善点として残った。

## 2. 使ったツール・skill・コマンド

### skill

- `godot-development`: Godot 4.7 の起動、headless 検証、インポート、エクスポート、既知の注意点の確認に使った。
- `game-asset-search`: 外部素材を採用する場合の調査方法、ライセンス確認、クレジット記録の基準として使った。最終的に画像は外部素材を使わず、フォントだけを採用した。
- `commit` / `commit-create-pr`: 差分点検、検証、コミット、push、draft PR 作成の手順に使った。
- `webtunnel`: GitHub Actions runner 上の Web エクスポートを Chromium で開き、実操作するために使った。
- `agent-browser`: webtunnel の CDP 接続先を操作し、状態確認、クリック、キー入力、スクリーンショット取得に使った。共有セッションではなく citybuilder 固有の接続先を使った。
- `pr-attach-screenshots`: 確認済みの画像を R2 に配置し、PR の説明へ証跡として載せるために使った。
- `write-adr`: 判断が長期的な共有設計へ影響するか基準を確認した。今回はゲーム固有の変更に閉じており、ADR は作成しなかった。

### ローカルのコマンドと用途

- `gdlint scripts/`: GDScript の lint に使った。
- Godot 4.7 CLI: headless 起動、インポート、selfcheck、スクリーンショット、動画用起動、各プラットフォームへのエクスポートに使った。
- `make lint`、`make import`、`make check`、`make integration`、`make selfcheck`、`make screenshot`、`make movie`、`make movie-play`、`make test`: 個別検証と CI 相当の一括検証に使った。
- `make build-all`、`make build-web`、`make citybuilder-run`: macOS・Windows・Linux・Web の成果物生成とローカル起動に使った。
- `python3 scripts/dev/generate_assets.py`: BGM、環境音、SE の WAV を固定手順で生成した。
- `python3 scripts/dev/check_procedural_assets.py`: 生成物のバイト列、更新時刻、チャンネル数、サンプル形式、ピーク、ループ端点などを検査した。
- `ffmpeg` / `ffprobe`: 録画生成、再生時間やストリームの確認、動画の末尾や代表時点のフレーム抽出に使った。
- ImageMagick の `magick` / `identify`: 画像サイズの確認と、変更前後・状態別スクリーンショットの比較一覧作成に使った。
- `gh` / `gh api`: issue・PR・workflow・check・artifact の取得と、PR の作成・更新に使った。
- `curl`: フォントなど、出所が明確なファイルの取得に使った。
- `puts`: 確認済みのスクリーンショットをアップロードし、PR から参照できる URL を得るために使った。
- `rg`: コード、ログ、ライセンス、警告・エラー、対象文字列の横断確認に使った。
- `git`: 差分、追跡状態、コミット履歴、ブランチ状態の確認とコミット・push に使った。
- `lsof`、`ps`、`NSRunningApplication` を使う終了処理: 検証後に残った Godot プロセスを特定し、対象プロセスだけを終了するために使った。
- 画像表示ツール: 各 PNG と抽出フレームを実際に開き、文字切れ、重なり、色、状態差、アニメーション途中の形を目視した。

## 3. 欲しかったが無かったツール・skill・スクリプト

- `Line2D` / `Polygon2D` で作った等角投影オブジェクトについて、全種類・全状態・複数ズームの一覧を自動生成し、描画境界からのはみ出しや小さすぎる線を検査する仕組みが欲しかった。今回の 13 種類 × 6 状態の確認は専用ギャラリーを実装して補ったが、ゲームごとに作る手間がある。
- `screenshot.gd` の撮影一覧を manifest として読み、変更前後、他ゲームとの比較、状態別の画像をラベル付き contact sheet にするスクリプトがあると、ImageMagick の個別コマンドと手動選定を減らせる。
- ローカルの全検証、ログ全文の警告・エラー検査、許容する環境警告の分類、動画からの代表フレーム抽出、webtunnel 起動、証跡アップロード、PR 本文更新までを一つにつなぐ証跡作成用 skill が欲しかった。各工程は自動化されているが、工程間の受け渡しはまだ手作業が多い。
- GitHub Actions の大きな artifact を、途中から再開し、ハッシュで完全性を検査できるダウンロードスクリプトが欲しかった。今回の Web 操作動画の取得中断に直接効く。
- agent-browser のクリックで、Godot の設計解像度、canvas の表示領域、ブラウザのビューポートを入力すると座標を変換する補助コマンドが欲しかった。現状は canvas の実寸を読み、計算した座標を手入力している。
- 音量差、クリッピング、無音、ループ端点は機械検査できたが、BGM と SE の聞き分けや長時間聴いた時の負担は自動評価できなかった。短い試聴一覧の生成と、用途ごとの主観評価項目を揃える仕組みがあると確認しやすい。
- `pr-attach-screenshots` では caption のキーに拡張子を含める点が分かりにくかった。skill の利用例に実際のキー形式が明記されていると、試行錯誤を減らせる。

再利用価値が特に高いのは、等角投影オブジェクトの状態別ギャラリー生成と、検証から PR 証跡作成までの一括実行である。どちらも今後の Godot ゲームで繰り返す可能性が高く、個別ゲームのコードではなく skill と汎用スクリプトにするのが適している。

## 4. 素材の準備方法と使い勝手

### 画像・盤面オブジェクト

外部の画像素材は使わなかった。建物、道路、自然物などは `Line2D` と `Polygon2D` を組み合わせ、実行時に描画した。背景もシェーダーで紙の濃淡、グリッド、走査線に相当する表現を生成した。元ネタの画像やロゴを避けやすく、色調、選択色、問題色、ズーム、アニメーションをコードから一貫して制御できた。

一方、コードだけでは素材単体のプレビューがしにくく、輪郭の調整にも実際のゲーム解像度での撮影が必要だった。細部を描き込んでも縮小時に消えるため、一般的なベクターイラストとは異なり、ゲーム内の最小表示サイズを基準に設計する必要があった。以前の SVG は最終的に不要になり、採用した素材だけが残る構成にした。

### BGM・環境音・SE

Python で波形を合成した。倍音、ノイズ、エンベロープを組み合わせ、4 曲の BGM、5 種類の SE、ステレオ環境音を生成した。乱数は固定 seed にし、同じ入力から同じバイト列と更新時刻になる冪等な生成処理にした。WAV は 22,050 Hz・16 bit で、BGM と環境音はステレオ、SE はモノラルとした。

生成方式は、外部ライセンスが増えず、曲調や長さをゲーム用途に合わせやすく、リポジトリ上で再生成可能な点が良かった。クリッピング、ピーク、チャンネル、ループ端点、決定性もスクリプトで検査できた。一方、音楽としての魅力、音の疲れにくさ、SE の印象は数値検査だけでは判断できず、最後は試聴が必要だった。高度な作曲や生楽器らしさが必要なゲームでは、この方式だけでは不足する。

### フォント

IBM Plex Sans JP を Google Fonts の公式リポジトリから取得した。フォント本体だけでなく、OFL の全文と取得元を `CREDITS.md` に記録した。日本語と数字を一つの書体で揃えられ、青焼き風 UI の読みやすさも確保できた。

公式リポジトリから取得する手順は単純で、再取得元も明確だった。ただし、フォントファイルだけを置くのでは不十分で、ライセンス本文、著作権表示、Reserved Font Name の有無、再配布条件まで確認する必要がある。今回、外部素材に由来する管理負担は実質的にこのフォントへ集約された。

## 5. 動作確認の方法

### headless のロジック・入力検証

`selfcheck.gd` では、道路接続、電力、需要、災害、成長と衰退、クリア、破産、保存データ破損時の復旧、状態の不変条件を検証した。描画や人間の操作速度に依存しないため、シミュレーションの回帰を素早く特定するのに効いた。一方、UI の重なり、色、アニメーション、フォーカスは確認できない。

結合検証では、キーボード、マウス、ゲームパッド相当の `InputEvent` を実際のシーンへ送り、チュートリアルのスキップ、建設プレビュー、建設不可理由、税率、接続した発電所、手動の月送り、保存と再開、結果画面を確認した。関数を直接呼ぶだけでは見落とす入力経路やフォーカスの問題を検出できた。ただし、OS や実機ゲームパッド固有の感触までは再現しない。

### `screenshot.gd` と画像の目視

`screenshot.gd` で 27 枚を生成した。タイトル、チュートリアル 3 画面、詳細・全体表示、有効・無効な建設プレビュー、成長中・発展後、粒子・画面揺れ、4 種類のオーバーレイ、停電、昼夜、クリア、破産に加え、13 種類の盤面要素を 6 状態で並べたアニメーションギャラリーを撮った。

静止画は、文字切れ、重なり、余白、色の識別、縮小時の輪郭、状態差を比べるのに最も効いた。自動テストが成功していても、帳簿表示の重なり、結果文のはみ出し、チュートリアル矢印の誤位置などは PNG の目視で見つかった。一方、静止画だけでは点滅や補間の速さ、遷移の自然さは判断できない。

### movie とアニメーション検証

`make movie` で起動からメイン画面まで約 4.87 秒の録画を作り、真っ黒なフレームや起動直後の崩れがないことを確認した。`make movie-play` では実入力を伴う約 28.06 秒の操作を録画し、16 個の代表時点へフレームを抽出して、タイトルから操作、クリア、タイトル復帰までを追った。

アニメーションは、全 13 種類 × 6 状態を並べ、各状態を進捗 0%、50%、100% で撮るギャラリーを用意した。これにより、単にアニメーション名が存在するだけでなく、中間形状、終端、線の消失、描画境界を確認できた。さらに実際の盤面サイズで、建設粒子、選択表示、問題表示、画面揺れを撮影し、動画の連続フレームでも変化を確認した。これでも非常に短い一瞬の欠けは抽出間隔によって見落とし得るため、代表時点の静止画と連続動画を併用した。

### CI artifact

CI の Linux・Xvfb・llvmpipe 環境でも screenshot と movie を生成し、citybuilder の artifact に入った 27 枚の PNG と動画の最終フレームを目視した。macOS ローカルだけでは分からないフォント、シェーダー、レンダラ、インポート差を確認するのに効いた。VSync 非対応の警告は Linux の仮想描画環境に由来する既知のものとして内容を確認し、ゲーム由来の警告と区別した。

CI は再現可能な別環境として強いが、artifact を作っただけでは見た目の確認にならない。実ファイルをダウンロードし、PNG と動画フレームを開くところまでを完了条件にした。

### webtunnel

GitHub Actions runner 上で Web エクスポートを配信し、webtunnel と agent-browser で Chromium を遠隔操作した。WebGL2 が有効で、Godot の通知が出ていないことを確認した後、タイトル、チュートリアル、スキップ、ポーズ、建設、重複建設の拒否、1.15 倍ズーム、電力オーバーレイ、マウスドラッグ、月送り、13 か月目の人口 600、タイトルへ戻る流れを実操作した。主要な 4 画面は PR の証跡にも使った。

これは、headless では通らないブラウザ入力、canvas の表示、WebGL、実際の画面遷移を確認するのに有効だった。一方、確認できるのは Web 版であり、デスクトップのフルスクリーン切替、実ゲームパッド、ウィンドウ操作は保証しない。ローカル実行、CI artifact、Web 実操作は代替関係ではなく、それぞれ異なる不具合を拾うために併用した。

### 足りなかった確認

実機ゲームパッドの押し心地、長時間プレイ時の難易度と性能、音量バランス、BGM の疲れにくさは完全には自動化できていない。また、動画の全フレームを画素差や意味で検査する仕組みはなく、代表フレームと目視に依存した。今回の受け入れ条件に必要な操作と描画は確認したが、長時間の主観的な品質評価は検証範囲外だった。

## 6. Godot 固有のハマりどころと回避策

- `SubViewport` を使う盤面では、`Control` のグローバル座標をそのまま使えない。入力、プレビュー、矢印、ツールチップのどの座標空間を扱っているかを明示し、変換関数を一か所へ集める。
- `Line2D` / `Polygon2D` の手続き描画は拡大時にきれいでも、Camera2D の縮小で線が消える。最小ズームで輪郭と状態差を確認し、細部よりシルエットと面を優先する。
- Godot の `Button` はゲームパッド入力を先に消費することがある。画面全体の戻る・スキップ操作は `_input` で先に扱い、`accept_event()` の影響も確認する。
- `Control` のフォーカスは、画面を隠す、親を差し替える、フェーズを進める処理で解除される。遷移途中ではなく、最終的に表示された画面で `grab_focus()` する。
- ドラッグ操作を `_process` ごとの現在セルだけで処理すると、高速移動でセルが抜ける。前回セルとの間をグリッド経路で補間する。
- `await get_tree().process_frame` 一回だけでは、シェーダー、フォント、SubViewport、ファイル保存が撮影可能な状態まで進まないことがある。条件を確認して待ち、保存後はファイルの存在だけでなく画像を開いて確認する。
- headless 起動成功は描画成功を意味しない。`selfcheck` はロジック、`screenshot.gd` は静止画、movie は時間変化、GUI/Web 実操作は入力と遷移というように役割を分ける。
- 終了処理で表示ノードを先に削除すると、録画末尾が灰色や空画面になる。正常な最後の画面を保持したまま `SceneTree.quit()` へ進む。
- Godot のログを単純な文字列検索で検査すると、アセット名に `warning` や `error` が含まれるだけで失敗する。今回はアセットを意味の近い別名へ変更し、警告検査そのものは維持した。
- `.godot/imported` とエクスポート結果は、OS、レンダラ、Godot の版による差が出る。素材追加後は明示的に import を行い、macOS ローカルだけでなく Linux CI でも再生成する。
- Godot 4.7 のデスクトップエクスポートには対応版の export templates が必要である。テンプレートの有無と版を先に確認し、プロジェクト本体と異なる版を混ぜない。
- Web エクスポートではブラウザ表示領域とプロジェクト解像度が一致しない場合がある。固定座標でクリックせず、canvas の bounding box から縮尺と余白を計算する。
- GL Compatibility でも、macOS と llvmpipe のシェーダー・VSync 対応は同一ではない。環境由来の警告は内容を確認して分類し、ゲーム由来の警告を一括で無視しない。
- 音声の import やループ設定はファイル生成だけでは完了しない。再インポート後に実際のチャンネル数、形式、ループ端点を検査し、ゲーム内でも再生状態を確認する。
- 保存データは実装変更後も古い値や破損値が入る可能性がある。ロード時に型と範囲を検証し、不正なデータでは安全な初期状態へ戻す。この経路も selfcheck に含める。

今回最も有効だった回避策は、Godot の一つの検証手段を万能と見なさず、純粋ロジック、実入力、静止画、動画、別 OS、Web 実操作を重ねたことだった。特に UI とアニメーションは、テストの exit 0 では品質を判断できないため、撮影対象をコードで固定し、生成された実画像を毎回目視する必要があった。
