# ghostrogue 第2ラウンド開発ヒアリング

## 1. 開発の進め方

最初に `AGENTS.md`、`documents/PROJECT.md`、対象 issue、前回の PR、`documents/knowledge/ghostrogue.md` を読み、既存版を `make ghostrogue-run` で実際に遊んだ。そこで、ゲームのルール量に対して「町を歩くホラー」という見た目の個性が弱いこと、地図・戦闘・図鑑が別々の画面に見えることを主な手直し対象にした。

次に、既存の状態遷移とテストを壊さない範囲を確認し、素材調査、画面の土台、カットイン演出を分けて進めた。素材はライセンスを先に確定してから取得・加工し、写真背景、テクスチャ、効果音、フォント、生成画像を配置した。その後、次の順で実装した。

1. 写真を3色の網点風に変換するシェーダーと背景レイヤー
2. 12層を横方向に歩く町並みと懐中電灯、霧、前景
3. ノートを模した共通UIと、タイトル・導入・選択・戦闘・図鑑の再構成
4. 初回チュートリアル、霊と技の選択、標的表示、攻撃・被弾・消滅カットイン
5. 環境音と心音のレイヤー、セーブ形式の更新
6. selfcheck、入力を送る統合テスト、代表画面とアニメーション状態を撮る `screenshot.gd` の拡張

実装後は、headless テストだけで終えず、ローカル起動、スクリーンショット全件の目視、録画、macOS・Windows・Linux・Web のエクスポート、CI artifact、webtunnel によるブラウザ上の通し操作へ順に進んだ。最後に旧版との before/after、他ゲームとの識別性、カットインの連続フレーム、Web 操作経路を比較画像にして PR に載せた。

主に詰まった点と解決方法は次のとおり。

- `AtlasTexture` の一領域を `Polygon2D` と独自シェーダーへ渡すと、領域ではなくアトラス全体が表示された。元アトラスを直接渡し、ポリゴンの UV をアトラス内の絶対ピクセル座標へ変換して解決した。
- 導入文が小さな領域に重なった。連続改行を描画前に正規化し、文字サイズと行間を実画像で調整した。
- 図鑑は情報を詰めただけでは読みにくかった。ページ、見出し、余白、現在値の階層を整理し、戦闘中は選択中の技と標的が一目で分かる表示にした。
- 黒を主色にしたタイトルは、録画末尾の平均輝度 `YAVG` による真っ黒判定を誤って失敗した。明るい側10%の `YHIGH` を使い、描画要素が存在するかを判定した。
- 自動プレイ録画がチュートリアルで止まった。画面に実在する「チュートリアルを省略」操作を自動入力し、チュートリアル自体は別の統合テストで検証した。
- webtunnel の接続先を当初 8080 と見込んだが、workflow が公開していたのは 8000 だった。実行中のログとポート情報を確認して接続先を直した。
- GitHub Actions の大きな artifact の一括取得がタイムアウトした。HTTP Range で13分割して取得し、結合後に ZIP と内容を検証した。

## 2. 使ったツール・skill・コマンド

### skill

- `godot-development`: Godot 4.7 の起動、import、headless 検証、エクスポート、既知の注意点を確認した。
- `game-asset-search`: 素材候補の探し方、ライセンス確認、`CREDITS.md` の記録方法に使った。
- `imagegen`: オリジナルのタイトル画像と、12体の霊を収めたアトラスを生成した。
- `agent-browser`: `ghostrogue` という明示セッションで webtunnel の Chromium を操作した。
- `webtunnel`: GitHub Actions 上で Web エクスポートを起動し、タイトルから探索、霊の獲得、戦闘、図鑑まで操作した。
- `gh-r2-image` の手順: 実際のアップロードは `puts` を使い、比較画像を PR から閲覧できる URL にした。
- `commit`、`commit-create-pr`: 差分検査、個人情報検査、コミット、push、draft PR 作成の手順に使った。

### コマンドと外部ツール

- `make ghostrogue-run`: エディタなしの実ウィンドウで旧版と完成版を操作した。
- `make lint GAMES=ghostrogue`: `gdlint` による GDScript の lint を実行した。
- `make import GAMES=ghostrogue`: 追加した画像、音声、フォントを Godot 4.7 でインポートした。
- `make check GAMES=ghostrogue`、`make selfcheck GAMES=ghostrogue`、`make test GAMES=ghostrogue`: 起動、ロジック、統合入力を検証した。
- `make screenshot GAMES=ghostrogue`: 代表画面と状態差分を PNG にした。
- `make movie GAMES=ghostrogue`、`make -C games/ghostrogue movie-play`: 無操作の起動録画と、自動入力付きの通し録画を作った。
- `make build-all GAMES=ghostrogue`、`make build-web GAMES=ghostrogue`: 3デスクトップOSと Web をエクスポートした。
- `ffmpeg`、`ffprobe`: OGG への音声正規化、動画情報の確認、2秒間隔と末尾フレームの抽出、輝度検査に使った。
- ImageMagick の `magick`、`identify`、`montage`: 写真の切り抜きと加工、寸法確認、比較表とコンタクトシート作成に使った。
- `cwebp`: 加工済み写真を lossless WebP にした。
- `gh issue`、`gh pr`、`gh run`、`gh api`: issue・既存 PR の調査、PR 作成と更新、CI 状態と artifact の取得に使った。
- Wikimedia Commons API、OpenGameArt、Google Fonts: CC0 写真、CC0 テクスチャ・音声、OFL フォントの取得元と権利情報の確認に使った。
- `curl`: API 応答、素材、artifact の取得に使った。
- `puts`: PR 用の比較画像をアップロードした。
- `rg`、`git diff`、`git status`、`git check-ignore`: 実装調査、差分、未追跡物、gitignore の確認に使った。

## 3. 欲しかったが無かったツール・skill・スクリプト

- **PR 用の視覚証拠作成ツール**: 旧版と新版の対応画面、他ゲームとの識別性、アニメーションの連続フレームを指定すると、ラベル付き比較画像の作成、アップロード、PR 本文への挿入まで行うもの。今回は URL の回収、画像選定、montage、`puts`、本文編集を手作業でつないだ。
- **素材受け入れ台帳ツール**: 配布ページ URL、作者、ライセンス、取得日時、元ファイル、加工内容を一度入力すると、ファイル配置と `CREDITS.md` を同期し、画像内の文字・人物・位置情報も検査するもの。
- **Godot のアトラス・シェーダー検査スクリプト**: `AtlasTexture`、`Sprite2D`、`Polygon2D`、独自シェーダーの組み合わせごとに、期待した領域だけが描かれるか小さな画像比較テストを作るもの。
- **GitHub Actions artifact の耐障害ダウンローダー**: 大容量 ZIP を再開可能な Range download で取得し、サイズ、ZIP、ファイル一覧まで自動検証するもの。
- **スクリーンショット検査ツール**: 文字の切れ・重なり、コントラスト不足、同一画像の混入を検出し、全 PNG のコンタクトシートを生成するもの。
- **webtunnel 操作記録ツール**: Godot の論理解像度とブラウザ canvas の座標を変換し、クリック経路、スクリーンショット、録画を一つのシナリオから再現するもの。

この中では、比較画像・アップロード・PR 本文更新までをまとめる skill と、素材台帳を作る skill が、別ゲームでも繰り返し使えて特に効果が大きい。

## 4. 素材の準備方法と使い勝手

### 写真

Wikimedia Commons API から CC0 の町、団地、路地、墓地の写真を4枚取得した。1920px の原画像を保存し、必要な範囲を切り抜き、読める看板や文字をぼかし、1280×720へ整形した。さらにグレースケール化、コントラスト調整、3色の ordered dither を施し、lossless WebP にした。

実在感と場所ごとの差が強く、横道の識別性を最も高めた素材源だった。一方、写真の選定、人物や文字の確認、ライセンス確認、ゲーム内で浮かない加工には手間がかかった。API で候補とメタデータを取得できる点はスクリプト化しやすかった。

### テクスチャと音声

OpenGameArt から CC0 のテクスチャ2点と効果音・環境音8点を取得した。テクスチャは紙や汚れの質感として薄く重ね、音声は `ffmpeg` で形式と音量を揃えて OGG にした。環境音と心音は場面や闇の値に応じて既存の手続き生成 BGM へ重ねた。

小さな素材をまとめて探せる点は便利だったが、一つの配布ページに複数ライセンスや複数作者が含まれることがあり、ページ名だけで判断できなかった。個々のファイルと説明を照合する必要がある。既存の手続き生成 BGM はループと再現性に優れるため残し、外部音声は環境音と合図音に限定した。

### フォント

Google Fonts から OFL の Reggae One を取得し、ライセンス本文と著作権表示を同梱した。日本語グリフがまとまっており導入は容易だった。強い見出しには有効だが、長文本文へ全面適用すると読みづらいため、用途を限定した。

### 生成画像

画像生成でタイトル画像と4列×3行の霊12体アトラスを作った。既存作品の名称・画像・ロゴを使わずに、ゲーム固有の第一印象と霊の造形差を短時間で得られた。特にタイトルの効果は大きかった。一方、アトラスのセル位置、余白、切り抜き、透過、各セルを Godot でどう参照するかは人手で検査・調整が必要だった。

### 手続き生成 SVG

既存の手続き生成 SVG は、可動部を分けやすく、同じ画風の差分を再現可能に作れる点が強かった。ただし、大きな背景や主役画像に使うと抽象的で場所の記憶が弱くなった。今回からは人物の動き、入口、霧、懐中電灯など動的要素へ役割を絞り、背景の実在感は写真、主役の造形は生成画像に分担した。

## 5. 動作確認の方法

### headless の selfcheck と統合テスト

`selfcheck.gd` では、闇の増減、経路生成、戦闘規則、霊の獲得と消滅、控えの昇格、セーブ／ロードと旧形式からの移行を検証した。さらに実際の `InputEvent` を送る統合テストを77件まで増やし、画面遷移と操作不能を検出した。ルールと状態遷移には最も速く効いたが、文字の重なり、写真の見え方、アニメーション、音は分からない。

### `screenshot.gd`

代表画面だけでなく、全12層、選択肢、図鑑ページ、闇の段階、チュートリアル、戦闘中の技・標的、各キャラクターの待機・移動・攻撃・被弾・消滅を撮るよう拡張した。最終的に101枚を生成し、カテゴリ別のコンタクトシートと必要な原寸画像を目視した。導入文の重なり、アトラス全体が表示される問題、図鑑の読みにくさ、標的表示の弱さはこの工程で見つかった。

アニメーションはリアルタイムの一瞬を偶然撮るのではなく、`AnimationPlayer` を開始・中間・終了の決まった進行位置へ移動して連続フレームを撮った。攻撃、被弾、消滅の3状態を比較し、位置、拡大率、透過、残像、対象キャラクターが正しいかを確認した。この方法は差分が決定的で、CI でも再現できた。

### movie とローカル起動

`movie` では5秒・150フレームの起動状態を録画し、0秒、2秒、4秒、末尾を抽出した。`movie-play` では30秒・900フレームに14個の入力を送り、チュートリアル省略、探索、戦闘、結果、タイトル復帰までを録画して2秒間隔と末尾を確認した。静止画では分からない画面切替、暗転、アニメーションの時間的なつながりに効いた。

ローカルの `make ghostrogue-run` でも実ウィンドウを開き、マウス操作と音声を確認した。自動検証では弱い音量バランスや操作感を確認するには必要だった。

### CI artifact

CI の Xvfb と llvmpipe 上でも101枚の PNG と movie を生成し、artifact をダウンロードして全カテゴリと動画フレームを目視した。ローカルだけで成立するパスやインポート状態を避けられ、クリーン環境で同じ見た目が出ることを確認できた。llvmpipe 由来の既知の VSync 警告はあったが、ゲーム由来の WARNING / ERROR はなかった。

### webtunnel

最終コミットの Web エクスポートに対し、タイトル、導入、左右移動、墓地への侵入、霊の獲得、強制戦闘、3体分の技選択、標的表示、勝利、図鑑まで実際にブラウザ入力で通した。canvas の変化、ボタンが押せること、ブラウザエラーがないことを同時に確認でき、実ユーザー経路の検証として最も強かった。

ただし Web 版で分かるのは Web 固有の動作であり、デスクトップのフルスクリーン、物理ゲームパッド、各OSネイティブのウィンドウ挙動は補えない。また、今回の検証は音が鳴ることまでは確認したが、長時間プレイ時の主観的な音量バランスまでは自動判定できない。

## 6. Godot 固有のハマりどころと回避策

- **`AtlasTexture` と独自シェーダー**: `Polygon2D` の UV と `AtlasTexture.region` が期待どおり合成されない組み合わせがある。シェーダーへ元アトラスを渡し、region の原点を加えた絶対ピクセル UV を作る。セル単体の原寸スクリーンショットも用意する。
- **動的 UI の文字領域**: `Label` の矩形が収まっていても、日本語グリフの実描画、折り返し、改行、フォントの行間は重なることがある。最長文を含む状態を `screenshot.gd` で撮り、原寸で確認する。連続改行は表示前に正規化する。
- **暗い画面の真っ黒判定**: ホラー画面を平均輝度 `YAVG` だけで検査すると、正常でも失敗する。背景の設計を明るくするのではなく、`signalstats` の `YHIGH` など、存在すべき明部を測る。
- **アニメーションの検証**: headless 実行中の時刻任せではフレームが不安定になる。`AnimationPlayer` の進行位置を明示的に動かし、開始・中間・終了を別画像にする。通しの時間関係は movie で補う。
- **録画終了時の音声リソース**: 音声再生中に SceneTree を即終了すると、終了ログや録画完了が不安定になり得る。終了18フレーム前にプレイヤーを停止し、stream 参照を外してから終了する。
- **Web の座標系**: Godot の論理解像度は1280×720でも、runner 上の canvas は1279×656だった。ゲーム座標をブラウザ座標として直接クリックせず、canvas の実寸、比率、余白から変換する。
- **Web の起動判定**: HTML が返ることだけでは Godot の起動成功にならない。canvas の生成、WebGL2、画面差分、Godot の起動ログ、ブラウザエラーを組み合わせて判定する。
- **一時出力とセーブ**: `tmp/` と `build/` に `.gdignore` を置き、テストのセーブ先も `res://tmp` に分離する。検証生成物や前回のユーザーセーブが import や再現性へ混ざらないようにする。
