# 農場生活シム「こもれび農園」開発ヒアリング

対象は issue #37 の開発開始から、PR #48 をレビュー可能にするまで。実装・検証ログ、素材クレジット、開発中の記録をもとに振り返る。この文書は依頼されたヒアリング用で、コミットしない。

PR: https://github.com/bannzai/godotpractice/pull/48

## 1. 開発の進め方

### 作った順序

1. 作業指示書、issue、プロジェクトの規約、既存ゲームの実装・知見、Godotと素材準備のskillを読んだ。変更範囲と検証コマンドを先に確認した。
2. 最初にタイトル→プレイ→結果→タイトルの最小ループと検証入口を作り、コミットしてdraft PRを作成した。最初から全機能を完成させるまでPRを保留せず、その後の進捗を本文へ反映した。
3. 素材生成、農業・経済・保存のロジック、検証スクリプトを3担当に分け、担当ファイルを固定した。主担当は画面・入力・農場表示・音声の組込みを進めた。Godotの描画付き検証は担当を一本化し、同時起動や同じ画像の上書きを避けた。
4. Farm autoloadに作物、体力、時間、出荷、季節、勝敗、保存を集約した。画面遷移、地形表示、キャラ再生は別スクリプトに分けた。表示する種価格・成長日数・売値もロジックの定義から取得した。
5. 独立したキャラ画像、6動作、農作業の粒子、収穫時の停止・揺れ・フラッシュ、翌朝のフェード、3層背景、Theme、BGM・SEを組み込んだ。手帳・持ちもの・図鑑・商店・保存再開を実装した。
6. headlessのロジック検証と入力検証を通し、実描画・録画で見つけた不具合を直した。SVGの透明度、選択枠の描画順、商店ラベルの重なり、道具ボタンの文字切れなどはこの段階で修正した。
7. ローカルの検証、デスクトップ3環境とWebの書き出し、CIの成果物確認、webtunnelでの実操作、画像公開を実施した。最後に知見文書をコミットし、そのコミットのCIも全31ジョブ成功を確認してdraftを解除した。

コミットは「画面ループと検証入口」「農業・季節・保存と演出」「最終検証の知見」の3段階だった。

### 詰まった点と進め方の反省

- **素材の構文が正しいだけでは描画品質を保証できなかった。** 半透明の雲・影・眼鏡がGodotで黒くなった。SVG生成器を修正して画像35枚を再生成し、Godotでの画素検査と再撮影を行った。素材を大量に作る前に、透明度・フォント・代表キャラ1体を実エンジンで試すと手戻りを減らせる。
- **保存座標の数値検査だけでは足りなかった。** 画面内でも建物の内部なら再開後に動けない。保存検証と移動を同じ通行判定に揃え、障害物内部などの検証を追加した。
- **ゲームの不具合と実行環境の制限を切り分ける必要があった。** worktreeの共有Git管理領域、Godotのログ・保存先、macOSのXPC接続、Tailscale、putsのKeychain参照で制限に当たった。ログと実ファイルを確認し、依頼済みの処理に必要な権限で実行した。システム設定の変更や認証情報の新規発行はしなかった。
- **Webの長い連続操作で時間を使った。** 操作は進んでいるのにagent-browserが返答を読み取れず、失敗表示になった。現在画面を別接続で確認し、3日分以下の入力に分割した。確認待ちではベッドのダイアログを開いてゲーム時間を止めた。途中で木に移動を阻まれた時も、画像と衝突領域を照合して経路を直した。
- **証拠を揃える工程にも実装と同じ程度の段取りが要った。** ローカル画像、録画フレーム、Web画像、最新CI画像を揃え、公開して本文を更新する作業が多かった。途中から画像一覧・公開URL・ハッシュ・本文生成をスクリプト化した。
- **公開の自動承認で一度止まった。** 最後のWeb画像のputs公開が「公開の承認がない」と判定された。作業指示書にあるputs公開の明示的な依頼を確認し、根拠を添えた同じ操作の再実行で通った。未解決の承認待ちは残していない。

ローカルで実行した主要コマンドは次のとおり。Godotには作業ディレクトリ内のself-containedバイナリを`GODOT`として指定した。描画付き検証は必要な実行権限で行った。

```sh
make test GAMES=farmsim
make screenshot GAMES=farmsim
make movie GAMES=farmsim
make build-all GAMES=farmsim
make build-web GAMES=farmsim
make farmsim-run RUN_FLAGS='--script res://scripts/dev/shutdown.gd'
make farmsim-run RUN_FLAGS='--quit-after 60'
```

ゲームディレクトリでは`make movie-play`、素材生成器の`--verify`と`--images-only`も使った。Webでは`up farmsim --software-webgl --ref game/farmsim --wait`、`cdp farmsim`、`down farmsim`、`fetch-recording.sh`を使用した。`make clean`は上記の検証実施一覧には含めない。

## 3. 欲しかったツール・skill・スクリプト

今回個別に用意した処理や、判断に時間がかかった処理を次回は共通化したい。以下は今回の作業で欲しかった機能であり、他の全skillに同等機能が存在しないと調査した結果ではない。

| 欲しかったもの | 減らせる作業・必要な機能 |
| --- | --- |
| Godotで素材を確認する小さな検証シーン | 代表SVG、半透明の影、フォント、スプライトシートをインポートして撮影・画素検査する。外部SVG表示との違いを素材量産前に発見したい。 |
| キャラの実再生を撮る共通スクリプト | キャラと動作の一覧から`frame_changed`を待ち、開始・途中・終了を撮影する。再生の停止やコマ未到達をタイムアウトで検出し、一覧画像まで作りたい。 |
| 証拠画像の公開・PR反映をまとめる処理 | 原本のハッシュ、putsのURL、HTTP読戻し結果を記録し、変更した画像だけ再公開する。本文への埋込み漏れや古いCI画像の残存も検査したい。今回は`upload-evidence.py`と`render-pr.py`を一時領域に作った。 |
| Web操作の完了を安全に確認する補助 | 長い入力を短い区間に分割し、通信の応答と操作完了を区別する。応答不明時に入力を再送せず、現在の画面を取得したい。今回の`web-input.py`はキー配送には使えたが、長い処理の応答待ちは弱かった。 |
| Godot・Tailscaleの実行環境診断 | 保存先、ログ先、テンプレート、macOSの描画起動、tailnet参加、CDP応答をそれぞれ調べ、ゲームのロード失敗と権限制限を区別したい。 |
| 音源の確認をまとめる処理 | クリップ、無音、音量、ループ境界の差、再生箇所、終了時解放を一括で確認したい。数値検査の結果と、人が試聴する短い音源一覧を同じ成果物にしたい。 |

godot-developmentには保存位置と通行判定の共通化、実入力によるメニュー停止検証、実アニメーション撮影の例があると再利用しやすい。webtunnelには、GitHub APIのタイムアウトをrun失敗と区別する診断と、短い操作単位の例を追加したい。

また、今回の共有CIではゲームの知見文書だけを更新しても全ゲームが検証対象になった。知見文書を対応するゲームへ割り当てる変更検出があれば、待ち時間と実行量を減らせる。共有workflowは今回変更せず、提案に留めた。

## 4. 素材の準備方法と使い勝手

### 画像

PythonからオリジナルSVGを35枚生成した。内訳は、キャラ3、作物4種×成長4段階の16、建物・小物6、UI5、背景4、地形アトラス1。主人公・商店主・鶏は各512×768の別スプライトシートとし、128pxのコマを4列×6行に配置した。帽子と作業着、眼鏡と籠、鶏冠と羽で輪郭を描き分けた。

色・輪郭・サイズをコードで揃えられるため、UIと背景を同じ絵柄へ寄せやすかった。特定の部品だけの修正、全画像の再生成、ハッシュ照合も簡単だった。一方、ポーズの自然さや細部の表現は描画コードの調整が必要で、画像生成サービスのように文章だけで豊かな絵を得る方法ではない。SVGの別レンダラとGodotで透明度の結果が違う点にも注意が必要だった。

画像生成サービス、image_gen、Geminiによる画像生成、既存作品の画像は使っていない。これらの使い勝手を今回の実績として比較することはできない。

### BGM・SE

Pythonで22050 Hz・16bit・ステレオPCMのWAVを14本生成した。BGMはタイトル・春・夏・盛り上がり・結果の5曲、SEは道具、出荷、翌朝、UI、成功・失敗などの9種。倍音を含む撥弦・木琴・低音、分散和音、打楽器などを重ね、単一の正弦波だけにならないようにした。外部録音や既存楽曲は使っていない。

コードで長さ、音量、音色、ループを調整でき、外部サービスの待ち時間や認証がなかった点は使いやすかった。BGM終端8msの接続補正とSEの音量包絡を調整し、全14本のクリップ・無音検査、全5曲のPCM端点差0を確認した。

ただし、今回の音源評価は数値と再生設定・出力の確認が中心で、実際の試聴による聴き心地の評価はできていない。音量の数値が妥当でも、長く聴いた時の疲れや場面への合い方までは保証できない。合成音楽の好みは判断点としてPRにも残した。

### フォントとクレジット

日本語フォントは、既存monsterquestで使っていたM PLUS Rounded 1c RegularをOFL.txtと一緒に複製した。日本語グリフとライセンス文書が揃った既存素材を再利用でき、準備が少なかった。丸い字形も絵本調の画面に合わせやすかった。狭い道具ボタンでは文字が切れたため、実画面を見てフォントサイズを調整した。

フォントの素材源: https://fonts.google.com/specimen/M+PLUS+Rounded+1c

画像・音源はオリジナル生成物、フォントはOFL-1.1としてCREDITS.mdに区別して記録した。生成物へ勝手にCC0を付けず、再生成元と制作方法を残した。SVG35枚・WAV14本・フォントとライセンス文書を合わせた全51ファイルで、再生成検証のハッシュ一致を確認した。

## 5. 動作確認の方法、効いた点と不足

| 方法 | 実施内容と効いた点 | 確認できないこと・不足 |

### アニメーションの検証

素材にフレームが存在すること、実際に再生すること、見た目が変わることを分けて確認した。3体それぞれに6動作を用意し、フレームの存在・画像差・再生を検査したうえで、描画付きの撮影を行った。

撮影ではフレーム番号を直接設定して済ませず、`AnimatedSprite2D`を再生して`frame_changed`を待った。各動作の0・1・3コマへ到達したら停止して撮影し、3体を横に並べた。6動作×3時点で18画像、キャラごとでは計54コマの到達ログを確認した。開始・途中・終了を一覧で比較できるため、同じ絵が続いているだけの素材や再生漏れを見つけやすかった。

農作業は実際に道具を使い、開始から約0.16秒後を撮って粒子とTweenの途中を確認した。連続画像は姿勢の比較に、プレイ録画は動作と入力のつながりや遷移の確認に役立った。静止画だけでは動きのリズムや快適さを十分に評価できないため、両方必要だった。

ローカルの最終検証18ログは全文を確認し、エンジンのWARNING・ERROR・終了時リークなし。CIの既知のV-Sync警告は本文に明記した。PRの証拠画像57枚はputs公開後にHTTPで読み戻し、原本とハッシュ照合した。Webセッションはdownし、録画を取得して専用ブラウザ接続も閉じた。

## 6. Godot固有のハマりどころと回避策

以下は今回実際に確認した挙動。すべてのGodotバージョン・環境に当てはまると一般化はしていない。

| ハマりどころ | 回避策と検証 |
| --- | --- |
| SVGの8桁色が期待どおり半透明にならなかった | `#RRGGBBAA`を6桁の色と`fill-opacity`・`stroke-opacity`へ分離した。Godot内の雲・影・眼鏡の画素検査と、再インポート後の目視で確認した。 |
| 親Node2Dの`_draw()`で描いた選択枠がTileMapLayerの下に隠れた | 選択枠と畑の境界用に最後に追加するNode2Dを用意し、そのdrawで描いた。画面上で枠が畑より手前に出ることを確認した。 |
| 時刻のCanvasModulateがUIまで暗くする | 農場とUIを別CanvasLayerにし、背景も別層へ分けた。夕方の画面でHUDと手帳の読みやすさを確認した。 |
| ゲーム入力とGUIの決定・フォーカス移動が重なる | 道具の使用と決定を分け、プレイ中の調べる入力を`_input()`で消費した。モーダル表示中は背面ボタン・移動・時間を停止し、入力後のフォーカスも確認した。 |
| 画面内の保存座標でも通行不能な場所がある | 保存データの検証と移動に同じ`Farm.can_walk()`を使用した。数値範囲だけの判定をやめ、家・井戸・池などを含む不正座標を検証した。 |
| 描画更新前に撮ると演出途中や指定コマを正しく記録できない | `process_frame`と`RenderingServer.frame_post_draw`を待ってからPNGを保存した。キャラは`frame_changed`で実再生の到達を待った。 |
| 音声をstopした直後の終了で解放が間に合わない | 通常終了は音を止めてフレームを進め、`_exit_tree()`側でも停止と参照解放・待機を行った。Movie Makerでは末尾12フレーム前に音を止めた。通常終了とフレーム指定終了を別々に検査した。 |
| `config/name`の変更が`user://`の保存先変更を伴う | サンドボックス内で新しい保存先の作成に制限が出た。内部名は元の`farmsim`を保ち、ウィンドウ表示名を日本語にした。Godotには絶対パスのログ先とself-contained環境を渡した。 |
| headlessの起動成功と、描画付き起動の成功は別 | macOSでは描画起動時にXPC接続の制限が出た。ゲームの構文エラーと混同せず、ログを確認して通常権限で描画・録画を行った。 |
| Web版にWebGL2が必要で、画面の縦横比もデスクトップと異なる | webtunnelを`--software-webgl`付きで起動した。ブラウザ1280×656に対してゲームは16:9を維持し、左右の余白を含めて実画面を確認した。HTMLが返ることだけで起動成功とは判定しなかった。 |

次回は、代表素材の実インポートと小さな操作録画をもっと早い段階で通したい。ロジック・素材・演出を並行して進める方針は有効だったが、描画差、入力の重なり、終了時の音声解放を先に確かめるほど後半の再撮影を減らせる。
