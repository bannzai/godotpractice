# rollball 開発ヒアリング

## 1. 開発の進め方

### 作業の順序

1. 最初に issue の受け入れ条件、`documents/PROJECT.md`、既存の rollball、近い構成のゲーム、Makefile の検証入口を読み、既存版を起動・撮影した。先に現在の画面と操作を把握し、「機能は成立しているが、画面構成が汎用的で、初見で次に何をすればよいか分かりにくい」という問題を分けた。
2. 既存の物理、体積による巻き込み、成長、勝敗を変えず、見た目の土台から直した。`clay_surface.gd` でプリミティブへ決定的な頂点色むらと法線ノイズを加え、粘土の質感を部屋、家具、小物、主人公へ共通適用した。Kosugi Maru を同梱して、OS の日本語フォントへ依存しない表示にもした。
3. 次にゲームの導線を「タイトル → おもちゃ箱の部屋選択 → 初回だけの3段階チュートリアル → プレイ → 結果」へ組み替えた。木の床と家具が中心の「おもちゃのアトリエ」と、桃色の床、窓、ラグ、積み木の島を持つ「ひだまりプレイルーム」を作り、選択画面のプレビューと実際の配置・進み方を一致させた。
4. プレイ中の説明を、画面下の一律な操作一覧から、状況に応じた手掛かりへ移した。巻き込める最寄りの玩具に金色の輪、矢印、短い説明を表示し、大きすぎる物体に当たった時は紙札で理由を示した。直径、目標、個数、時間は別々の画用紙片として配置し、タイトル・選択・チュートリアル・結果も同じ紙工作の方向で揃えた。
5. 既存のモデル別アニメーションと演出を新しい画面へ接続し、部屋ごとの環境音を追加した。3Dモデル、UI、音を外部作品へ依存しない手続き生成で揃えた後、ロジック検証、実入力の統合検証、代表画面、連続フレーム、プレイ録画、エクスポート、実時間性能の順に検証を広げた。
6. ローカル検証後に CI の PNG と動画を取得して目視し、さらに webtunnel 上の Web 版をタイトルから結果まで実際のキー入力で操作した。Web 操作で、Enter 1回に対してチュートリアルが2段進む不具合を発見した。修正後は、関数を直接呼ぶだけでなく実 `InputEventKey` の押下・解放を送ってページ番号を確認する回帰試験を追加し、ローカル、CI、Web を再確認した。
7. 最後に、検証画像・動画を既存の R2 へアップロードし、PR の検証欄から確認できる状態にした。公開アップロードはユーザーの承認を得てから実施し、アップロード後は URL の応答とバイト数も照合した。

### 詰まった点と解決

- 指示ではフォントを OFL と想定していたが、Kosugi Maru の公式配布物は Apache License 2.0 だった。指定されたライセンス名へ無理に合わせず、Google Fonts の `METADATA.pb`、配布ディレクトリのライセンス本文、フォント内部の name table を照合し、公式どおりのライセンス本文とクレジットを同梱した。
- macOS で Godot が背面にあると、描画完了を待つ `RenderingServer.frame_post_draw` が進まず、スクリーンショット処理が止まることがあった。Godot のウィンドウを前面へ戻してから撮影し、生成ファイルとログの両方で完了を確認した。
- 選択変更直後のカスタム描画が、複数フレーム待っても古い状態で撮られることがあった。値の更新とは別に、対象画面と子 `Control` へ `queue_redraw()` を発行し、Canvas の再描画後に保存した。
- 独自の `confirm` と標準の `ui_accept` に Enter / A を両方登録した状態で、フォーカス中の `Button` と `_unhandled_input()` が同じ操作を処理していた。フォーカス中のボタン操作は GUI に任せ、ゲーム側で二重に `pressed` を発火しないようにした。
- webtunnel の一般例にあるポート 8080 では接続できず、今回の caller workflow が公開していた実ポートは 8000 だった。workflow と起動ログを正として CDP 接続先を決めた。Tailscale と macOS キーチェーンへアクセスする操作は sandbox 外の許可が必要だったため、必要なコマンドだけ承認を得て実行した。
- CI artifact の通常ダウンロードとブラウザ経由のスクリーンショット取得が遅い場面では、`gh api` で artifact の zip を直接取得し、ローカルで一覧・フレームを確認した。agent-browser のスクリーンショット完了が遅い時も、処理結果を推測せず生成物の存在と実画像を確認した。

## 2. 使ったツール・skill・コマンド

### skill と操作ツール

- `godot-development`: Godot 4.7 の CLI 起動、検証、Movie Maker、export templates、既知の注意点を確認するために使用した。
- `game-asset-search`: フォントの取得元、作者、ライセンス、CREDITS の記録方法を確認するために使用した。無料3Dモデルや画像素材の採用には使わなかった。
- `webtunnel`: GitHub Actions runner の Web エクスポートを Tailscale 経由で開き、実ブラウザ上の操作確認に使用した。
- `agent-browser`: webtunnel の専用 CDP セッションへ接続し、ページ状態、スクリーンショット、キー入力、console / errors を確認した。
- `gh-r2-image` と `puts upload`: 承認後に検証 PNG と動画を既存の Cloudflare R2 へ置き、PR から参照できる URL にするために使用した。
- `commit`: 差分確認、検証、個人情報検査、コミット、push、PR 更新の手順に使用した。

### 実行した主なコマンドとプログラム

- Godot 4.7 stable を GL Compatibility で実行した。`make test GAMES=rollball` で `gdlint`、import、boot、integration、selfcheck、終了処理をまとめて検証した。
- `make screenshot GAMES=rollball` で `scripts/dev/screenshot.gd` を描画付きで実行し、代表画面とアニメーションのサンプルを生成した。
- `make movie GAMES=rollball` で起動からタイトルまで、`make -C games/rollball movie-play` で実キー・スティック入力によるプレイを Movie Maker で録画した。
- `make -C games/rollball performance` で VSync を無効にした実時間の描画性能を測った。
- `make -C games/rollball run RUN_ARGS="--script res://scripts/dev/run_smoke.gd"` で、描画付きの起動、実キー移動、F11 の全画面切替と復帰、Esc、通常終了を確認した。
- `make build-all GAMES=rollball` と `make build-web GAMES=rollball` で macOS、Windows、Linux、Web をエクスポートした。
- `gdlint scripts/` を GDScript の静的検査に使った。
- `scripts/dev/generate_audio.py --verify` を、WAV の決定的な再生成、非無音、非クリッピング、端点、長さの検査に使った。クレジットとライセンスの存在は selfcheck でも検査した。
- `ffmpeg` / `ffprobe` を、AVI から MP4 への変換、末尾フレームと一定間隔フレームの抽出、動画の長さ・コーデック・音声トラック、黒画面でないことの確認に使った。
- ImageMagick の `identify`、`compare`、`montage` などを、画像寸法、差分、一覧画像の作成に使った。最終判断は元の PNG も開いて目視した。
- `git` と `gh` を差分・履歴・PR・CI run の確認に使い、artifact の取得が遅い場面では `gh api` から zip を直接取得した。`curl` は公開した R2 URL の HTTP 応答と実データの照合に使った。

## 3. 欲しかったが無かったツール・skill・スクリプト

- Godot の画面状態を列挙すると、「状態を設定 → 必要な物理フレームを待つ → `queue_redraw()` → 描画完了を待つ → 一貫した名前で保存」まで行う汎用撮影ハーネスが欲しかった。今回は `screenshot.gd` に個別実装したため、5モデルを並べた6アニメーションの3時点や各画面の撮影コードを手で保守した。
- Godot の GUI と `_unhandled_input()` をまたいで、1回の実キー・ゲームパッド入力が何回処理されたかを記録する入力トレース兼回帰試験の雛形が欲しかった。関数単位のテストでは、`confirm` と `ui_accept` の二重処理を検出できなかった。
- macOS の描画付き Godot を確実に前面化し、`frame_post_draw` の停滞を検出して診断を出すラッパーが欲しかった。現在は撮影が止まった時にプロセス、ウィンドウ、生成枚数を別々に調べる必要がある。
- webtunnel の実ポート、CDP URL、Godot キャンバスの位置と倍率を取得し、ゲーム座標からクリック座標まで変換する補助コマンドが欲しかった。汎用例のポートを前提にした接続失敗と、1280×656 のブラウザ viewport に対する座標計算を手作業で切り分けた。
- CI artifact の取得、PNG 枚数と動画情報の検査、動画の間引きフレームと末尾フレームの生成、一覧画像作成までを1コマンドにしたスクリプトが欲しかった。R2 への公開は承認境界として残しつつ、その直前までと、承認後のアップロード結果照合を自動化できる。
- `game-asset-search` に Google Fonts 専用のライセンス検査が欲しかった。`METADATA.pb`、実際のライセンスファイル、フォントの name table を照合し、OFL などの想定と公式配布が違う時に停止できれば、今回の手動確認を再利用できる。
- 静止画の pixel diff だけでなく、アニメーションの途中停止、部位が動かない、1入力で2状態進む、といった時間方向の異常を検出する Godot 用の軽量な視覚回帰ツールが欲しかった。動画全体の最終的な見た目とテンポは、今回も人による目視が必要だった。

## 4. 素材の準備方法と使い勝手

### 画像・3D 表現・UI

- 新しい写真、ラスター画像、既成の3Dモデルは使わなかった。主人公、アヒル、ロボット、汽車、植木、家具、小物は Godot のプリミティブを組み合わせた独自シーンで、色だけでなく耳、翼、車輪、葉、装備などのシルエットでも識別できるようにした。
- 粘土表面は、固定 seed の `FastNoiseLite` と正弦波から作る頂点カラー、`NoiseTexture2D` の共有法線マップ、高い粗さの `StandardMaterial3D` で生成した。元メッシュと基準色をキーに変換済みメッシュ・マテリアルをキャッシュしたため、100個を超える配置でも物体ごとにノイズ資源を作らずに済んだ。再現性、ライセンス、既存アニメーションとの両立は良かったが、プリミティブの頂点密度によって模様の出方が変わり、ノイズが強いと石や砂に見えるため、実画像を見ながら弱い値へ調整する必要があった。
- UI は Godot の `Control`、`StyleBox`、CanvasItem shader、手続き SVG で作った。SVG は輪郭が安定し Godot 外でも確認しやすい一方、別ファイルの図案と画面レイアウトの調整が分かれる。今回増やした紙札 UI は文字量、フォーカス、画面遷移と同じ場所で直せる点が扱いやすかったが、Godot の実描画への依存が強く、headless だけでは崩れを判定できなかった。
- 画像生成 AI とフリー画像・フリー3D素材は使わなかった。外部素材の画風を合わせる作業を避け、既存の手続きモデルと部位アニメーションを保ったまま特色を足す方を選んだ。

### BGM・SE

- BGM、SE、2部屋の環境音を含む13個の WAV は、Python 標準ライブラリによる数式合成で生成した。木琴、撥弦、鐘、低音、ノイズ打楽器、紙擦れ、粘土を置く音、遠い玩具のベルを組み合わせ、生成コードと由来を CREDITS に記録した。
- この方法は第三者音源のライセンス確認が不要で、再生成した SHA-256 が一致するほど再現性が高く、長さ、ピーク、無音、クリッピング、端点を自動検査しやすかった。一方、波形が正常でも世界観に合うか、音量バランスが快適かは保証できない。この実行環境では聴感評価を完了できず、動画の音声トラックと波形までの確認に留めた。

### フォント

- Kosugi Maru を Google Fonts の公式リポジトリから取得し、ゲームへ同梱した。日本語を丸い紙工作 UI と同じ雰囲気で表示でき、Linux CI でも OS fallback に依存しない点が良かった。
- 使い勝手上の問題は、依頼時の OFL という想定と実際の Apache License 2.0 が違っていたことだった。Google Fonts だから一律 OFL と扱わず、公式メタデータ、ライセンス本文、フォント内部情報の三点確認が必要だった。

## 5. 動作確認の方法と、効いた点・足りなかった点

### headless のロジック・統合検証

- `selfcheck.gd` では体積、巻き込み可否、成長、脱落、進行状態、シーンと素材のロード、クレジットなど、描画を必要としない決定的な条件を速く検査した。壊れた参照や計算の回帰を早期に止める用途に効いたが、UI の重なり、白飛び、文字の可読性、アニメーションは判定できない。
- `integration.gd` では実シーンへ左右矢印、移動キー、左スティック相当、結果メニューの十字キーと A、Enter の押下・解放を送り、通常の接触で成長して成功する経路、時間切れ、カメラ、画面遷移を確認した。チュートリアル修正後は、Enter 1回で1ページだけ進むことも検査した。物理ゲームパッド本体を接続した試験ではなく、Godot の入力イベントを注入する試験である。

### スクリーンショットとアニメーション

- `screenshot.gd` で最終的に35枚を生成し、タイトル、2部屋の選択、チュートリアル3段階、両部屋の目標ハイライト、プレイ、成長、反発、勝利、時間切れ、結果、遷移を目視した。
- アニメーションは静止した1枚だけで済ませず、5モデルを同時に並べ、待機・移動・巻き込み・衝突・お祝い・時間切れの6状態を、それぞれ開始、途中、終了直前の3時点で撮影した。これにより、部位が動くこと、途中で通常状態に上書きされないこと、基準姿勢へ戻ること、照明による白飛びや不自然な影がないことを比較できた。
- 3時点のサンプルは主要な姿勢の欠落検出には効くが、補間の滑らかさ、速度、短いちらつきは保証できない。その部分は連続したプレイ動画でも確認した。

### movie、CI artifact、Web

- `make movie` の5秒動画で起動直後からタイトルまでが黒画面でないこと、描画と音声付き Movie Maker が警告なく終了することを確認した。
- `movie-play` では実入力を1,170件送り、61個、直径3.229m、19.18秒で結果へ到達する一連のプレイを録画した。間引きフレーム、末尾フレーム、元動画を確認し、画面遷移、連続アニメーション、HUD、演出を横断して見た。
- ローカルの実時間性能は、184物体の非操作状態で平均70.84 FPS、通常移動・巻き込み・成長で平均75.63 FPS だった。Movie Maker の固定フレーム数や CI の llvmpipe の速度を性能値として扱わなかった。
- CI artifact は35枚の PNG と MP4 を取得し、ローカルと描画環境の違う llvmpipe 上でも欠落、黒画面、大きな崩れがないことを目視した。CI の成功だけで見た目を合格にせず、artifact の実体を確認した。
- webtunnel では Web 版を実ブラウザで開き、タイトル、部屋選択、チュートリアル、移動、巻き込み、結果まで操作した。最終確認は22個、直径3.25mで結果へ到達し、console / errors が空であること、録画内容、全キー解放、セッション停止まで確認した。ここで Enter の二重処理を発見できたため、Web 上の実操作は静止画だけでは拾えない入力経路の検証に特に効いた。

### 残る限界

- 物理ゲームパッドを実際に接続した操作は未検証である。
- Windows / Linux はエクスポート成功と CI 上のロードまでで、各 OS の実機プレイは未検証である。
- BGM、SE、環境音は生成検査と動画の音声トラックを確認したが、人がスピーカーやヘッドホンで聴く主観的な音質・音量評価は未検証である。
- スクリーンショットと動画は大きな崩れや代表的な時間変化を確認できるが、すべての解像度、GPU、長時間プレイを網羅するものではない。

## 6. Godot 固有のハマりどころと回避策

- `--headless` はロジック検証には向くが、実描画、Control の再描画、影、フォント、shader、アニメーションの見た目は保証しない。描画付き `screenshot.gd`、Movie Maker、Web の実ブラウザを別経路で使った。
- `RenderingServer.frame_post_draw` は、macOS で Godot が背面にある時に進まないことがあった。撮影前にアプリを前面化し、タイムアウト時はプロセス終了だけで成功扱いせず、ログと期待する PNG 数を確認した。
- Control のプロパティを更新してフレームを待つだけでは、カスタム描画が更新済みとは限らない。連続撮影では親子の `Control` へ `queue_redraw()` し、その後の描画完了を待つ。
- `InputMap` の独自アクションと `ui_accept` が同じ物理入力を共有すると、GUI が先に処理した入力を `_unhandled_input()` 側で再発火しやすい。フォーカス中の `Button` は GUI に任せ、押下・解放を含む実イベント試験で状態遷移数を確認する。
- InputMap の特殊キー番号を推測すると左右矢印を取り違えやすい。定数と実 `InputEventKey` を使い、ゲーム内の移動結果まで回帰試験する。
- 単発の巻き込み・衝突アニメーションを物理フレームごとの待機・移動指定で上書きすると、途中で切れる。開始イベントで一度だけ再生し、単発状態の間は通常状態へ戻さない。各 AnimationPlayer のトラック先頭で基準姿勢も復元する。
- `--audio-driver Dummy` と headless の組み合わせで WAV を再生すると、終了時に `AudioStreamPlaybackWAV` / `AudioStreamWAV` が残る場合がある。音を必要としない検証では再生を始めず、Movie Maker では終了フレームより前に停止して参照を解放した。
- Godot 4.7 の `OS.get_cmdline_args()` には、エンジンが消費した `--quit-after` が残らない。Movie Maker ではユーザー引数 `--audio-stop-at-frame` も渡し、終了12フレーム前に音声を停止・解放した。通常終了では停止後に8フレーム待った。
- WAV は import 後に QOA 圧縮されるため、`data.size() / 2` をサンプル数としてループ終端に使うと曲が途中で切れた。`get_length() * mix_rate` からサンプル数を求めた。
- `--path` を指定した時の Movie Maker の相対パスは、現在の shell ではなく Godot プロジェクトを基準に解決される。パスを重ねると録画に失敗してもエンジンが exit 0 を返す場合があるため、ログだけでなく MP4 の存在、長さ、最終フレームも検査した。
- sandbox 内では Godot の標準ユーザーデータ領域への書き込み拒否が、ゲームの不具合に見えることがある。エンジンの保存先エラーとゲームのロードエラーを分け、必要な描画付き検証だけ許可された環境で実行した。
- Godot の export は Git の ignore を配布除外として扱わない。`tmp/` の大量の検証画像が成果物へ入ったため、各 export preset の `exclude_filter` に `tmp/*,build/*` を明示し、エクスポート後の内容も確認した。
- 環境光と指向性ライトを同時に強くすると、明るい粘土マテリアルが白飛びした。数値だけで決めず、タイトル、両部屋、モデル一覧の実 PNG を並べ、床、ラグ、小物の色と影が区別できる強さへ下げた。
